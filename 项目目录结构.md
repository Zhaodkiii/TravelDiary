### 1. 登录与会话管理
这部分负责“人怎么进来、登录后怎么留住、掉线后怎么回去”。

用户行为链路大致是：
1. 打开 App 后，系统先尝试恢复本地会话。
2. 如果有可用登录态，就直接进入主界面。
3. 如果没有登录态，就进入登录页。
4. 登录页支持 Apple 登录、手机号验证码登录和设备游客登录。
5. 登录成功后，App 会保存会话信息，后续启动优先恢复。
6. 当 token 过期时，网络层会触发失效事件，启动层统一收口处理。

这套模块最重要的点是把“会话”和“token”分开看：
会话更像当前是谁，token 更像通行证。
通行证失效要刷新，真正的会话切换才会影响页面和缓存。

这是用户登录后管理自己账号资料的地方。

它主要做几件事：
1. 展示当前账号资料。
2. 展示当前绑定了哪些登录方式。
3. 支持绑定或修改手机号、邮箱、Apple。
4. 支持账号注销前的确认和安全校验。

手机号和邮箱都不是普通输入框那么简单：

### 4. 文件与 OSS
这部分负责文件怎么传、传到哪、怎么记住传过什么。

业务链路通常是：
1. 用户在客户端选择文件。
2. App 先走本地缓存和文件包装层。
3. 如果要上传，就去后端换取 OSS 凭证。
4. 拿到临时凭证后直传 OSS。
5. 上传结果再回写到文件业务层。

它的关键不是“把文件丢上去”这么简单，而是要保证上传前后都能追踪、能重试、能预览、能和账号状态绑定。
一旦换账号或者掉线，缓存和凭证都要有正确边界。

### 5. OCR
这部分是图片或文档内容识别的编排层。

它做的事情是：
1. 收集待识别素材。
2. 预处理图片或文档。
3. 根据环境和配置选择阿里云 OCR、本地 OCR 或系统能力。
4. 把识别结果再交回上层使用。

它不是单独一个识别接口，而是一个“识别流程协调器”。
这样上层只管传输入和拿结果，不需要知道具体走哪个 OCR 引擎。

### 8. 网络层
这是所有后端请求的统一入口。

它做两件事：
1. 把 auth、otp、device、files、oss、ocr、aiConfig、deactivation、accountIdentity 这些 API 统一装配出来。
2. 给上层提供稳定的 token、错误处理、缓存和失效通知入口。

业务层不应该自己拼 URL，也不应该自己处理一堆分散的请求细节。
有了这一层，登录、账号管理、AI、文件和 OCR 才能共用同一套网络基础设施。
