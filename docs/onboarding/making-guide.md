# 首次用户制作引导

以「旅行随记 9」第一页「雨崩，慢一点」为内置演示，按收集 → 背景 → 照片 → 贴纸 → 文字推进。每次点击只推进一个阶段，已完成内容保留。背景采用 12 行交替笔刷遮罩逐步揭示原有背景图，不冒充原作者的真实笔画录制。

入口在 ContentView：新安装时在已挂载的 AppCoordinatorView 上方覆盖展示。会话恢复、首次自动游客登录、设备登记、账号准备和首次书架读取在引导期间并行推进，不重建根路由、不重复登录。点完成/跳过且书架首读已结束后，移除引导直接展示主页；若尚未就绪，保留引导画面，仅按钮显示“正在准备主页…”。离线、登录失败、账号准备失败可转入原有网络/登录/重试页面，避免卡住。完成或跳过使用安装级 UserDefaults 标记 diary.onboarding.completed.v1；开始时记录 diary.onboarding.started.v1，即使后台游客登录消费了首次资格，中途退出仍可再次展示引导。已有用户不强制展示。设置 → 通用 → 重看制作引导可随时打开，关闭不更改首次标记，也不创建书本或示例记录。

动画期间主按钮不可点击；可以直接看本步效果，随时跳过或回退。重播只重置当前阶段，task 随步骤/重播/关闭取消。减少动态效果时直接呈现阶段完成状态。应用返回前台会重播尚未完成的步骤。

资源位于 DiaryOnboarding.bundle，仅含第一页、13 个对象、19 张限边 1600 像素的离线素材。使用 DiaryPageRenderer 渲染透明分层，保留原图层顺序、照片裁切、撕纸边框与字体样式，不改动源文件。可用 scripts/prepare_onboarding_sample.py 从导出的书重新准备资源（需要 Pillow）。

Debug 启动参数 `-diary-onboarding` 可强制展示，用于模拟器验收。正常启动仍遵循首次规则。测试 DiaryOnboardingTests 覆盖首次资格、中断后资格、完成持久化、已有用户及内置素材渲染分组。

## 2026-11-06 默认首页变更后的交接修复

现象：日志已到“Prepared signed-in account / 账号运行时准备完成”，引导仍一直显示“正在准备主页”。原因是默认 selectedTab 已改为 travelCapture，但 homeReadyAccountID 仅由 diaryEditor 书架的首读回调设置。TabView 按需加载，未选中的书架不会出现，因此引导等待永远无法满足。

TravelCaptureHomeView 现在也在首次 reload 和待处理照片恢复结束后报告就绪；根协调器只接收当前显示页的首读回调。书架页仍保留首读回调。任务被取消时不上报；首读失败时现有错误入口也可交接。新增“当前首页首读完成”和“入口就绪”日志，便于区分认证与页面加载。

新增集成回归测试 defaultCaptureTabFinishesHandoffBehindGuideWithoutOpeningShelf：在引导覆盖下挂载实际 SupportMainCoordinatorView，保持默认随记标签，验证主页就绪可以满足已请求结束的引导交接；该测试不依赖访问书架。

本次验证：iPhone 17 Pro / iOS 26.1 模拟器 Debug 构建成功，隔离运行 DiaryOnboardingTests 共 9 项全部通过。真实主页回归测试日志已出现 `当前首页首读完成 tab=travelCapture`，在不选择手帐标签的情况下完成交接判定。测试使用本地空书库和测试账号模型，不依赖真实登录网络；不代表真机网络登录的端到端验收。
