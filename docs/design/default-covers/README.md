# 默认封面设计方案

日期：2026-11-16。以下为产品与工程设计，附本次实现的行为与资源规格。

当前实现会在引导发布、编辑器完成、AI 作品保存、相册及模板导入时补齐封面。封面随普通页面存档，用户可在阅读器开篇或页面管理中更换三种样式。书名前后同步取决于用户是否编辑过封面标题。用户明确删除后可以从样式面板重新添加。

应用内底图位于 `TravelDiaryClient/Projects/App/Resources/DiaryDefaultCovers.bundle`。原始提案通过等比重采样和轻微居中裁切生成 2185×3130 像素、双轴 300 ppi 的 sRGB JPEG，保留原图实际细节水平。单页封面 JPEG 按相同规格输出，PDF 以 185×265 mm 设置页面物理尺寸。实体印刷将开篇页随内容提交，外壳仍按当前印刷商品协议单独处理。

## 1. 产品决策

每本完成保存的手帐应有可编辑封面。使用预置底图加本地文本图层，不在每次完成时调用图片模型。封面独立于正文页码，也独立于阅读器皮质外壳。新用户不需要增加选择步骤，完成后可选“更换封面”。

默认选用素雅织纹；复古拼贴、水彩远山作为可选风格。新居、日常、亲子等非旅行主题也能使用素雅织纹。拼贴提案含建筑及地图装饰，更适合作为旅行类备选，不作为全场景默认。图中印刷装饰文字需在正式母版中清理。

## 2. 当前项目依据

- DiaryBook.swift 已定义 coverSize = 2185×3130、coverPageID、coverDraft、shellPageID，effectiveCover 可区分封面与外壳。
- readingSpreads 始终保留 [nil, effectiveCover] 开篇；缺封面也占据阅读位置。exportSpreads 只在 effectiveCover 存在时包含封面。
- bodyPages/bodyPageCount 已排除封面；应保留正文第 1–2 页与现有跨页关系。
- DiaryEditorHomeView.swift 无有效封面时显示“待添加封面”。当前书架卡片使用 3:4 外框，封面实际约 0.698:1；需要容器留白或匹配比例，禁止拉伸裁字。
- DiaryDocumentStore.swift 已有 prepareCoverDraft / finishCoverDraft / setCover，替换封面检查预期 ID，并归档旧封面。自动补齐需要专用事务，不能借用或覆写用户尚未完成的 coverDraft。
- DiaryCoverLifecycleTests.swift 已测试删除后保持无封面；新自动补齐策略须保留用户明确删除的意图，扩展而非简单推翻此行为。

## 3. 视觉及文字

| 方案 | 素材 | 用途 |
| --- | --- | --- |
| 素雅织纹 | 01-linen.png | 默认；暖米白织纹、浅压纹边框、底部小枝叶 |
| 复古拼贴 | 02-collage.png | 旅行备选；撕纸、邮票、胶带和植物 |
| 水彩远山 | 03-watercolor.png | 自然旅行备选；浅绿蓝灰群山、暖色日光 |

图片仅作背景，书名必须是原生文字图层。主标题中心约位于画面高度 35%，宽度不超过 72%，与装饰至少保持明确留白；默认深棕或墨绿，确保小缩略图可辨识。主标题建议初始字号 140–180 设计像素，按真实字形测量换行、缩小，常规最多三行；极长名称使用独立短封面标题，完整书名继续保存在书籍元数据中，不能直接永久截断原书名。英文按词换行，长单词允许断行，中文按字形排版；验证 emoji 和缺字字体回退。

默认主标题取本子书名；空白名称使用“我的手帐”。日期仅在已有明确记录范围时显示，不能将制作日期伪装成旅行日期。作者、城市、副标题默认不显示，不从照片推测私人信息。用户可编辑标题、显隐日期、换背景；更换风格保留已编辑文字。

书名未手动改过时随本子重命名同步；一旦用户编辑封面标题，切为独立文字，提供“与书名同步”选项。不要整页重建导致用户排版丢失。

## 4. 完成流程和交互

正文持久化成功 → 读取最新书籍目录 → 检查封面状态 → 缺失且允许自动添加时发布默认封面 → 刷新缩略图 → 展示制作完成。

各制作入口在共同的“保存到手帐”边界调用同一个补齐服务：引导首次保存、整本制作、模板导入、后续手动制作首篇内容。具体调用点实施时继续追踪；不能只在引导页面增加逻辑，也不能在 SwiftUI body 渲染时写入文件。

完成页显示封面预览，主按钮“查看手帐”，次按钮“更换封面”，轻量提示“已为你配好封面，可随时更换”。不增加强制选择弹窗。首次查看成品可从封面打开；“继续编辑”仍恢复上次编辑的正文位置，自动补齐不能更新用户最近编辑位置。

阅读器保持当前左侧内衬、右侧封面的结构；底部标签改为“封面”，之后仍是“第 1–2 页 / 2”。书架展示同一封面渲染结果，统计可写“2 页 · 含封面”。缩略图轨道把封面固定在正文前，不允许拖到正文中间。皮革和装订阴影仅属于阅读器外观，不烘焙进封面背景或印刷文件。

## 5. 状态和自动补齐规则

建议增加可向后兼容的可选字段：coverOrigin（automatic/user）、coverTemplateID、coverTemplateVersion、coverAutoFillPolicy（allowed/disabled）、coverTitleBinding（bookTitle/custom）。这些均为拟议字段，当前代码尚未实现。

| 情况 | 行为 |
| --- | --- |
| 有有效封面 | 保留，无论自动或用户创建 |
| 无封面且未禁止自动补齐 | 安装一次默认封面 |
| 有未完成封面草稿 | 默认封面可独立建立，但保留草稿；恢复草稿时重新绑定替换基线，禁止无条件覆盖 |
| 用户明确移除封面 | 保存 disabled；下次完成、重启和导出均不擅自补回 |
| 撤销自动添加 | 删除该自动封面并设 disabled，提供恢复默认入口 |
| 有封面 ID 但资源损坏 | 作为修复问题处理，保留原始数据；不可当作从未有封面直接覆盖 |
| 旧版本缺失字段 | 解码为兼容默认，区分无法得知历史删除意图的问题 |

旧作品建议：书架可临时展示可识别的默认预览，不批量修改历史目录或更新时间；用户首次继续制作时再持久化。由于旧数据没有删除意图标记，不应启动时无条件给所有旧作品补封面。预览不是实际封面时，导出前须明确处理，避免所见与导出不符。

## 6. 存储、一致性与故障

拟新增 DefaultCoverCatalog、DefaultCoverDocumentBuilder、ensureDefaultCoverIfNeeded。前者管理预置素材、标题区域、配色和模板版本；builder 生成普通单页 DiaryDocument；服务在书籍存储串行事务内复核目录并发布。

写入顺序：生成文档和资源快照 → 确认文件完整可读 → 复核 bookID、coverPageID、策略与目录版本 → 原子发布目录。竞争期间若用户已创建封面则放弃自动发布；重复回调、进程恢复、重复点击都只产生一个有效封面。未引用快照可延后清理。不得将半成品 ID 先写进目录。

模板素材跟随应用离线提供；已保存作品应引用固定版本或将素材保存进作品资源，导出源文件时包含资源。更新应用不能悄悄改变旧封面。默认风格不要每次随机选；初版统一素雅织纹，用户主动切换后持久保存选择。

图片失败时使用本地纯色纸底加可编辑标题作为降级；存储失败时保留已经成功保存的正文，提示“内容已保存，封面暂未添加”，提供重试。不能把整本显示为保存失败，也不能声称封面已完成。

缩略图缓存键至少包括 bookID、封面 revisionID、模板版本、标题内容或文字修订。列表按显示尺寸解码缩略图，编辑与导出才加载大图；单张 2185×3130 RGBA 解码约 26 MiB，不在书架同时解码所有母图。

## 7. 尺寸和导出

目标：18.5×26.5cm，2185×3130px，水平与垂直 300ppi（常俗称 300dpi）。整数像素对厘米换算存在正常舍入误差。

本次内置 image_gen 返回的视觉提案实际为：织纹 1047×1503px，拼贴及水彩 1047×1502px，均 72ppi 元数据。它们不是最终 2185×3130、300ppi 印刷母版。改分辨率标记不会增加细节；正式资源阶段必须完成足尺寸输出/重制及印刷检查，不能将当前图直接宣称达标。

最终 PNG/JPEG 嵌入 sRGB 配置与 300×300ppi；保留无文字底图、可编辑封面文档、合成图和缩略图。PDF 中物理页面尺寸应显式设置约 524.41×751.18pt，不能依赖图片 DPI 猜测。正式母版正文和装饰均不能带模型伪文字。

默认成品输出不含出血；印厂若要求四边 3mm，则另出 19.1×27.1cm、约 2256×3201px 文件，背景向外延展，不能拉伸现有成品冒充出血。重要文字建议距裁切线至少 10–12mm；具体装订、包边、书脊与出血按印厂模板确认。当前需求仅是正面单页封面，不等于封底＋书脊＋封面的整张装帧稿。

阅读、书架、图片导出、PDF、视频及打印应使用同一已持久化封面。整本导出默认包含封面，正文页码不变；单页导出选择器显式列出“封面”。不能把阅读器左侧皮革当成一个空白 PDF 页面；打印封面是否独立文件应跟随既有订单协议核查，不能只修改 exportSpreads 就假定所有出口都正确。

## 8. 实施与验收

第一阶段：确认默认风格，完成正式母版；实现离线模板、独立文字、存储补齐、书架及阅读刷新、导出一致性。第二阶段：封面更换面板、短标题设置、模板扩展与旧作品引导。

验收：新用户零额外操作获得封面；已有封面逐字逐层保持；正文第 1–2 页和跨页顺序保持；重复完成/杀进程恢复不重复添加；保留用户封面草稿；删除或撤销后不自动复活；并发用户封面获胜；断网可用；资源缺失可降级；磁盘错误不损坏正文；长中英文和 emoji 不溢出；改书名正确使缓存失效；各种导出包含正确封面且无皮革内衬；印刷尺寸及物理页面尺寸正确；旧文件缺字段可读取。

生成方式：内置 image_gen。完整提示词见 prompts.json。三张原图作为风格提案保存，应用资源使用尺寸归一化后的 JPEG。
