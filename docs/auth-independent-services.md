# 独立测试服务切换

不修改 FRP、Nginx、数据库结构或 Apple 身份解析。前提：切换后入口稳定指向选定服务；共享组交替分配仍可能导致反复退出。

## 服务端部署

在每台 SparkService 根目录运行 `python3 scripts/configure_local_jwt.py`，然后重启后端。
脚本向本机 .env 写入随机 JWT_SIGNING_KEY，重复运行保留已有配置。不复制另一台 .env。若此前已复制密钥，用 --rotate 显式更换（已有登录失效）。如进程环境另设 JWT_SIGNING_KEY，需移除覆盖或同步更新。
本机已生成配置并重启 backend，健康检查 200；另一台尚未执行。

## 客户端

新登录和清除 token 更新会话版本；旧刷新不能覆盖新凭证。请求排队前后校验版本。每个请求最多刷新一次，并发刷新复用任务。认证失效事件携带版本，旧事件不退出新会话。相同设备画像共用登记任务，重置后旧登记不提交状态。
明确认证失败退出，临时网络或服务错误保留凭证。退出清理可重建资源缓存、ETag 和设备认证元数据，不删除 Core Data、草稿或未上传文件。认证失效时轮换账号文件目录命名空间，旧目录保留，原 scope 记录在 storage.retainedAccountScopes.<owner摘要>，不自动导入另一个服务；恢复旧草稿目前需按记录人工恢复，尚未提供恢复 UI。显示“登录已失效，请重新登录。”

## 验收

1. A 登录、创建日记，稳定切至 B，下一次鉴权请求退出一次。
2. B 重新登录，按 B 数据库创建/恢复账号。
3. 切回 A，退出重登后恢复 A 的服务端账号数据。
4. 相同数字账号 ID 不复用远端缓存；本地草稿保留，检查不会自动上传到另一服务。
5. 刷新期间新登录，旧刷新 401 不清除新 token。
6. 断网、502/503 不退出，相同画像设备登记只保留一个在途任务。
