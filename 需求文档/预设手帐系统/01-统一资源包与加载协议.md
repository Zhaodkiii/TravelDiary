# 统一资源包与加载协议

版本：v1.1；日期：2026-10-14；状态：客户端本地加载及存档映射已实现；云端 Provider 和协议扩展待后续。产品流程见 [总需求](./README.md)。

## 1. 格式与职责

预设包是只读分发文件，用户本子是可修改作品。二者共用图层语义与渲染器；分发包额外带分类、缩略图和依赖清单，用户存档额外带本子目录、修订版本和草稿。导入通过适配器生成现有 DiaryDocument，并由 DiaryDocumentStore 发布为现有存档结构。

不能把 Swift Codable 的默认编码细节当作跨语言文件协议。制作端用 Python，客户端用 Swift；对外 JSON 明确使用命名坐标字段、字符串键和类型 discriminator，Swift 端独立 DTO 映射到运行时模型。

## 2. 内置资源目录

```text
DiaryPresets.bundle/
├── series.json
├── 城市系列/
│   ├── suzhou.diarypreset/
│   │   ├── package.json
│   │   ├── pages/
│   │   ├── objects/
│   │   ├── assets/
│   │   └── previews/
│   └── shanghai.diarypreset/
├── 徒步系列/
│   └── yubeng.diarypreset/
└── 美食系列/
    └── local-snacks.diarypreset/
```

以上 drawings/fonts 为可选目录；没有内容不要求创建。图片格式首版允许 PNG/JPEG，预览首版固定采用 PNG/JPEG；WebP 后续验证解码支持后再开放。资源 bundle 必须在 Xcode 中保持目录结构，构建产物验收路径，不依赖同名文件被扁平复制到主 Bundle 根目录。包内不携带 PSD 原件；源工程及制作报告存放在制作仓库。

## 3. 目录与包字段

不再要求手动维护包含所有本的 catalog.json。series.json 只记录系列的 id、title、directory、sortOrder，例如 city/城市系列、hiking/徒步系列、food/美食系列。一个已有系列新增本不修改此文件；新增系列才添加系列配置。

启动时扫描已配置系列目录下的直接子目录 `*.diarypreset/package.json`，从各本清单生成内存 catalog，首版不扫描未配置目录或无限递归查找。book 卡片字段 templateBookID、packageVersion、seriesID、title、tags、sortOrder、pageCount、coverPath 全部从该本清单读取，packagePath 由扫描位置确定。package.json 的 seriesID 必须与所在系列一致；移错目录时校验失败并指出正确系列，不擅自改分类。

package.json 中的相对路径均以本 .diarypreset 根目录解析。预设本 ID 全局唯一；同名本可有不同 ID；同 ID 多个版本不同时随应用发布，构建校验应失败并提示移除旧包，不能取决于扫描顺序。系列内按 sortOrder、templateBookID 稳定排序。

package.json 建议结构：

```json
{
  "format": "TravelDiary.PresetBook",
  "schemaVersion": 1,
  "layerSchemaVersion": 1,
  "templateBookID": "hiking-yubeng-memory",
  "packageVersion": 1,
  "title": "雨崩",
  "seriesID": "hiking",
  "pageSize": {"width": 2185, "height": 3130},
  "coverPageID": "introduction",
  "pages": [
    {"id": "introduction", "title": "引言", "path": "pages/introduction.json"}
  ],
  "requiredCapabilities": ["image", "object"],
  "files": [
    {"path": "pages/introduction.json", "byteCount": 1234, "sha256": "<实际文件摘要>"}
  ]
}
```

这是字段说明示例，不是可直接运行的完整包。正式 files 必须包含所有被引用的页面、对象、素材、字体和预览；不包含 package.json 自身，避免自引用摘要。构建校验报告或未来远端发布索引可保存 package.json 摘要；云端未来需要另加可信签名机制，哈希只能校验完整性，不能证明来源。

schemaVersion 描述封装格式；layerSchemaVersion 描述图层协议；packageVersion 是同一本模板的内容修订号，三者不得混用。requiredCapabilities 明确使用的能力；不支持能力时不能声称完整可编辑。未知协议版本阻止导入并说明需要更新应用。

页面 JSON：id、title、size、rootContentID、preview（thumbnailPath/largePath）、editableSlots、source 可选信息。objects 以 ID 索引文件路径，assetTable 以资产 ID 索引 path、mimeType、pixelSize、sha256、byteCount、alpha、colorSpace。对象和资产索引固定放 package.json 统一管理，跨页可共用不可变图片。

首版统一一本中所有页面尺寸；制作端存在不同尺寸须显式选择统一目标及 contain 策略，或拆成不同模板本，不得默默拉伸。

## 4. 图层协议与当前模型映射

内容对象：id、revision、role、primaryLayerID（可空）、referenceSize、background（null 表示透明）、layers、drawingPath（可空）。role 使用 canvas/photo/text/sticker；普通 PSD 组映射为 canvas 内容对象。主内容图层与对象 role 保持一致。

图层字段：

| 字段 | 规则 |
| --- | --- |
| id/name/kind | 稳定身份、名称、photo/sticker/text/object/frame |
| size | width/height，局部设计单位，均为正 |
| transform | position:{x,y}、pivot:{x,y}、scale:正数、rotationDegrees |
| visible/locked | 控制显示和编辑；不改变层序 |
| assetID/contentID | 图片引用或子对象引用，按 kind 校验 |
| crop | zoom、offset:{x,y}，图片取景与外部摆放分开 |
| text/fontSize | 当前原生文字的基本字段 |
| frameTargetID/frameColor/frameWidth | 画框关联本内容对象的照片层 |

层数组固定从底到顶绘制；不另存 zIndex。坐标单位与屏幕像素无关，矩阵顺序为平移到 position → 旋转 → 等比缩放 → 平移负 pivot。子对象的坐标属于父内容对象。

每个需要独立打开的图片层都创建外部 object 实例和内部主图片层，使用 appendObject 等价流程；不直接把全部 sticker 叶子堆进根内容后就宣称支持独立对象编辑。背景图片也保留为对象，可默认锁定；纯色根背景可使用 background 字段。

当前模型不具备丰富字体、混合模式、图层透明度、任意蒙版及非等比缩放的完整表达。协议 v1 不凭空声明这些能力已支持；制作端必须烘焙为图片或阻止发布。新能力需同时扩展模型、渲染、编辑、保存与协议版本测试。

每个内容对象的 drawing 最后绘制，只覆盖该对象内部图层；对象放在页面中的层级仍由父数组决定。根画布涂鸦覆盖根图层。PSD 普通绘画像素层不转换成伪造 PencilKit 笔画；保留为图片层。

## 5. 可编辑槽位

editableSlots 描述经过确认的可编辑入口：slotID、layerID、kind（photo/text）、label、required=false、默认内容。必须指向真实且类型匹配的图层；不新增第二份位置和尺寸来源。

照片槽位标记建议取景比例，实际取景以图层外框决定。文本槽位只允许引用原生文字层；图片标题即使名称包含“文字”也不能登记成 text 槽位。预览能力摘要由槽位与图层验证计算。

来源追踪记录 templateBookID、templatePageID、packageVersion、importedAt，可附原始层名；它不作为保存依赖，不参与用户图层身份。模板更新不会基于来源自动覆盖副本。

## 6. 加载分层与接口职责

当前落地文件：`Infrastructure/Presets/DiaryPresetPackage.swift` 实现 Bundle 来源发现、包文件 SHA-256 校验和 DTO 到运行时文档映射；`Application/DiaryPresetImportIntent.swift` 保存恢复意图与取消状态；`DiaryDocumentStore.importPreset` 完成素材复制、页面版本写入和发布；`Presentation/DiaryPresetLibraryScreen.swift` 实现浏览、预览与目标本选择；`scripts/ValidateDiaryPresets.swift` 在 Xcode 资源复制后验证构建产物。当前 Provider 接口为同步本地扫描，远端接入仍需要 async provider、下载缓存和签名校验。

建议文件（名称为待实现设计）：

```text
Domain/Presets/
  DiaryPresetCatalogDTO.swift
  DiaryPresetPackageDTO.swift
  DiaryPresetLayerDTO.swift
  DiaryPresetSource.swift
Infrastructure/Presets/
  BundleDiaryPresetProvider.swift
  DiaryPresetPackageLoader.swift
  DiaryPresetPackageValidator.swift
  DiaryPresetDocumentMapper.swift
Application/Presets/
  DiaryPresetBrowseModel.swift
  DiaryPresetImportService.swift
Presentation/Presets/
  DiaryPresetLibraryScreen.swift
  DiaryPresetBookDetailScreen.swift
  DiaryPresetPagePreviewScreen.swift
  DiaryPresetDestinationSheet.swift
```

- Provider.listCatalog()/resolvePackage(id,version)：返回元数据或本地只读根目录；首版 Bundle，未来 Remote 实现相同职责。
- Loader.loadMetadata()/loadPageGraph()：按需读目录与选中页依赖，禁止浏览一个分类就解码所有原图。
- Validator.validatePackage()/validatePageGraph()：校验协议、路径、哈希、引用、图层能力和资源限额。
- Mapper.instantiatePages()：DTO 转运行时模型，分配 ID、解析本页依赖并建立对象图。
- ImportService.importBook()/importPages()：目标选择结果、尺寸适配、素材复制、事务发布、幂等重试。

浏览使用缩略图；全屏只预读当前及相邻页。进入编辑时按当前渲染需求解码预览图，导出使用高质量资源。缓存与作品分开，缓存删除不得导致作品无法打开。

## 7. ID、依赖闭包与持久化

模板内的字符串 ID 是制作标识，导入时映射为用户存档 UUID。按 selected pages → rootContentID → child contentID/assetID/drawingPath/fonts 计算依赖闭包，只复制需要的资源。

所有 layerID、primaryLayerID、frameTargetID、rootContentID 和 contentID 必须完整重映射。同一本内相同内容哈希的图片可共用一个资产记录，但可变对象内容不共享：两页引用同一模板对象时应分别实例化，编辑一页不能改变另一页。循环引用拒绝。

导入后仍落为 books/<bookID>/book.json、assets/、pages/<pageID>/revisions/<revisionID>/manifest.json 及 objects/*.json、*.drawing。由现有存档写入器编码，不要求 Python 直接生成账号作用域、用户 UUID 或修订指针。

当前导入已写入页标题与来源版本；新本通过暂存目录移动发布；已有本通过唯一 ID 的素材/页目录和 book.json 发布。导入意图日志支持重试和孤立数据清理。云端签名、并发锚点冲突交互和更复杂的回滚保留为后续增强。

## 8. 校验与容量

相对路径禁止绝对路径、..、包外符号链接；未来解压还需限制展开大小和路径。校验文件存在、字节数、哈希、图片可解码、尺寸及像素上限、有限坐标、ID 唯一、引用完整、层数与深度符合现有校验器。文件扩展名与真实格式必须相符。

建议制作警戒线：单本 50 页、200 MB，总体积根据实际内置资源预算调整；超过警戒线需制作审核，不是未经测量的客户端承诺。运行时硬性限制独立配置，并不得高于现有对象层数 200、嵌套深度 32 等约束。图片解码像素预算还需真机内存测量后确定。

云端将来接入时，同一包须经过相同校验；网络地址只出现在来源提供者元数据，不进入图片图层或替代本地素材路径。

## 9. 跨语言协议的进一步约定

- 所有 JSON 使用 UTF-8；字段名区分大小写；时间为 UTC ISO-8601 字符串，版本为正整数。文件哈希是小写十六进制 SHA-256。
- 包内 ID 使用稳定 ASCII 字符串；显示名称可以中文。assetID 不强制等于哈希，但同 ID 不允许对应不同资源。文件路径统一使用 `/`，对大小写敏感，不能依赖开发机文件系统的大小写容错。
- page.size 与 package.pageSize 必须一致；所有尺寸以设计单位计。源 PSD 可按原像素尺寸设置设计单位，导出 DPI 是单独元数据，不由预览像素或设计单位推断。
- `background: null` 为透明，颜色使用 RGBA 0～1。省略可选字段遵循 DTO 默认值；required 字段缺失报错。数值禁止 NaN/Infinity，scale 必须满足运行时校验范围。
- objectTable 的键对应对象 JSON 内 id；assetTable 的键对应素材记录 id。files 是完整性索引，不作为图层顺序或对象层级来源。
- coverPageID 必须指向 pages 中的页面。目录不记录未发布页面，不允许封面引用不存在的草稿。
- 模板中主图层 ID、画框目标 ID 必须在所属内容对象内解析；层级引用只能通过 contentID 指向包中对象。
- 原生 `.drawing` 只能来自客户端支持的 PencilKit 序列化；跨平台 PSD 工具无法合成此格式时不生成该文件，drawingPath=null。用户存档写入器仍可按当前协议写空 drawing 文件。

首版照片占位不能使用“缺失 assetID”绕过现有校验；制作者提供默认示例图片或工具生成有效占位图片，并标记可替换槽位。占位图和用户替换后的真实照片遵循相同资源引用方式。

文字排版的增强字段需明确 capability 和协议升级；不能把 DTO 中尚未映射到运行时的字体字段当成已经生效。验收应包含 Python 输出 → Swift 解码 → 模型校验 → 存档重开 → 渲染的完整链路。

## 10. 自动发现、编译与启动

资源容器在 Xcode 中一次性配置为保留目录的整体复制资源；验收实际 .app 内的系列与本包结构，不依赖同步文件组自动扁平化复制。之后增加本包只需移动文件并重新构建，不能要求逐本添加 target membership 或注册 Swift 常量。

发布构建必须校验所有被发现包及其完整依赖；有错误就阻止发布并输出具体路径。开发运行时若遇到无效包，隔离该包、记录可定位原因，其他包仍可浏览。

启动阶段后台扫描小型 package.json，建立可观察的目录状态；预设页面显示加载状态，不在主线程解码整本原图。缩略图、逐页预览及编辑资源继续按需读取。启动阶段不转换 PSD、不向只读 Bundle 写 catalog、不自动创建“我的”副本。应用升级后重新发现随包本清单；可重建缓存不替代 Bundle 的权威清单。

未来 Remote provider 从云端索引获得本包，最终同样解析单本 package.json；本地目录发现仅是 Bundle provider 的来源实现，不改变包内图层协议。
