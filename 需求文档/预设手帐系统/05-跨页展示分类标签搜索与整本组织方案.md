# 预设手帐：跨页展示、分类标签、搜索与整本组织方案

日期：2026-10-16。状态：需求与技术设计，尚未实现本文新增协议、数据库与 UI。适用：iOS 预设库、Django diary_presets、管理后台、制作和 OSS 发布流程。

配套：[统一资源协议](01-统一资源包与加载协议.md)、[云端资源需求](03-云端预设资源与iOS加载需求.md)、[后台与 OSS 技术方案](04-后台页面管理与OSS直传下载技术方案.md)。本文细化展示和检索；涉及已有规则时，以本文明确注明的新设计作为后续实施目标，不代表当前已上线。

## 1. 结论与图片需求解释

采用“系列 → 手帐本 → 阅读单元 → 单页”的组织方式。阅读单元可以是封面、单页或跨页；跨页引用左右两张独立页面，不将可编辑页面合成一张大图。

用户图片作为视觉参考：宽屏中每行两张完整的跨页卡片，每张卡片保持左右页面相邻、完整显示，行列对齐；卡片下面必须显示该跨页的名称。图片中的艺术标题不能代替 UI 名称。参考图片用于布局说明，不据此自动推定舟山现有页面配对。

三种浏览模式：

| 模式 | 卡片代表什么 | 图片 | 名称示例 | 主要动作 |
| --- | --- | --- | --- | --- |
| 整本 | 一个已发布的手帐本 | 封面；进入详情可翻阅整本 | 舟山 · 海风会替我们记得 | 查看整本、整本添加 |
| 跨页 | 一个明确配对的阅读单元 | 左右页合成缩略图 | 东福山 · 风比我们先到 | 预览、添加这两页 |
| 单页 | 一个真实页面 | 单页缩略图 | 东福山 · 海岸照片页 | 预览、添加这一页 |

默认预设首页展示整本；进入一本后默认跨页模式，可切换单页。全库搜索可切换“全部 / 手帐本 / 跨页 / 单页”。浏览偏好按设备保存，不改变模板内容。

首版跨页指两个独立画布的联合展示和联合导入；跨书脊拖动图层、一个对象同时跨两页编辑不属于首版，需要未来独立画布协议。

## 2. 当前实现与差距

本次查看到：后端已有 Series、Template、Version.snapshot、Upload、DownloadPlan、Event；页面与素材保存在版本 JSON 中，并非已经有独立 Page/Spread 数据表。iOS 已有 RemotePresetLibraryScreen、DiaryPresetBookReader、PresetDownloadManager，阅读器会依据内容数组位置计算双页。资源协议当前使用 schemaVersion=1，客户端校验版本。

因此新增工作是显式阅读单元、标题标签、索引、跨页网格和跨页导入语义，不是再建一套文件上传系统。当前工作区还有正在修改的阅读与导出代码，本文不修改这些代码，也不将它们当作已发布能力。

现有舟山 v1 是已发布版本，应保持不可变。新配对、名称和标签完成后发布新版本；不直接改 v1 快照，不因本次写文档迁移生产数据库。

## 3. 分类怎么设计

### 3.1 系列作为唯一主分类

建议初始系列：海岛、城市漫游、山野徒步、美食探店、公路旅行、生活日常。只有实际有内容的系列才展示；不必一次创建大量空分类。舟山仍属于海岛系列。

一本只属于一个主系列，跨类检索交给标签，避免同一本多处复制。系列 ID 使用稳定 slug，如 islands；中文名可以改，OSS 路径和模板 UUID 不随改名变化。系列后台支持排序、隐藏，含书系列不能直接删除，需先迁移书或停用。

### 3.2 多维筛选，避免把所有词变成系列

| 维度 | 示例 | 规则 |
| --- | --- | --- |
| 地理位置 | 中国 / 浙江 / 舟山 / 东极岛 / 东福山 | 独立地点树，允许多个地点；地点有稳定 ID 和别名 |
| 内容主题 | 海边、灯塔、古城、日落、海钓 | 多选受控标签 |
| 视觉风格 | 水彩、拼贴、复古、极简、胶片 | 多选；不是编辑能力保证 |
| 使用场景 | 开篇、每日记录、路线、照片墙、总结 | 页面角色可单值，场景标签可多值 |
| 季节与氛围 | 夏季、秋日、治愈、热闹 | 可选，避免强行填满 |
| 布局 | 横向跨页、竖向单页、照片为主 | 从结构计算优先 |
| 编辑能力 | 可替换照片、可编辑文字、图片装饰文字 | 从验证结果计算，禁止运营虚标 |

不把“海岛 / 舟山 / 东福山 / 水彩 / 夏季”做成五级目录。展示层最多系列和一本详情两级，其他维度筛选即可。

## 4. 名称、标签和搜索词治理

### 4.1 名称独立于 PSD 文件名与图片文字

- 手帐名：舟山 · 海风会替我们记得。
- 跨页名：东福山 · 风比我们先到。
- 左页名：东福山 · 风比我们先到 · 左页；右页名：东福山 · 风比我们先到 · 右页。允许更有意义的短名，如“海岸记录”“海风照片”。
- 搜索结果副标题：海岛系列 / 舟山 · 海风会替我们记得 / 第 6–7 页。
- PSD 文件名保留在制作来源记录中；v02、分层重建、初稿等不出现在面向用户的标题里。

标题必填，建议本名与跨页名各 2–60 个字符、单页名 2–80 个字符；数据库继续允许现有更长上限，导入时显示警告，不静默截断。标题不要求全局唯一，身份只看 ID。卡片标题最多两行，详情和 VoiceOver 展示完整名称。

### 4.2 标签数据规则

标签包含 id、dimension、slug、display_name、aliases、active；同维度 slug 唯一。别名如“沈家门 / 沈家門”归于一个地点或标签，不重复建立实体。拼音及首字母是检索字段，不显示为一堆标签。

建议每本 3–8 个主题/风格标签，每个跨页 2–6 个，每页 0–4 个；这是编辑提示，不是硬性发布门槛。标签应描述实际内容，不能为提高命中随意添加热门地点。

显式标签与继承上下文分开保存：页面能通过所属本检索到“舟山”，但不会自动继承本内所有具体景点。跨页搜索包含本名、自己的标签和两页显式标签；本的搜索可聚合子页地点，但排序低于本名命中。接口返回 matched_fields 或匹配摘要，说明命中来自哪一层。

后台可合并标签并维护旧别名；旧版本快照不重写，当前搜索索引可按新的别名解析。用户个人自定义标签将来单独建 owner 作用域，不混入官方模板标签。

## 5. 整本、单页与跨页的数据关系

### 5.1 推荐结构

```text
Series 海岛系列
└── Template 舟山（稳定 UUID）
    ├── Version 1（不可变，保留）
    └── Version 2（不可变，发布后可设为 current）
        ├── pages：真实单页、各自图层和资源引用
        ├── readingUnits：封面 / 单页 / 跨页，按 position 排列
        ├── metadata：名称、地点、标签、能力摘要
        └── assets：按 sha256 去重的 OSS 对象
```

pages 数组保留规范导入顺序；readingUnits 负责分组与展示。发布校验必须确认阅读单元展开后的页 ID 顺序与正文 pages 顺序一致，不能有两套互相矛盾的排序。外壳 shell 为独立装饰引用，不计正文页数；封面 cover 可以是实际页面，通过明确角色决定是否计入正文，不根据文件名猜测。

### 5.2 阅读单元字段

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| id | 稳定字符串/UUID | 改名或调序不变化，重新配对则创建新 ID |
| kind | cover / single / spread | 不从 pageIDs 数量盲猜语义 |
| title | 字符串 | 独立跨页名，必须展示 |
| position | 整数 | 本内顺序，发布时归一 |
| leftPageID / rightPageID | 可空页 ID | spread 至少一侧有效；single 的侧别也明确保存 |
| pageIDs | 计算值 | 按阅读方向展开，不能手工写出与左右页矛盾的值 |
| pairingSource | explicit / suggested | 自动建议必须确认后才能作为正式配对 |
| tagIDs / locationIDs | 数组 | 本单元显式标注 |
| preview | 资产引用 | 缩略图、大预览，均含 hash、尺寸、字节数 |
| presentation | 结构 | aspectRatio、装订方向、书脊样式、预览渲染版本 |

一个实际页面在同一版本的规范阅读顺序中只出现一次。跨页两侧不能指同一页，不能引用其他本/其他版本页。允许缺失左侧或右侧，但 UI 必须明确留白，不伪造实际页面和下载量。封面单独展示，不强行凑双页。

现有“首张右页，之后两两配对”的物理阅读规则可作为旧模板兼容显示，但不能直接认定为艺术设计的配对。无显式配对时显示“按页序浏览”，不在全库跨页搜索中冒充编辑确认的跨页。

### 5.3 协议示例（目标结构，不能直接用于当前 v1 发布脚本）

```json
{
  "schemaVersion": 2,
  "templateBookID": "21a8759e-e59f-58a0-b92e-86d41d88848a",
  "packageVersion": 2,
  "readingDirection": "ltr",
  "readingUnits": [
    {
      "id": "zhoushan-opening-spread",
      "kind": "spread",
      "title": "海风会替我们记得 · 开篇",
      "position": 1,
      "leftPageID": "opening-left",
      "rightPageID": "opening-right",
      "tagIDs": ["theme-sea", "style-collage"],
      "locationIDs": ["place-zhoushan"],
      "pairingSource": "explicit",
      "preview": {"thumbnailPath": "previews/spreads/opening-thumb.jpg"}
    }

```

示例省略现有必需字段与校验清单，页 ID 也是可读示例，实际使用发布快照中的真实 ID。升级需同时改 Python 包校验、发布时 ID 重映射、Swift DTO、下载闭包筛选与构建校验。跨页增加语义，建议正式使用 schemaVersion=2；layerSchemaVersion 不因纯展示变更而升级。新客户端兼容读 v1/v2，旧客户端通过最低客户端版本过滤或明确升级提示，不把 v2 伪装成 v1。

## 6. Django 数据库设计

继续扩展 diary_presets，无需另建一个跨页 app。文件存储继续使用 file_manager/OSS 基础设施，不把跨页模型放进通用文件模块。

第一阶段保留 Version.snapshot 作为发布内容的唯一权威数据；新增规范化检索投影，避免全面重写既有模型。

| 表/扩展 | 主要字段 | 约束与用途 |
| --- | --- | --- |
| Template 扩展 | metadata_revision、可选摘要 | 业务稳定身份；不把内容更新混入个人作品 |
| Tag | dimension、slug、name、active | dimension+slug 唯一 |
| TagAlias | tag_id、normalized_alias | 维护词典；同维度别名冲突需处理 |
| Location | parent_id、name、aliases、稳定外部编码可选 | 父级不能成环；坐标可选，不必定位用户 |
| CatalogEntry | version_id、entity_type、entity_id、title、parent_book_title、position、normalized_text、pinyin、search_revision | version+type+entity_id 唯一；本/跨页/单页统一检索结果 |
| CatalogEntryTag | entry_id、tag_id、source | source 区分 explicit/context；组合唯一 |
| CatalogEntryLocation | entry_id、location_id | 地点筛选，父级扩展在查询层处理 |
| CatalogEntryPreview | entry_id、object_key、hash、width、height、size、role | 可选独立表，或存 JSON；禁止保存短期签名 URL |
| Event 扩展 | actor、动作、前后 revision、摘要 | 记录配对、拆分、排序、标签变更和发布 |

CatalogEntry 不承载可编辑图层，只是可重建索引。阅读单元保存在 draft/snapshot，未来数据规模或后台并发需求确实需要时再拆成草稿关系表。避免数据库关系表和 JSON 同时被编辑形成双主数据。

索引建议：(version_id, entity_type, position, entity_id)、(entity_type, title)、各标签/地点关联反向索引；实际全文方案需在确认生产 MySQL/MariaDB 版本后选择，不能假定其中文全文配置相同。

发布流程：校验快照 → 生成预览并确认 OSS 可读 → 构建该版本完整索引 → 数据库事务切换 Template.current 与 catalog_revision → 发布成功。失败保持旧版可见。首版内容量小可同步写索引；将来异步索引必须在完成前不切 current，避免出现新本搜不到或只有半本结果。

下架只从公开目录和搜索排除，不删除用户已导入副本。旧版本、有效下载计划与审计记录保留；OSS 回收按引用计数/扫描和宽限期执行，不能点击删除单页就立即删共享 blob。

## 7. OSS 目录与预览生产

沿用 bucket zhaodkdream、北京区域及 traveldiary/presets/ 前缀。实际对象仍按内容寻址：

```text
traveldiary/presets/blobs/sha256/{hash}                 原素材、页预览、跨页预览
traveldiary/presets/releases/{templateUUID}/{version}/package.json
traveldiary/presets/staging/{uploadSession}/source.diarypreset.zip
```

逻辑包路径可使用 previews/spreads/{unitID}-thumb.jpg 和 -large.jpg，发布后映射到 hash key。不要另开“海岛/舟山/中文标题”的实体 OSS 目录；分类由数据库和 manifest 表达。重命名无需搬文件。

列表只读封面或跨页缩略图；点击预览才读大图；点击添加才下载页面 JSON 和素材。文件均由 iOS/浏览器直接访问 OSS 的短时签名 URL。API 返回结构、尺寸、hash 和授权 URL，不代理图片、ZIP 或素材字节。

建议派生尺寸：跨页缩略图宽 640 和 960，详情大图宽 2048；单页保留现有预览策略。尺寸是制作目标，不是把原图拉伸到固定比例。JPEG 用于不透明预览，确需透明用 PNG；色彩统一 sRGB，导出方向归一。压缩质量以肉眼验收为准，初始目标跨页缩略图 80–250 KB，2048 大图 300 KB–1 MB，复杂内容允许超过并告警。

跨页预览由同一版本的左右页渲染结果合成，hash 输入还应包含书脊样式和渲染器版本，任何一个输入改变都重做预览。若页面已带外框或装订图形，不叠加第二套书脊。外观装饰与正文资源分开，装饰不进入导入内容。

预览生成在制作电脑或独立处理 worker 中完成，大文件直传 OSS，低带宽 API 主机不拉整包生成图片。当前独立 worker 是否部署需实际核实，文档不假定它已运行。处理失败阻止该次发布，不进入人工审核状态；编辑确认配对属于内容编排操作，不是审批流程。

## 8. UI 详细设计

### 8.1 预设首页

从上到下：导航标题“预设手帐”与下载入口 → 搜索框 → 系列横向选择条 → 可折叠筛选 → “整本 / 跨页 / 单页”模式切换 → 结果数量与排序 → 卡片列表。

“全部”是系列筛选，不是一个实际 Series。切模式保留关键词、系列和风格，清除与该实体不兼容的筛选并轻量说明。每种模式单独保存滚动位置。搜索与筛选状态可恢复，不能每次返回都回列表顶部。

### 8.2 图片中的双列跨页网格

```text
[ 全部系列 ▾ ]   [跨页 ▾]   [筛选]          24 个跨页
┌──────────────────┐  ┌──────────────────┐
│  左页  │  右页   │  │  左页  │  右页   │
└──────────────────┘  └──────────────────┘
东福山 · 风比我们先到     青浜岛 · 留在海边的旧房子
舟山 · 2 页 · 云端         舟山 · 2 页 · 已缓存

┌──────────────────┐  ┌──────────────────┐
│  左页  │  右页   │  │  左页  │  右页   │
└──────────────────┘  └──────────────────┘
朱家尖 · 黑色石头白色浪花 海钓 · 今天轮到我当钓手
```

以上名称是参考图示例文案，正式名称以逐页内容编排结果为准。

两列卡片相同宽度、统一预览容器比例、图片 contain、不裁切；不同纵横比留中性背景。每张预览下方左对齐标题，副标题显示所属本和实际页数，再显示最多两个标签。不要把名称覆盖到图片上挡住原有文字。

推荐间距：边距 16–24 pt，列间距 12–20 pt，卡片间纵距 20–28 pt；标题 15–17 pt，副标题 12–13 pt。卡片采用清淡背景，避免高对比阴影抢内容。名称区域固定为最多两行对应的高度，保持每行底部对齐。

iPhone 普通竖屏跨页默认一列，避免两页缩小到不可辨认；提供紧凑双列选项满足快速总览。iPad/宽屏默认两列，大窗口可三列。每张跨页建议最小宽 300 pt，紧凑模式可低于此值但必须明确可点开。动态大字体自动减列，禁止为了维持两列压缩字号。此为自适应同一设计，并非将参考图的桌面密度强塞到手机。

卡片点击只预览；“使用”作为明确按钮/菜单动作。触控目标至少 44×44 pt。图片加载错误不隐藏名称和页面位置，保留占位与重试。不要因 URL 无效 compactMap 掉页面，造成页序和跨页错位。

### 8.3 一本详情与跨页预览

头部显示封面、本名、简介、系列/地点、实际正文页数、跨页数、资源体积与编辑能力；切换“跨页 / 单页 / 翻阅”。整本添加按钮固定底部，避开安全区。

跨页预览上方显示跨页名，下方显示所属本、左右页名与页码；支持捏合放大、双击缩放、前后跨页切换、定位单侧大图。横屏保留完整跨页，竖屏可切“看左页 / 看右页”。缩放状态下优先图片平移，缩小到适配比例后允许翻页，避免手势冲突。

动作分别为“添加这两页”“仅添加左页”“仅添加右页”。缺侧只显示实际可添加动作。“整本添加”始终意味着创建新本；从已有本发起则提示跨页将插入的位置。整本与两页不能共用模糊的“使用模板”按钮。

跨页总览与仿真翻书是两种展示：总览用于筛选，翻书用于连续阅读。减少动态效果设置开启时使用简单切换，不强制翻页动画。VoiceOver 朗读跨页名、所属本、左右页名、下载状态与操作。

## 9. 搜索设计

### 9.1 可搜索内容与匹配策略

首版搜索：本名、跨页名、页名、系列名、标签、地点、别名、经过编排的描述。拼音全拼/首字母通过离线生成索引支持，中文原词优先。不要把 PSD 图层名称、磁盘路径或文件 hash 加入用户搜索。

图片里的艺术文字只有被录入标题/描述后才能搜到。首版不自动 OCR；未来 OCR 可作为低权重候选文本，经内容人员纠错后采用，不宣称当前已支持。

同一维度多选使用 OR，不同维度使用 AND。例如地点“舟山或苏州”且风格“水彩”且实体“跨页”。地点选舟山包含其子地点。关键词与筛选共同生效。空关键词是浏览，不执行全文匹配。

默认排序：完整标题匹配 > 标题前缀 > 标题包含 > 地点/标签 > 父本上下文 > 描述；同分用运营 position、稳定 ID 排序。提供“推荐 / 最近发布”，不要把下载次数当首版必需指标。全部结果按本/跨页/单页分组，每组展示少量和“查看全部”，避免一本 63 页淹没其他本。

### 9.2 实现路径

初始中小规模使用数据库参数化查询和规范化文本，统一 Unicode NFKC、空白、大小写；%/_ 等 LIKE 通配符按文字转义。繁简、别名、拼音通过词典扩展，限制扩展数量防止查询膨胀。关键词上限 100 字符，默认每页 24、最大 60，设置查询超时与接口限流。

简单 contains 在大规模索引上可能全表扫描，必须测量。目标数据达到数万搜索实体或 P95 持续超过 300 ms 时评估独立搜索服务；这只是评估门槛，先看真实数据，不为首版强制安装 Elasticsearch。中文全文方案实施前单独确认数据库版本、分词与索引支持。

分页使用稳定排序的 cursor，绑定 query、filters、sort、catalog_revision；目录变更使旧游标失效时返回明确重刷提示。只索引 current 且 active 的版本；下架时同步失效缓存。查询结果携带实体 ID、版本和阅读单元 ID，点开时不能自动跳到新版本的同名页。

iOS 输入停止 300 ms 后查询，取消旧请求并用 request generation 防止旧响应覆盖新结果；中文输入法组合文本阶段不提交。滚动分页去重，不无限预取。离线时仅搜索已缓存的目录，顶部明确“离线结果”，不把它伪装成全库结果。

搜索历史只保存在设备，可清空；不默认记录用户私人作品标题到服务端搜索日志。错误信息不包含签名 URL 或令牌。

## 10. API 合约建议（新增，不表示现有路由已支持）

沿用 /api/v1/diary-presets/ 命名空间；最终路径在实施时保持现有客户端兼容。

| 请求 | 作用 | 返回重点 |
| --- | --- | --- |
| GET taxonomy/ | 系列、标签、地点筛选项 | IDs、名称、层级、revision |
| GET catalog/?kind=spread&q=海风&series=islands | 分页浏览/搜索 | entries、next_cursor、catalog_revision、匹配摘要 |
| GET templates/{id}/{version}/ | 已固定版本详情 | pages、reading_units、预览引用、能力、数量 |
| POST templates/{id}/{version}/plans/ | 生成选择资源的下载计划 | operation scope、page_ids、去重字节数、计划 ID |
| POST plans/{id}/urls/ | 刷新指定路径下载授权 | 短时签名 URL、expires_at |

计划请求明确 selection.kind 为 book / spread / pages；spread 带 reading_unit_id，服务端按该版本展开两页；不得相信客户端伪造的跨页成员。既有计划端点如已实现继续兼容，不同时维护两套不同授权逻辑。

列表不返回所有页与所有图层资源，只返回该卡片必要预览。图片缓存 key 用 hash+variant，不用签名 URL，授权刷新不重复存图。列表元数据与 URL 的过期分开管理，304 或本地目录缓存不能使客户端永久复用已过期 URL；提供按已授权预览资产刷新 URL 的批量接口或重新读取当前页。

管理 API 继续要求后台权限、revision 乐观锁；配对、拆分、批量标签、排序均作为完整操作写入 Event，冲突返回 409 并提示刷新，不覆盖另一管理员修改。

## 11. 下载、导入与本地存储

- 只浏览：只获取当前可见缩略图，预取下一屏；详情预取当前跨页和相邻跨页的大图，设并发与内存上限，不下载图层素材。
- 添加跨页：计算左右页资源闭包并按 hash 去重，共享背景/字体只下载一次；空白侧不计入下载。先完成并校验两页，再原子提交到目标本。
- 添加整本：展开规范阅读顺序，汇总真实页面闭包；不为每一页另建互不关联任务，不重复下载同一素材。
- 统一下载管理器展示“准备 → 下载 X/Y MB → 校验 → 添加 → 完成”，字节进度达到 100% 时不能提前显示添加完成。缓存命中的字节与本次需传输字节分开说明。
- 暂停/续传沿用已有分段与持久化基础；断网、进后台、应用重启后恢复状态。后台持续传输需另做 URLSession 后台会话能力验证，不能承诺现有实现一定持续下载。
- 下载任务固定账号、模板版本、选择页、目标本、插入锚点、operationID；重复点击复用正在进行的相同操作，用户完成后主动再添加允许新副本。
- 目标本在下载中被删、只读、切换账号或锚点移除，提交前重新校验；用户重新选目标，不能悄悄插入别处。
- 缓存以 hash 去重并校验；用户作品导入时拥有自己的引用/文件，清理预览缓存不得破坏已导入本。根据空闲磁盘检查缓存、暂存和副本所需空间。

用户本需要保存本地 readingUnits 及源模板 provenance：模板 ID、版本、源阅读单元 ID、源页 ID；导入后映射为新的本地页 ID。页名可改，排序可改，来源只用于追踪，更新模板不能覆盖作品。

跨页整体添加保持两页顺序与关系；只添加一侧时创建单页单元，不带悬空另一页 ID。原子导入不仅写两个页面文件，还要原子更新书本索引和阅读单元；失败不留半个跨页。

## 12. 后台编排与发布流程

后台导航：系列列表 → 本列表 → 本详情（内容编排 / 标签与搜索 / 预览 / 版本记录）。

内容编排左侧单页素材池，中间阅读单元列表，右侧选中单元属性。支持拖两个单页到左右槽、交换左右、解除配对、拆为单页、整组拖动、改单页/跨页名称、选择封面、预览手机和宽屏布局。

后台默认拖动整个跨页；移动其中一侧时弹出明确编辑选择“拆分后移动 / 取消”，这是防止内容误操作，不是发布审核。删除某页会展示受影响的配对、封面和阅读顺序；删除后缺侧允许保留为明确单侧单元，或同时拆分，不能自动与下一页重新配对。

单页已被一个单元使用时不可再拖入另一个规范单元；若要重复展示应复制页面实例并建立新 ID，素材仍可共享。跨页 ID 改名/调序不变，重新配对生成新 ID，并保留来源事件。

标签面板支持多选页批量赋值、删除、替换；操作前说明影响范围。自动建议名称/标签只作草稿，人工编排确认不影响“无审核直接发布”的产品要求。

标准过程：上传/选择已有页 → 填名称和分类 → 配对/排序 → 自动校验 → 生成预览 → 查看结果 → 发布新版本。自动校验失败必须指出具体页面和修复建议。发布成功后索引与目录同时切换，客户端刷新后可查到；已开始的旧版本下载继续遵循旧快照。

## 13. 舟山 v1 的接入方法

1. 从现有已发布 manifest 和制作选页记录建立“真实页 ID—源 PSD—页标题—预览”清单；不要从 OSS hash 猜文件含义。
2. 保留原有版本筛选：定海古城、沈家门、花鸟岛使用已选择的新版本；嵊山岛用第一版，排除初稿。配对工作不重新混入被淘汰页面。
3. 开篇明确：封面单独一个单元；指定跨页左页、右页配成“海风会替我们记得 · 开篇”。封面角色与装饰外壳区别标注。
4. 其余页面按地点、主题、画面连续性、左右版式逐组确认。文件名“左/右”只做候选匹配；没有把握的保持单页。63 页不能简单推断为 31 个跨页加封面，必须先确认实际角色和配对。
5. 建议地点包含定海古城、沈家门、朱家尖、东极岛、花鸟岛、枸杞岛、嵊山岛等，以实际页内容为准；“海钓”是主题而非地点。
6. 为每个单元填用户可读名称和少量标签，生成跨页缩略图，逐组核对中缝、标题、预览与编辑内容一致。
7. 在测试库发布新版本并测单页/跨页/整本添加；客户端 v2 协议兼容后再正式发布。保留 v1 的计划和副本，不清库、不重建现有用户数据。

## 14. 风险、边界与处理

| 问题 | 处理原则 |
| --- | --- |
| 插一页导致所有配对错位 | 保存显式配对，按 ID 引用，发布校验顺序 |
| 左右页视觉接不上 | 不只看文件名，制作端检查中缝；预览作为发布校验产物 |
| 奇数页、空白页、封面、外壳混淆 | 明确角色和真实页面数；视觉空白不伪造实体 |
| 一页删除后另一页怎么办 | 后台显式拆分/保留单侧，不自动改配 |
| 左右尺寸或比例不一致 | 首版同一本统一尺寸，发布阻止不一致；不暗中拉伸 |
| 参考图有书框而真实资源没有 | 外框属于可选展示皮肤，不制造用户作品内容差异 |
| 图片文字不可编辑 | 展示真实能力，不将图中大标题标成文字槽位 |
| 全库页面太多，搜索重复 | 按实体分组、父本折叠、分页及稳定排序 |
| 标签泛滥、同义词混乱 | 受控词典、别名和合并；保留实际来源 |
| 预览与版本内容不一致 | 版本绑定、hash 和渲染器版本校验，禁止旧图配新页 |
| 签名过期、403、弱网 | 有限重签/重试，401 走登录；403 不无限重试 |
| 大图导致内存峰值 | 按屏幕像素下采样，取消离屏任务，限制解码并发 |
| 页面 URL 失败导致数组缩短 | 保留实体与占位，不改变页序 |
| v1 客户端读取 v2 | 能力协商/最低版本门槛，新客户端兼容旧包 |
| 上下架与已下载冲突 | 已导入可用；新计划按可见权限；撤销策略另行定义 |
| 调用者枚举未发布页 | 所有详情/签名校验版本可见性和计划归属 |
| 公共读 OSS 绕过授权 | 新产物明确 private，匿名访问验收；不依赖 bucket 默认 ACL |
| 素材版权或真实人物隐私 | 制作阶段记录授权与来源，不上传私人原文件/定位元数据 |
| 跨页与物理页码奇偶矛盾 | 模板艺术配对优先；真实印刷排版另行校验，不能混为一谈 |
| RTL 等未来阅读方向 | 首版明确 ltr；结构预留，未实现前不宣称支持 |

## 15. 实施阶段与验收标准

### 阶段 A：结构和内容

完成 v2 Schema、阅读单元校验、旧 v1 兼容、后台配对和标题、发布索引、舟山编排。验收：改名不改 ID；插入/删除/重排不误配；旧版可读；源文件和真实页 ID 可追溯；发布失败旧版本仍可见。

### 阶段 B：展示和下载

完成整本/跨页/单页网格、标题与副标题、预览、两页联合导入、目标本关系持久化。验收：宽屏两列与参考图一致；小屏可读；单侧失败不产生半个跨页；只看卡片不下载素材；两页共享文件只传一次；暂停重启可恢复；账号隔离有效。

### 阶段 C：检索与性能

完成标签地点治理、实体分组、关键词排序、分页、离线缓存提示。测试“舟山”“东福山”“海风”“海钓”、拼音别名、繁简词、组合筛选和无结果；旧响应不覆盖新搜索，下架不泄漏到结果。

建议可测性能预算：首屏 12 张缩略图实际传输目标不超过 3 MB（复杂图片记录超额原因）；预览只保留当前及相邻单元；代表性网络下目录 API P95 目标 300 ms，设备首屏可交互目标 2 秒。测试需注明机型、网络和冷热缓存条件，目标不是当前测量结果。

必须覆盖：空本草稿、单页本、纯封面、奇数正文、缺侧、重复 ID、跨版本引用、坏图、中文长标题、大字体、深色模式、磁盘不足、签名过期、后台被杀、重复点击、管理员并发编辑、旧版本任务继续下载。

最终交付包括协议样例与校验器、数据库迁移、后台编排、iOS 三种展示、统一计划与导入、搜索 API、真实舟山样本、性能记录和操作文档。自动化用结构/事务/权限测试兜底；视觉配对与小屏可读性必须真机或模拟器验收。

## 16. 本轮设计采用的默认决策

- 系列为主分类，地点/风格/主题为多维筛选；不增加多层繁琐目录。
- 跨页必须有独立标题，图片下方显示；页名也独立保留。
- 整本存单页与阅读单元引用，跨页图片只是派生预览。
- 模板配对由内容编排明确确认，自动两两配对仅作旧版阅读兼容。
- 宽屏双列跨页，手机默认单列并允许紧凑双列。
- 发布仍为校验通过直接发布，不增加审批人员或人工审核队列。
- 继续 OSS 直传直读，API 不承担大文件转发。
- 本文只交付方案，不修改现有舟山 v1、数据库或进行服务器发布。
