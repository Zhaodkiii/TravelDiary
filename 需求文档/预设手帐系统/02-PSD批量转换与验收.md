# PSD 批量转换、发布与验收

版本：v1.1；日期：2026-10-14；状态：电脑端转换/校验工具和 Xcode 构建校验已落地；视觉真机审查继续逐包执行。

关联：[预设系统需求](./README.md)、[资源包协议](./01-统一资源包与加载协议.md)。

## 1. 工具目标与边界

制作人员准备多个本子及各页 PSD，一次批处理输出客户端可加载的 JSON、分层素材、页面预览和目录索引；新增路线不需要改 Swift 图层坐标或重新写一个加载器。

这是开发机上的离线制作工具；手机首版只读转换后的包。转换脚本不能修改 PSD 原文件。首个完整验收至少使用一个两页本和另一个系列的本，雨崩引言用于已知像素图层样本。

工具固定独立创建于 `/Users/dream/Documents/project/TravelDiary/PSD转换工具`，不放入 iOS 工程，不编入 App。目录包含 convert_psd.py、batch.py、validate.py、requirements.txt 和中文使用说明；工具不编入 App。输出到本工具的 output 目录，由用户手动移动或复制到 iOS 系列资源目录。解析库版本锁定并以真实样本验证，不承诺解析所有 Photoshop 特性。

## 2. 输入组织与映射

工具接受单个 PSD 或目录；目录中的 PSD 按相对路径自然排序成为页序。推荐为每本建立干净的源目录，避免把备份 PSD 误当成页面；页面必须同尺寸。稳定 bookID、系列和版本通过参数提供。可选 mapping JSON 以页相对路径及层级索引路径标记照片槽位、真文字、文本框与锁定状态；未知层路径导致转换失败。

当前实现支持指定 role=photo/sticker/text。原生 text 映射需显式填写经人工校对的文案、fontSize 和 size；照片和文字槽位生成到 editableSlots。工具不会自动把名为“标题”的像素层变成文字。

## 3. 命令行

```sh
cd "/Users/dream/Documents/project/TravelDiary/PSD转换工具"
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt

.venv/bin/python convert_psd.py "/路径/苏州PSD目录" \
  --output "/路径/output/城市系列/suzhou.diarypreset" \
  --title "苏州" --book-id city-suzhou --series city --version 1
.venv/bin/python validate.py "/路径/output/城市系列/suzhou.diarypreset"
```

批量转换使用 JSON 数组清单，字段为 input、output、title、bookID、series、可选 version 和 mapping；用 `.venv/bin/python batch.py preset-batch.json` 执行。每本独立失败并汇总退出码。输出目录必须新建且以 `.diarypreset` 结尾；转换不覆盖已存在本。

转换通过后，用户把整个 `.diarypreset` 目录移动到 `TravelDiaryClient/Projects/App/Resources/DiaryPresets.bundle/<系列目录>/`，构建时资源检查自动校验全部文件和摘要，运行时按 package.json 自动发现。当前系列目录是徒步系列、城市系列、美食系列；已有系列追加一本无需改 Swift。新建系列才需扩展 series.json。

## 4. 图层转换规则

| PSD 内容 | 项目输出 | 编辑能力与限制 |
| --- | --- | --- |
| 普通像素层 | 透明 PNG + object 内容 + 内部 sticker/photo | 可独立打开、移动和装饰；不能还原已丢失的文字或源图 |
| 空普通层 | 跳过并记录 | 不生成零尺寸对象 |
| 被映射为槽位的空层 | 创建有明确尺寸的照片占位 | 无尺寸映射则失败 |
| 图层组 | canvas 对象内容 + 子对象 | 保留父子关系和顺序；组内坐标由源画布坐标换算 |
| 可解析文字层 | 经能力验证的 text 或经批准的栅格图片 | 必须满足字体和排版支持，否则阻止“可编辑文字”发布 |
| 图片化文字 | sticker 对象 | 报告为图片文字，绝不伪装 text |
| 嵌入/链接智能对象 | 在支持解析且可访问时转换内部图层，否则显式栅格化 | 链接缺失失败；栅格化后无法继续恢复原内部结构 |
| 图层透明度/简单遮罩 | 烘焙到 RGBA | 外观保留，原遮罩参数不可编辑 |
| 混合模式、剪贴关系、调整层、复杂效果 | 评估依赖组整体烘焙或拒绝 | 不能逐层栅格后假设效果与原图一致 |
| PSD 笔刷像素层 | 图片对象 | 不生成假的可擦除 PencilKit 笔画 |
| 隐藏层 | 保留 supported 图层及 visible=false | 不进默认预览；无支持能力仍必须报告 |

严格模式遇到无法表达的可见效果失败；需要烘焙时在 mapping 显式批准，并列出失去独立编辑的图层。依赖背景的混合效果可能需要扩大烘焙范围，不能只输出单层 PNG 就宣布还原成功。

导出图像使用完整层边界及透明度，保存原点偏移；不能把每层统一拉满画布。若裁去透明边距，必须同时补偿图层位置。负坐标及画布外装饰保留，页面最终导出才按页面边界裁剪。源文件 RGB/CMYK、位深和 ICC 差异需要显式转换到首版支持的 sRGB/8 位，并报告，不能把配置文件差异忽略成“无损”。

图层顺序必须用测试证实解析器返回方向，再转换为项目从底到顶顺序。透明度不能在素材与渲染模型中重复应用。

## 5. 照片与文字的制作要求

想让用户“替换照片”，必须指定 photo 层和外框/取景参数。已裁切的 PSD 像素层只能提供当前像素，无法凭转换恢复被删掉的原图；若要完整取景范围需制作端补充原照片资源。

想让用户“修改文字”，须有原生可解析文本，或由制作者手工补充文案、字体、字号、文本框和排版映射。OCR 可在后续作为辅助输入，不能未经核对自动发布。当前客户端文字样式较简单，任意 PSD 富文本不能直接保证保真；超出支持范围要升级渲染能力，或保留为图片并标明限制。

标题、正文、日期等可编辑槽位必须实际试改；验证中文、多行、长句、空文本及缺字。字体缺失不能静默改变布局；正式包需有可用替代方案或拒绝发布。

雨崩引言现有 15 层全部是有效像素内容，第一版转换可保留为图片对象；需要“可编辑标题正文”的版本必须另做文字重建，不能通过修改 kind 字段实现。

## 6. 输出及转换报告

工具产物是每本独立、自包含的 .diarypreset 目录包，内含 package.json、pages、objects、assets 和 previews；不是整个应用资源 bundle。iOS 资源容器为 DiaryPresets.bundle，用户将单本包放进对应系列目录，详见协议。另在 reports/<bookID>/<version>/ 保存报告，不加入手机包：

- source SHA-256、转换器版本、依赖版本、映射摘要、执行结果。
- 每页输入尺寸、颜色处理、源层数量、空层/隐藏层数量、输出对象数量、层序映射。
- 真文字/图片文字/照片槽位数量、资源字节数、重复素材节省量。
- 每个降级或失败的源层路径、原因、烘焙范围、剩余编辑能力。
- PSD 合成参考、转换结果预览、差异图以及人工审核结论。

发布 packageVersion 必须由制作人员明确递增，脚本不能因每次执行时间不同自动制造内容版本。

## 7. 预览、校验与发布步骤

1. 解析所有页及依赖并生成暂存资源，检查尺寸和映射。
2. 做 package 版本、图层语义、文件引用闭包、SHA-256 和素材可解码校验。
3. 转换工具按输出图层数据合成预览；Xcode 测试样本已将内置雨崩预览与 iOS 原生渲染做像素误差对照。新包仍应检查边界情况。
4. 在统一尺寸和色彩空间比较 PSD 合成图与项目预览，输出差异指标与热图。初始容差需结合真实样本校准，不能把未经验证的固定阈值当成保真承诺。
5. 人工检查文字、边缘透明、层序、裁切、分组和可编辑槽位。
6. 用户将审核通过的单本 .diarypreset 目录包移入 iOS 对应系列目录；无需修改 Swift 注册表。Xcode 构建阶段脚本检查复制到 App 的资源树，启动时扫描包清单建立展示目录。
7. 真机离线完成浏览、整本/单页导入、编辑、保存重开、导出；通过后标记该版本发布。

## 8. 验收矩阵

| 场景 | 必须结果 |
| --- | --- |
| 切换徒步/城市/美食系列 | 直接展示雨崩、苏州等预设本，目录来自 JSON，无需 Swift 新增坐标 |
| 整本两页导入 | 页序、封面、名称正确；保存重开仍能分别编辑 |
| 同一本导入两次 | 两个独立副本，修改一个不影响另一个 |
| 单页加入现有本 | 只复制依赖闭包，插入位置正确，原封面不变 |
| 单页创建新本 | 只含选定页，尺寸和封面正确 |
| 竖页加入正方形本 | 等比居中，无拉伸、裁切或遗漏笔画 |
| 智能对象独立编辑 | 各图层可打开，装饰/背景/涂鸦保存返回位置正确 |
| 框内替换照片 | 外框与装饰不动，取景合法，原模板不变 |
| 真文字和图片文字 | 能力标识准确，真文字可改，图片字不误导 |
| 删除模板缓存或升级应用 | 已导入作品仍独立加载 |
| 导入中断及重试 | 无半本坏页，同 operationID 不重复创建 |
| 目标本同时排序或被删除 | 检查最新目录并明确失败/重选，不覆盖更新 |
| 缺文件、错 hash、循环引用、越界路径 | 明确拒绝包，其他有效预设可继续使用 |
| 同名素材/中文路径 | 无覆盖与找错文件，包内路径准确 |
| 不支持字体/混合效果 | 报告且阻止未经批准发布，无静默降级 |
| 两页复用图片但独立内容 | 图片可去重，页面与对象编辑互不影响 |
| 转换重复运行 | ID 稳定，无无意义重复资源；失败结果不进目录 |
| 断网/无相册权限 | 内置预设正常浏览导入；替换照片权限单独处理 |

## 9. 尚需实测的参数

内置包总容量、单包页数、解码像素预算、预览压缩质量、冷启动加载时间和导入耗时，需要真实素材和目标手机测量。不得为了凑数量发布只有名称没有内容的路线分类。后续云端接入另补下载、可信来源、断点续传和离线缓存验收，现阶段只保留接口。

例如把完整的 `output/城市系列/suzhou.diarypreset` 移动到 `/Users/dream/Documents/project/TravelDiary/TravelDiaryClient/TravelDiaryClient/Projects/App/Resources/DiaryPresets.bundle/城市系列/`。不能只移动 package.json 或素材图片，也不要求同时移动其他本。同一系列可以持续追加新的本包。输出中的报告和源 PSD 留在电脑工具目录，不随本包搬入 App。

转换工具负责生成与校验；iOS 构建只负责资源纳入与发布校验，不执行 PSD 转换、不依赖本机 Python 环境。应用启动读取已随 App 打包的目录，不读取电脑源目录。修改电脑资源目录后必须重新编译并安装应用才能在设备上看到新本。

新增验收：只移动一个苏州本包到城市系列目录，不改 Swift 和 catalog，重新构建安装后启动应用，“预设 → 城市系列”自动出现苏州，整本和单页均可预览导入。
