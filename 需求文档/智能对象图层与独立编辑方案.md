# 智能对象图层与独立编辑方案

日期：2026-10-14  
版本：v0.1  
状态：根据最新需求新增的产品与数据设计，待实现。

关联：[总需求](./手帐项目总需求文档.md)、[原编辑器设计](./画布编辑器详细设计.md)、[整体架构](./画布编辑器整体架构与目录设计.md)、[文件设计](./画布文件设计/README.md)。

## 1. 本次需求的核心

**照片、贴纸、文字在主画布上各自是一个独立对象；每个对象都可以单独打开，在自己的编辑画布中添加背景、照片、文字、贴纸、画框和涂鸦。点击完成后，整个对象回到主画布，仍然可以再次打开修改内部内容。**

本项目称其为“智能对象图层”。这里描述的是本产品的编辑模型，不要求读取或保存 Photoshop 智能对象及 PSD 文件。

用户主要看到两层操作：

1. **主画布排版**：摆放和调整整个对象的位置、大小、方向、前后顺序。
2. **对象内部编辑**：只处理选中对象的内容与装饰。

本方案扩展原来的“照片组合”：照片、文字、贴纸三种起点统一使用对象容器。原来的“只有页面有画笔”调整为“页面有整页画笔，每个对象另有自己的画笔”。

## 2. 三个典型例子

### 2.1 照片对象

```text
主画布添加照片
→ 选中照片，点击“编辑对象”
→ 打开独立照片编辑画布
→ 调整照片取景，添加画框、胶带贴纸和日期
→ 点击“完成”
→ 主画布显示带画框、贴纸和日期的完整照片对象
```

移动或旋转照片对象时，画框、贴纸和日期一起变化。再次打开后，照片仍能替换，画框仍能更换，日期仍是可编辑文字。

### 2.2 文字对象

```text
主画布添加“今天很开心”
→ 选中文字，点击“编辑对象”
→ 添加黄色背景、星星贴纸和下划线涂鸦
→ 完成后成为一张可整体摆放的文字卡片
```

背景位于文字后方，星星是独立内部图层。修改文字不会将背景或贴纸变成文字图片的一部分；调整文字换行不会自动移动所有装饰。

### 2.3 贴纸对象

```text
主画布添加一张猫咪贴纸
→ 选中并打开独立编辑画布
→ 给猫咪画胡须、加帽子贴纸和一句文字
→ 完成后作为一个新的贴纸对象回到主画布
```

涂鸦跟随猫咪对象移动。再次进入后可以擦除涂鸦或移除帽子，原始猫咪素材保持完整。

## 3. 主画布结构

```text
手帐页面
├── 页面背景
├── 对象图层列表（从底到顶）
│   ├── 照片对象 A
│   │   ├── 对象背景
│   │   ├── 主照片
│   │   ├── 画框
│   │   ├── 胶带贴纸
│   │   ├── 日期文字
│   │   └── 对象涂鸦覆盖层
│   ├── 文字对象 B
│   │   ├── 背景色块
│   │   ├── 主文字
│   │   ├── 星星贴纸
│   │   └── 对象涂鸦覆盖层
│   └── 贴纸对象 C
│       ├── 主贴纸
│       ├── 附加贴纸
│       └── 对象涂鸦覆盖层
└── 页面画笔覆盖层
```

页面对象数量与内部图层数量不同。例如页面有三个对象，它们内部可以有十几个图层。在主画布只选中整个对象；打开后才选中其内部图层，减少误触。

## 4. 交互流程与界面

### 4.1 从选照片进入

保留已确定的入口：系统照片选择器 → 读取照片 → 创建页面和照片对象 → 打开主编辑器并选中照片对象。

默认先进入主画布；选择“编辑对象”再进入照片独立编辑视图。若以后希望选照片后直接进入对象编辑，可调整入口导航，不改变数据结构。

### 4.2 主画布选中状态

- 单击选中对象，显示边框、缩放旋转操作及“编辑对象”。
- 拖动、缩放、旋转、复制、删除与层级调整作用于整个对象。
- “编辑对象”为明确入口；可增加双击作为快捷方式，但不依赖用户发现隐藏手势。
- 页面独立贴纸和独立文字仍然存在，只是统一拥有智能对象外壳。

### 4.3 独立对象编辑视图

建议采用独立全屏页面：

| 区域 | 内容 |
| --- | --- |
| 顶部 | 取消、对象名称、撤销、重做、完成 |
| 中部 | 对象本地画布，透明区域用棋盘格表示 |
| 底部添加栏 | 图片、文字、贴纸、背景、画框、画笔 |
| 内部图层面板 | 当前对象的图层顺序、锁定及显示状态 |
| 上下文工具 | 当前照片裁剪、文字输入、贴纸变换等 |

独立视图只显示当前对象。主页面中的其他对象、页面背景和页面涂鸦不应合入对象内容。

### 4.4 完成与取消

建议采用工作副本机制：

- 打开时从已提交对象复制编辑状态，保留对象 ID 和初始内容版本。
- 编辑过程中在工作副本中修改，独立视图内可以逐步撤销。
- “完成”校验资源和内容后，提交整个对象的新版本，更新主画布预览。
- “取消”丢弃本次工作副本，主画布对象保持打开前的状态。
- 主画布撤销一次“编辑对象”，恢复对象打开前的完整内容；重做恢复提交后的内容。
- 返回手势或关闭按钮有未提交修改时，提供继续编辑、保存返回或放弃修改的明确选择。

这一规则替换原方案中“完成组合编辑仅切换编辑范围”的行为。对象独立编辑是一次明确事务，不把内部每个动作和完成动作重复记录到主页面历史。

## 5. 数据模型：外部摆放和内部内容分开

```text
SmartObjectLayer
  id                       页面对象身份
  name                     显示名称
  visible / locked
  opacity                  整个对象的不透明度
  transform                对象在页面的位置、倍率、旋转、锚点
  contentId                引用独立对象内容

ObjectContent
  id                       对象内容身份
  revision                 内容版本
  role                     photo / text / sticker
  primaryLayerId           主照片、主文字或主贴纸
  referenceSize            稳定的本地参考尺寸
  origin                   固定本地原点
  background               可为空
  layers[]                 内部图层，顺序从底到顶
  drawingRef               对象涂鸦，可为空
```

`role` 决定默认工具与初始内容，不限制对象只能容纳同类型图层。照片对象中可以加文字，文字对象中可以加照片，贴纸对象中可以加另一张贴纸。

`primaryLayerId` 用于“替换主照片”“编辑主文字”等快捷操作，不决定前后顺序。删除主内容需要明确处理：首版建议保留一个可替换的主内容槽位，用户删除整个对象则从主画布完成。

内层基础类型为 image、text、shape/frame。画框属于独立装饰层；裁剪蒙版属于被裁剪图片的属性，二者不能混为一份数据。

## 6. 对象层级与嵌套边界

页面 layers 决定对象之间的层级；对象内部 layers 决定照片、背景装饰、文字、贴纸之间的层级。

对象 A 对外整体排序，页面上的对象 B 不能直接插进 A 内部两层之间。需要这种效果时，把对应装饰添加到 A 内部。

首版建议开放“页面 → 对象编辑器 → 内部基础元素”两级编辑范围。内部照片可以选中后打开裁剪/替换面板，文字可以打开输入与样式面板，贴纸可变换；这些都是当前对象编辑器中的内容处理。

**尚待后续决定：是否允许内部任意元素再转换为一个可独立打开的子智能对象。**若支持，需要完整的父子编辑栈、版本递归提交和导航面包屑。本轮先不把无限嵌套作为已确定范围。

## 7. 位置、大小和方向如何保持

### 7.1 两套坐标各自负责什么

- 外部 transform 决定整个对象在手帐页面上的位置、缩放和旋转。
- 内部图层 transform 决定照片、文字、贴纸在对象本地坐标中的排布。
- 独立编辑器查看缩放只改变显示，不能写入任何内容 transform。

```text
屏幕坐标 = 页面查看矩阵 × 对象外部矩阵 × 内部图层矩阵 × 图层本地点
```

打开独立编辑器时，使用对象本地坐标显示，通常摆正呈现，不带入对象在页面上倾斜的角度。点击完成后重新应用原外部矩阵。

### 7.2 完成后不能跳位置

对象完成编辑时默认只替换 content 版本，不修改外部 position、scale、rotation、pivot。因此给照片新增画框或给文字增加背景，不会导致主画布对象重新居中。

允许装饰超出主照片原始边缘。新增装饰可以扩大可见边界，但不会自动修改固定原点与锚点。预览图必须同时记录它对应的本地 bounds；不能仅保存 PNG，然后把 PNG 左上角当作对象原点。

例如对象本地可见范围从 `(0,0,400,300)` 扩展成 `(-20,-20,440,340)`，缓存图片应在本地 `(-20,-20)` 处绘制。对象在页面上的原始 transform 保持不变，照片主体不会平移 20 个单位。

## 8. 背景、画框和涂鸦

### 8.1 对象背景

文字可添加纯色、圆角色块或图片背景，背景只属于该对象。默认参考对象本地画布尺寸；若需要随文字自动增高，应明确 `fitToTarget + padding` 约束，不能靠每次重开猜测。

首版可先提供手动背景尺寸；自动随文字变化的背景作为可选的显式模式。两种模式都需要持久化。

### 8.2 照片画框

画框至少分为：

- 简单边框：颜色、宽度、圆角等参数绘制。
- 装饰画框：透明 PNG 或相框素材作为独立内部层。

建议用 targetLayerId 指向对应照片，并保存画框样式与内外边距。照片框尺寸变化后根据关联重新计算画框；照片替换只改变图像资源与取景，不删除画框。

默认置于目标照片前方；初始插入在照片后一个数组位置。之后用户可在对象内部调整画框与贴纸的顺序。删除目标时必须删除或解除关联的画框，避免悬空引用。

### 8.3 两种画笔范围

| 绘画位置 | 保存归属 | 移动对象时 | 覆盖范围 |
| --- | --- | --- | --- |
| 主页面 | Page.drawingRef | 留在页面原位置 | 所有页面对象上方 |
| 独立对象视图 | ObjectContent.drawingRef | 跟随对象整体变换 | 当前对象内部内容上方 |

对象画笔不保证位于其他页面对象上方。如果照片对象被另一个页面对象遮挡，它内部的涂鸦也一起被遮挡。只有页面画笔覆盖整个页面。

首版对象画笔默认允许在对象画布范围涂鸦，不自动按贴纸透明像素裁剪。若需要“只能画在贴纸轮廓内”，应另提供明确的蒙版模式。

## 9. 本地文件结构

扩展现有不可变修订方案：

```text
<documentId>/
├── CURRENT.json
├── revisions/<revision>/
│   ├── manifest.json
│   ├── pages/<pageId>.json
│   └── objects/
│       ├── <photoContentId>.json
│       ├── <textContentId>.json
│       └── <stickerContentId>.json
├── assets/
│   ├── 原照片文件
│   ├── 贴纸与相框图片
│   └── 字体资源
├── drawings/
│   ├── <页面绘画内容哈希>.drawing
│   └── <对象绘画内容哈希>.drawing
├── drafts/<editSessionId>/
│   └── 未完成对象编辑草稿
└── cache/objects/
    └── 可重新生成的透明预览图
```

manifest 增加对象内容索引 `contentId → 路径`。页面对象只引用 contentId；对象文件保存内部图层与 drawingRef；assets 仍按资源 ID 共用。

首次实现可以在每个完整修订中保存全部页面和对象 JSON，先保证提交一致。图片与绘画 blob 使用不可变资源复用，不随着对象移动反复复制。

完成对象编辑时，将新对象内容与页面引用作为同一次文档提交发布，最后更新 CURRENT。必须避免页面指向新对象内容，但对象文件尚未保存的状态。

未完成编辑可写入 drafts 用于异常退出恢复；该草稿不影响已提交主画布。再次进入时提示恢复或放弃。取消编辑后清理草稿，素材需在所有文档、草稿、历史及导出引用释放后再回收。

## 10. 缓存与再次编辑

主画布可使用对象透明预览图提升流畅度。缓存键至少包含 contentId、内容 revision、输出比例和渲染版本；缓存记录对应本地可见 bounds。

编辑完成使该对象缓存失效；移动对象通常不改变其内容缓存，只有显示清晰度需求变化才需要更高分辨率缓存。

打开对象必须读取内容 JSON、原素材和原生绘画数据。缓存缺失可以重建，不能失去编辑能力。导出使用对应版本的完整内容或满足输出分辨率的已验证缓存，不直接拉伸手机上的低清预览。

## 11. 复制、版本与撤销

- 首版复制对象生成新 layerId 和新 contentId，内容深复制，图片资源可共用。修改副本不影响原对象。
- 不默认采用多个对象共享同一可变 contentId 的联动副本；若未来支持，应有明确“关联复制”功能。
- 对象内部使用自己的临时历史，页面使用页面历史。
- 完成对象编辑产生页面级 `UpdateObjectContent` 命令，记录前后内容版本及资源引用。
- 对象编辑期间首版锁定主画布修改；完成前验证对象仍存在、内容版本仍匹配。
- 返回主页面后撤销，恢复对象前一完整版本；再次进入独立编辑器必须读取已恢复版本，不能复用过期工作副本。

## 12. 核心文件与接口调整

在现有 DiaryEditor 模块中增补或调整：

| 文件 / 类型 | 职责 | 核心方法 |
| --- | --- | --- |
| DiarySmartObjectLayer | 主页面对象的外部摆放及内容引用 | 创建照片/文字/贴纸对象 |
| DiaryObjectContent | 独立对象的本地画布、主元素及子层 | 校验内容、计算可见边界 |
| DiaryObjectEditSession | 工作副本、内部选择及撤销 | open、execute、undo、redo、commit、cancel |
| DiaryObjectEditorScreen | 独立全屏对象处理视图 | 进入、完成、取消、内部工具切换 |
| DiaryObjectRenderer | 内部图层、背景、画框与绘画合成 | render、visibleBounds、renderPreview |
| DiaryObjectRepository | 内容文件和未完成草稿 | loadContent、saveDraft、discardDraft |
| DiaryDocumentStore | 页面及对象版本一致提交 | saveDocumentSnapshot、recover |
| DiaryObjectPreviewCache | 缓存图片和对应本地 bounds | resolve、invalidate、purge |
| UpdateObjectContentCommand | 页面历史中的一次对象编辑 | apply、revert |

核心提交流程：

```text
主画布选择对象
→ loadContent(contentId)
→ ObjectEditSession 创建工作副本
→ 独立视图编辑，记录内部历史
→ commit 校验并产生新内容版本
→ 页面执行 UpdateObjectContentCommand
→ 保存对象和页面的完整修订
→ 缓存失效并刷新主画布
```

## 13. 与当前原型的差异

当前开发中的原型已按照片组合、内部贴纸文字和页面画笔开始实现；本方案涉及进一步升级，不能将已有“编辑组合”入口视为已满足全部需求。

需要新增：

1. 三种元素统一的智能对象容器及 contentId 引用。
2. 真正独立的对象编辑页面与完成/取消工作副本。
3. 文字对象背景、照片画框及对应约束。
4. 每个对象独立的涂鸦数据。
5. 页面与对象两级历史，以及对象版本整体提交。
6. 对象内容文件、草稿恢复与带 bounds 的透明缓存。

现有存档升级时，照片组可迁移为照片对象，页面普通文字和贴纸分别包装为对应对象，保留原始图层 ID 映射、坐标和层级；原页面画笔仍留在页面。新协议必须递增版本，不使用旧 schemaVersion 静默解释新结构。

## 14. 实现顺序

| 阶段 | 工作 | 完成标准 |
| --- | --- | --- |
| A | 统一对象模型、独立编辑页面、工作副本提交 | 照片打开、编辑、完成、取消都正确 |
| B | 照片内部贴纸文字与画框 | 完成后整体显示，再次打开仍可分别修改 |
| C | 文字对象与背景 | 文字可改单字、换行，背景与装饰保留 |
| D | 贴纸对象与对象涂鸦 | 涂鸦跟随贴纸，页面笔画不跟随 |
| E | 存档迁移、草稿、缓存和输出 | 重开与导出保持外部位置及内部内容 |

## 15. 验收场景

1. 添加照片并独立打开，增加相框和日期；完成后整组可拖动，再打开日期仍能修改。
2. 文字加背景和星星贴纸；修改文字后背景、贴纸按已保存规则保留，文字不变成不可编辑图片。
3. 贴纸上涂鸦；返回主页面旋转贴纸，涂鸦跟随旋转。
4. 同时存在页面笔画与对象笔画；移动对象时仅对象笔画跟随。
5. 对象原本已缩放旋转，独立编辑新增越界装饰；返回后主体位置、角度、倍率不跳变。
6. 独立编辑点击取消，主页面对象与页面历史均保持打开前状态。
7. 完成后在主页面撤销一次，恢复完整旧对象；重做恢复新对象。
8. 复制对象后编辑副本，原对象不变化。
9. 保存退出重开，三类对象都能继续独立编辑，内部素材、文字和笔画完整。
10. 清理对象预览缓存后重开，作品与编辑能力不受影响。
11. 输出只包含实际对象画面，透明棋盘格、选中框及编辑工具不进入成品。

## 16. 本轮决策与剩余范围

已按用户描述确定：三类独立对象、独立打开处理、照片可加画框贴纸、文字可加背景贴纸、贴纸可涂鸦、完成后整体返回。

本稿给出的设计选择：工作副本完成/取消、独立对象画笔、固定原点与锚点、对象内容独立文件、普通复制内容独立。

后续再细化：内部智能对象继续嵌套的深度、贴纸轮廓内涂鸦蒙版、背景自动适配文字、具体相框素材及样式范围。它们不阻塞第一阶段的独立对象编辑闭环。
