## 1. 文档定位与需求状态

本文汇总手机手帐项目的产品目标、编辑流程、图层模型、文件存储、加载保存、技术边界、阶段计划及验收标准。本文描述目标能力，不代表当前工程已经实现。

本需求对应现有 TravelDiary 客户端中的手帐业务。现有账号、相机、文件、网络等模块作为集成背景，不因本文自动改变其职责。工程背景见[现有项目汇总](../总领文档/项目汇总.md)。

全文采用以下状态：

- **已明确**：用户直接提出的能力和约束。
- **建议基线**：根据讨论形成的可执行设计建议，供评审确认；正文中的默认规则均属此类，除非明确标注已明确。
- **待确认**：影响产品范围或技术实现、尚未获得明确结论的事项，集中列于第 15 节。

### 1.1 已明确的需求

1. 主要在手机上制作手帐，提供预设模板。
2. 用户可以添加、替换、拖动和编辑照片，添加贴纸和文字。
3. 照片、贴纸、文字可独立编辑，参考 PSD 的分层组织思路。
4. 一张照片可以配上独立的贴纸、文字图层，再作为整体放入主手帐背景。
5. 页面也可以直接放置独立贴纸和独立文字。
6. 画笔独立存在，覆盖所有普通内容图层。
7. 首版先导出图片；PDF、云同步和深层分组后续再做。
8. iPhone 优先，照片组合保留分层，贴纸允许伸出照片边缘，画笔覆盖整页。
9. 先完成单页最小原型，验证编辑、裁剪、统一撤销、保存重开和导出一致性，再扩展模板库、多页、素材库与整本批量导出。

### 1.2 建议基线

- 一本手帐支持多页；每页具有背景、内容图层和画笔覆盖层。
- 照片与装饰通过分组组合，完成组合编辑后保留内部图层，支持再次修改。
- 数据采用图层树，首版交互只开放页面与照片组合两个编辑范围。
- 保存采用本地文档目录，素材和排版分开；通过资源 ID 建立引用。
- 优先按 iOS / SwiftUI 方向开展技术验证；不将某个第三方编辑器直接作为文档模型。
- 原型先支持当前页图片；完整首版扩展整本按页图片。PDF、云同步、深层分组不纳入首版；在线电子相册另立范围。

## 2. 产品目标与范围

### 2.1 产品定位

面向普通用户的手机手帐排版工具。用户从模板开始，将照片、文字、贴纸和手绘内容组织成可保存、可再次编辑的作品。

核心价值是降低排版门槛，让照片替换、装饰、文字记录和页面整理在手机上顺手完成。PSD 用于参考分层、分组和非破坏性编辑思路，不意味着需要兼容完整 Photoshop 功能。

### 2.2 核心模块

| 模块 | 主要职责 |
| --- | --- |
| 手帐与页面管理 | 创建作品、封面、页面增删复制与排序 |
| 模板系统 | 预设布局、照片占位、默认文字与装饰 |
| 画布编辑器 | 选中、移动、缩放、旋转、层级、锁定、撤销 |
| 照片与素材 | 导入、替换、裁剪、贴纸和背景资源 |
| 文字与画笔 | 可编辑文字、整页顶层绘画 |
| 文档存储与导出 | 自动保存、恢复编辑、资源加载、成品输出 |

### 2.3 首版范围与实施顺序

完整首版目标包含模板制作闭环、基础多页管理、照片组合、页面独立元素、顶层画笔、统一撤销重做、自动保存和图片导出。先实现单页原型，原型通过后再扩展模板库、多页管理、素材库和整本批量导出；原型不等于完整首版。

详细规则见[画布编辑器详细设计](./画布编辑器详细设计.md)，任务顺序及验证门槛见[最小原型实施与验收计划](./最小原型实施与验收计划.md)。

后续候选能力包括多选、任意组合与解组、深层嵌套、滤镜与调色、抠图、复杂蒙版、混合模式、PDF、印刷参数、云同步、协作及模板市场。首版不承诺 PSD 文件导入或导出。

## 3. 术语与基本规则

| 术语 | 定义 |
| --- | --- |
| 手帐文档 | 一本可编辑作品，包含页面、资源索引和必要素材 |
| 页面 | 固定设计尺寸的独立排版区域 |
| 图层 | 可独立控制的内容对象，含位置、变换、显示与锁定状态 |
| 照片组合 | 具有照片用途的分组，包含照片及所属装饰 |
| 页面元素 | 直接属于页面、独立参与页面排序的贴纸或文字等 |
| 照片外框 | 照片的显示范围及形状，与框内取景分开保存 |
| 素材资源 | 照片、贴纸、背景、字体等实际文件 |
| 编辑范围 | 当前编辑整个页面，或某一个照片组合 |
| 画笔覆盖层 | 固定在内容图层上方的页面绘画数据 |

只有分组包含子图层。照片、文字和贴纸是叶子节点；“在贴纸上添加文字”表示两者组成一个分组，不表示贴纸节点直接拥有文字子节点。

“合并到页面”表示将组合放入页面并整体操作，不表示永久压平为图片。最终成品导出可以合成像素，原作品仍保留分层。

## 4. 用户流程与界面

### 4.1 主流程

```text
创建手帐 → 添加页面 / 选择模板 → 填充或添加照片
    → 编辑照片组合（照片、贴纸、文字）
    → 调整页面布局、添加页面贴纸和文字
    → 顶层绘画 → 自动保存 → 预览 → 导出
```

添加照片后直接放入页面，自动建立照片组合，不强制先进入装饰界面。用户需要时选择“编辑组合”。已保存作品重新打开后应能继续编辑每个元素。

### 4.2 编辑界面

| 区域 | 内容 |
| --- | --- |
| 顶部 | 返回、撤销、重做、保存状态、预览或导出入口 |
| 画布 | 当前页、选中框、变换手柄、参考线 |
| 底部添加栏 | 照片、贴纸、文字、背景、画笔 |
| 上下文工具栏 | 根据选择展示替换、裁剪、样式、层级、复制和删除 |
| 图层面板 | 当前范围中的对象、缩略图、显示与锁定状态 |
| 页面入口 | 页面缩略图、切换及页面管理 |

进入照片组合时明确显示当前编辑范围并提供“完成”返回页面。在当前范围新增元素，默认归属该范围。切换范围本身不产生作品修改记录。

## 5. 功能需求

### 5.1 手帐与页面管理

- 创建、重命名、打开和删除手帐；删除整本作品应明确影响并防止误触。
- 显示作品封面、名称及最近修改时间。
- 新增、复制、删除、排序和切换页面；建议首版至少保留一页。
- 复制页面时生成新的页面与图层 ID，可共用不可变素材，但排版修改互不影响。
- 页面使用固定设计宽高；屏幕查看比例不改变作品尺寸。
- 页面比例、封面来源和首版预设尺寸见待确认项。

### 5.2 模板

- 展示模板预览并用于新页面，模板提供背景、照片占位框、默认文字及贴纸布局。
- 应用模板生成独立页面和图层 ID，后续编辑不修改模板源文件。
- 点击照片占位框可选择照片，替换时保留外框位置、尺寸、角度和装饰。
- 模板使用与普通文档相同的图层结构，可额外保存占位用途、默认锁定及模板来源版本。
- 首版建议只在新建页面时应用模板；已有页面换模板涉及内容映射和丢失处理，不默认覆盖。
- 模板照片未填充时明确提示；导出时给出处理选择，不静默输出编辑占位符。
- 已使用的必要模板资源纳入作品，作品不依赖模板服务持续可用。

### 5.3 选中与变换

- 单击选中元素，点击空白取消；重叠时优先选择当前编辑范围内最上层可编辑对象。
- 页面范围选中照片组合整体，进入组合后选中内部元素。
- 支持拖动、等比缩放、旋转、复制、删除和基础对齐辅助线。
- 小元素提供适当扩大的触摸目标，图层面板可以选中被遮挡或移出页面的对象。
- 图层允许部分超出页面，导出裁切到页面边界；应提供移回可见区域的恢复操作。
- 照片组合内的贴纸和文字允许超出照片边缘，外伸内容计入组合可操作范围。
- 选中框、手柄、辅助线和编辑提示不进入导出。

建议首版手势规则：

| 状态 | 单指 | 双指 |
| --- | --- | --- |
| 页面或组合排版 | 选中、拖动；手柄缩放和旋转 | 缩放、平移查看画布 |
| 照片裁剪 | 移动框内照片取景 | 缩放框内照片；暂停画布手势 |
| 画笔模式 | 绘画或擦除，不选中内容图层 | 缩放、平移画布 |

裁剪状态应有明确提示及完成、取消入口。状态切换时结束或取消正在进行的手势，避免同一触摸同时触发多种修改。

### 5.4 照片与照片组合

- 从系统照片选择能力导入照片，复制必要文件到文档受管理的素材目录。
- 图片保持比例；基础编辑支持替换、取景、缩放及矩形裁剪，圆角等样式作为建议基线。
- 原素材保持不变，保存裁剪参数；重新进入裁剪可恢复原图范围。
- 替换照片为新资源引用，保留图层与组合布局，为新图重新计算有效取景。
- 移动、缩放和旋转组合时，内部照片、贴纸、文字一起变化。
- 默认只裁剪照片本身，不能把伸出照片的贴纸一起裁掉。
- 组合作为整体参与页面层级。页面元素只能在整个组合前后，不能穿插到其子图层之间。
- “完成组合编辑”保留子图层；缓存预览不可作为唯一存档。

### 5.5 贴纸与背景

- 提供基础贴纸选择与添加能力，支持移动、缩放、旋转、翻转、复制和删除。
- 照片和贴纸可共用图片图层类型，通过用途字段区分工具入口。
- 透明贴纸保留透明通道，显示与导出一致。
- 背景支持纯色及图片，固定在最底层，默认不参与普通拖动。
- 网络资源下载完成且可解码后才提交引用；失败时可重试，不产生损坏图层。
- 用户自定义贴纸、素材搜索及收藏的首版范围待确认。

### 5.6 文字

- 每段文字是独立可编辑图层，支持内容、字体、字号、颜色、行距和对齐。
- 编辑输入时处理键盘遮挡，完成输入后仍可重新编辑。
- 调整文本框宽度改变换行；调整字号改变文字大小；整体组合缩放按统一规则缩放文字。
- 首版建议使用应用提供的固定字体集合，保存稳定字体标识和版本。
- 字体缺失时明确提示并提供替代，不静默覆盖原始字体引用。
- 预览、保存恢复和导出采用一致的字体与排版规则；不得仅保存文字截图。

### 5.7 层级与锁定

- 同级图层数组按从底到顶存储；排序是唯一绘制顺序来源，不再持久化重复的 zIndex。
- 支持上移一层、下移一层、置顶和置底，操作限制在当前父级内。
- 隐藏图层不绘制、不参与画布选中，但保留数据，可从面板恢复。
- 锁定图层保持显示和导出，在画布上不能选中修改；从面板解锁。
- 分组隐藏或锁定作用于整个子树，不覆盖子图层原本的独立状态。
- 画笔覆盖层不能被普通图层置顶操作超过。

### 5.8 画笔

- 每页具有独立画笔覆盖层，支持绘画、颜色、粗细、橡皮擦和清空。
- 画笔固定在所有内容图层上方，新添加的照片不能覆盖已有笔画。
- 笔画采用页面坐标，移动照片时笔画不随照片移动。
- 橡皮擦仅影响画笔数据；清空画笔不删除其他图层，并支持撤销。
- 画笔与内容同步进行视图缩放和平移；笔画应裁切到页面边界输出。
- 若采用 PencilKit，优先保存 PKDrawing 原生数据；格式版本和最低系统兼容性需要在技术设计中落实。
- 首版不要求每张照片拥有独立画笔层，不要求专业自定义笔刷系统。

### 5.9 撤销与重做

- 用统一时间线管理照片、文字、贴纸、层级、背景、页面操作及画笔修改。
- 一次完整拖动或连续调节在提交时记为一步，文字输入按合理编辑事务合并。
- 选中、打开工具面板、切换编辑范围、缩放查看不计入作品历史。
- 撤销后产生新修改，清空对应重做分支。
- 第一版建议只保留当前文档编辑会话历史；关闭后重开恢复作品，不承诺恢复历史栈。
- 删除或替换素材后，只要撤销仍可能引用它，就不能清理原素材。
- 若使用 PencilKit，必须协调其绘画历史与文档历史，不能出现两个按钮各撤销不同时间线。

## 6. 文档与图层模型

### 6.1 结构

```text
DiaryDocument
├── 元信息：id、schemaVersion、标题、时间、封面引用
├── 素材资源表：AssetID → AssetRecord
└── 有序页面引用
    └── Page
        ├── 页面尺寸与背景
        ├── 内容图层（从底到顶）
        │   ├── Group（照片组合 A）
        │   │   ├── Image（照片）
        │   │   ├── Image（贴纸）
        │   │   └── Text
        │   ├── Image（页面贴纸）
        │   ├── Text（页面文字）
        │   └── Group（照片组合 B）
        └── 画笔数据引用
```

### 6.2 数据职责

| 对象 | 必要信息 |
| --- | --- |
| 文档 | 稳定 ID、格式版本、标题、页面顺序、资源表、提交版本 |
| 页面 | ID、设计宽高、背景、图层列表、画笔引用 |
| 图层通用信息 | ID、名称、类型、可见性、锁定、透明度、本地几何与相对父级的变换 |
| 图片内容 | assetId、用途、外框、取景与蒙版参数 |
| 文字内容 | 文本、文本框、字体引用及样式 |
| 分组内容 | 用途、子图层列表、组变换 |
| 素材记录 | ID、类型、相对路径、格式、文件大小；图片增加宽高与方向约定，建议记录内容校验值 |

持久化图层树为父子关系的唯一来源，运行时可以建立 ID 索引和父节点索引。素材 ID 仅放在需要引用资源的内容类型中。编辑历史不嵌入每个图层。

### 6.3 坐标与变换约定

- 页面使用设计单位，不使用设备屏幕像素；例如 1000 × 1400 仅作说明，不等于已确定页面比例。
- 子图层坐标相对于分组，顶层图层坐标相对于页面。
- 本地尺寸、布局调整、元素缩放和照片取景是不同概念，必须分别定义。
- 照片框与框内图片分开：cover 基础适配后叠加取景缩放及偏移，限制偏移避免露空。
- 定义固定旋转中心、角度单位、变换顺序和翻转规则；几何细节在专项设计中冻结。
- 组合移动只修改组变换；内部编辑不得因边界重新计算造成整个组合跳动。
- 屏幕显示应用查看变换、祖先组变换和元素变换；点击命中需逆向转换。
- 预览、命中检测和导出共享同一套几何语义。

### 6.4 三类状态分离

| 状态 | 保存要求 |
| --- | --- |
| 作品数据 | 持久保存，决定最终输出 |
| 编辑器状态 | 当前选择、模式、编辑范围、查看比例等，不参与成品绘制 |
| 历史记录 | 当前会话统一管理，有内存预算，不作为作品恢复的唯一来源 |

## 7. 文件存储与导入

### 7.1 本地文档目录

```text
diaries/<document-id>/
├── manifest.json
├── pages/
│   ├── page_001.json
│   └── page_002.json
├── assets/
│   ├── photo_001.jpg
│   ├── sticker_001.png
│   └── background_001.jpg
├── drawings/
│   └── page_001.drawing
├── previews/
│   └── photo_001.jpg
└── thumbnails/
    ├── cover.jpg
    └── page_001.jpg
```

文件名与 `.drawing` 扩展名为方案约定。manifest 保存文档信息、有序页面引用和资源索引；页面文件保存对应图层树及绘画文件引用，不在 manifest 再重复保存整份页面数据。

manifest、页面、实际素材和绘画数据属于核心数据，存入应用管理的持久目录。预览和缩略图为可再生缓存，可单独清理。应用删除后的系统数据保留行为不由自动保存承诺覆盖。

### 7.2 资源引用示例

```json
{
  "schemaVersion": 1,
  "id": "diary_001",
  "title": "海边旅行",
  "pages": [
    { "id": "page_001", "path": "pages/page_001.json" }
  ],
  "assets": {
    "asset_photo_001": {
      "kind": "image",
      "path": "assets/photo_001.jpg",
      "mimeType": "image/jpeg",
      "width": 4032,
      "height": 3024
    }
  }
}
```

示例仅说明引用关系，不是完整冻结的文件协议。

- 图层引用 assetId，由资源表解析相对路径；不写入设备绝对路径或临时相册地址。
- 多处使用同一素材可共享资源，裁剪和排版参数由各图层独立持有。
- 图片二进制不以 Base64 重复写入页面 JSON。
- 首版建议每份文档包含自身必需资源，暂不依赖跨文档共享仓库。
- 修改照片使用新资源或参数，不覆盖被其他图层共享的素材。

### 7.3 导入流程

```text
选择照片或素材 → 读取临时输入 → 校验可解码和格式
    → 处理方向与必要格式转换 → 持久保存素材
    → 生成预览 → 提交资源记录与图层引用 → 保存文档
```

导入的文件类型与方向策略需明确；若转换格式，应保留足够质量，并使预览与导出采用一致方向。导入失败不留下已提交的无效引用。作品必须在原相册照片删除后仍能打开。

### 7.4 可编辑文档包

建议后续通过 `.tdiary` 扩展名表达可编辑作品包，其传输形式为包含必要文件的 ZIP；日常编辑使用目录，避免每次修改重压素材。

首版是否提供此包的用户导入导出入口待确认，不影响内部按文档目录保存。导入包需校验路径不能越出目标目录、文件总量与解压大小、版本、ID 和资源引用，并在完整校验后建立新作品。

## 8. 加载、自动保存与恢复

### 8.1 加载

1. 作品列表优先读取索引和封面缩略图。
2. 打开文档读取 manifest，检查版本与必要文件。
3. 读取当前页，建立图层树及资源索引。
4. 按需加载当前页图片、字体和绘画数据，先显示可用预览。
5. 按背景、内容、画笔顺序呈现；图片就绪后保持几何不变地更新清晰度。
6. 切页释放不再需要的解码资源，按预算缓存邻页。

不得一次解码整本所有原图。未知的新格式版本不强行覆盖保存；缺失素材显示占位并保留图层数据，提供重试或重新关联。

### 8.2 保存一致性

- 以编辑事务提交修改，异步排队自动保存；交互进行中不要求每个采样点写盘。
- 显示“保存中、已保存、保存失败”状态，只有核心数据可靠提交后才显示成功。
- 新素材先落盘，随后提交引用它的文档状态。
- 多文件使用一致快照版本、临时文件及提交标记等机制；单个 JSON 原子替换不能代替整份文档事务。
- 失败保留上一个完整可恢复版本，并提供重试；缩略图生成失败不使核心文档无效。
- 切页、退出和进入后台触发保存尝试，但不依赖后台无限运行保证成功。
- 启动时识别未完成提交并恢复至最近完整版本，不将半写入状态当作正常文档。

### 8.3 素材回收

删除图层不立即删除素材。文档引用、历史栈引用和正在使用的导出快照均释放后，才允许回收。首版可采用保守的延迟清理，优先保障恢复能力。

## 9. 导出与相册

### 9.1 建议首版行为

- 预览当前页，导出当前页图片或按页面顺序批量导出整本图片。
- 保存至系统相册或通过系统分享能力发送输出文件；具体入口待产品确认。
- 建议 JPEG 适用于不透明成品，PNG 用于无损或透明需求；首版格式、尺寸与透明背景支持待确认。
- 批量导出保留稳定页面编号和顺序，不依赖系统相册的显示排序作为唯一顺序信息。
- 显示进度，支持取消；部分输出成功时明确列出结果和可重试页面。

### 9.2 输出一致性

- 从固定文档快照导出，避免导出过程中继续编辑造成前后页状态混用。
- 使用目标分辨率与必要原素材，不截图当前手机视口。
- 输出背景、可见内容与画笔，排除隐藏图层、选中框、辅助线和工具界面。
- 按目标页面尺寸裁切，照片取景、字体换行、透明度和图层顺序与预览一致。
- 逐页处理并释放中间资源，避免一次保留所有成品位图。
- 素材未就绪或字体缺失时不能静默输出与预览不同的结果。

PDF、在线翻页相册、印刷尺寸与出血、创建系统相册分类属于独立范围，需进一步确认。

## 10. 技术方案建议与现有工程边界

### 10.1 组件职责

| 组件 | 职责与建议 |
| --- | --- |
| 编辑器界面 | SwiftUI 展示工具、素材、图层及页面 |
| 文档模型 | 与具体 View、CALayer、图片缓存分离，使用可序列化类型 |
| 交互控制 | 当前范围、选择、模式、手势冲突、编辑命令 |
| 几何模块 | 坐标转换、命中检测、边界、吸附与变换 |
| 内容渲染 | 首先验证 SwiftUI 图层视图，按实际瓶颈决定优化 |
| 画笔适配 | PencilKit，隔离保存、绘制和历史协调 |
| 文档存储 | Codable 与文件操作封装、迁移、一致提交和恢复 |
| 资源管理 | 导入、缩略图、解码缓存、资源生命周期 |
| 导出服务 | 根据文档快照绘制页面并合成画笔 |

SwiftUI Canvas 不提供内部每个绘制对象的独立交互，需要自行设计命中与无障碍，不应把它是否可用等同于整个编辑器是否可行。[Apple Canvas](https://developer.apple.com/documentation/swiftui/canvas)

ImageRenderer 不能被假定能直接输出桥接的 PKCanvasView 内容；如采用它渲染 SwiftUI 内容，需要单独处理绘画输出并校准坐标。[Apple ImageRenderer](https://developer.apple.com/documentation/swiftui/imagerenderer)、[Apple PencilKit](https://developer.apple.com/documentation/pencilkit/)

不预设必须从 SwiftUI 逐步迁移到 CALayer、Metal。先验证目标设备和作品规模，再选择实现。Core Image 和专业滤镜框架按实际功能需要引入。

### 10.2 数据库与工程集成

- 文档文件是作品内容的权威来源；数据库可保存作品列表、文档位置和最近打开时间。
- 复用现有数据库与依赖装配方式，不因本需求自动引入第二套 SwiftData 数据库。
- 相机或相册模块提供导入输入；手帐模块负责取得持久素材副本，不依赖临时编辑器对象存活。
- 手帐编辑器独立管理原始资源、编辑参数和子图层，保存后仍可分别编辑。
- 云端文件与 OSS 能力后续通过适配层集成，本地编辑和已下载素材的恢复不依赖网络请求成功。
- 账号归属、游客转账号和切换账号的数据可见性沿用明确的隔离规则，具体产品行为需确认。

## 11. 质量与异常要求

| 场景 | 要求 |
| --- | --- |
| 手机交互 | 拖动反馈连续，解码、写盘和缩略图生成不长时间阻塞输入 |
| 大图、多元素 | 控制解码尺寸和缓存预算，逐页导出，避免无界内存增长 |
| 低存储空间 | 保存失败可见，保留上次完整版本，不误报已保存 |
| 权限取消或受限 | 照片选择、保存失败有恢复入口，不丢已有排版 |
| 应用中断 | 恢复最近完整提交，明确自动保存不能保证未提交动作零丢失 |
| 素材丢失 | 占位和提示，保留原 ID、布局及引用信息 |
| 字体变化 | 明确提示，避免静默改变排版后覆盖原文档 |
| 离线 | 已完整保存的作品可打开、编辑和导出 |
| 模板失败 | 保留原页面，不提交不完整替换 |
| 隐私 | 照片、文字不默认上传；新增云端处理须有明确产品流程 |
| 无障碍 | 工具具备可读标签，图层面板提供元素操作替代入口 |

具体最低设备、系统版本、页面数、图层数、导出分辨率、加载时延与内存目标待技术原型测量后冻结，不把未经验证的性能数字写作承诺。

## 13. 验收标准

以下用于建议基线确认后的功能验收；待确认范围最终确定后补充对应指标。

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| AC-01 | 套用模板并替换照片 | 外框和装饰不移动，新照片可重新取景 |
| AC-02 | 照片添加贴纸和文字后完成编辑 | 页面可整体变换，再进入仍可单独修改 |
| AC-03 | 移动照片组合 | 所属贴纸文字跟随，页面独立元素不跟随 |
| AC-04 | 重叠图层选择与排序 | 当前范围选最上层对象，面板可选被遮挡对象，排序结果正确 |
| AC-05 | 装饰伸出照片边缘 | 预览、重开、导出均保留装饰；照片裁剪不截掉装饰 |
| AC-06 | 隐藏与锁定 | 隐藏不输出，锁定仍输出但不可画布修改，面板可恢复 |
| AC-07 | 画笔跨过照片和文字 | 笔画始终在上，移动照片后笔画保持页面位置 |
| AC-08 | 移动照片、绘画、删除贴纸后连续撤销 | 按删除、绘画、移动的逆序恢复，重做顺序相反 |
| AC-09 | 保存关闭后重开 | 页面顺序、取景、文字、图层、画笔一致且可继续编辑 |
| AC-10 | 导入照片后删除系统原照片并离线重开 | 文档内照片仍可显示、编辑和导出 |
| AC-11 | 复制页面后修改其中一页 | 图层状态独立，共享素材不造成另一页变化 |
| AC-12 | 在不同查看缩放比例导出 | 输出尺寸不变，不含控制点；文字、裁剪和画笔位置一致 |
| AC-13 | 保存过程中模拟写入失败或中断 | 不出现损坏成功状态，可恢复上次完整文档 |
| AC-14 | 原素材缺失或格式版本不支持 | 提示原因，保留现有文件，不静默覆盖或删除图层 |
| AC-15 | 整本批量导出并中途取消或部分失败 | 页面顺序稳定，已完成结果与失败页面明确，可重试 |
| AC-16 | 编辑模式切换与双指操作 | 不同时触发拖图和绘画，裁剪缩放不误改页面查看状态 |

性能验收使用实际目标手机，包含多张高分辨率照片、透明贴纸、长中文文本和连续笔画；分别记录打开耗时、交互流畅度、峰值内存及导出耗时。
