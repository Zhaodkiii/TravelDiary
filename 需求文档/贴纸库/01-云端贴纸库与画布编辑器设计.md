# 云端贴纸库与画布编辑器设计

日期：2026-10-17。状态：拟实施方案，不代表已经上线。

本次修订：背景正式独立为背景库；新增后台管理、收藏统计、客户端完整重构与搜索规范。第 11—15 节为最终实施约束；前文 Sticker 模型名称在实施时按第 11 节统一为可支持两种库的 Material 模型。

## 1. 目标与现状

目标：上传手帐预设时同时整理贴纸库；用户浏览预设时能浏览、收藏其贴纸库；编辑画布时从当前手帐、收藏的库或全部素材中搜索并按需添加。原图及缩略图直传、直取 OSS，业务服务器只处理目录、权限和发布信息。

现有服务端 diary_presets 已有 Series、Template、Version、Upload、DownloadPlan、Event；Version 保存预设快照。客户端 DiaryStickerCatalog 目前提供本地符号和 PNG，DiaryStickerPickerSheet 提供选择入口；PresetDownloadManager 已有下载任务、进度和哈希相关机制，可抽取通用资源下载层。转换工具 build_sticker_library.py 当前只从苏州、上海包提取独立透明素材，按分类和文件哈希整理，尚不是全局资源注册系统。

现有《手帐贴纸选择器详细设计》保留为本地版本说明；本方案定义云端扩展的分类、收藏、加载及去重规则，实施时须同步旧说明。

## 2. 系列、手帐与贴纸库的关系

- 系列：城市系列、海岛系列，是内容归属，不是素材分类。
- 手帐模板：苏州、上海、舟山。
- 贴纸库：每个模板拥有一个稳定 ID 的主贴纸库，例如“苏州贴纸库”；模板升级发布新的库版本，收藏仍指向同一个库。
- 系列视图：动态聚合该系列各模板的贴纸库，不复制素材，也不新建一份系列图片包。
- 贴纸：可复用内容实体，能同时属于多个库；同一实体只维护一次分类和公共资源。
- 大分类：所有库统一使用同一份分类字典，库内可以配置排序，不能另造含义不同的大分类。

例如：城市系列 → 苏州手帐 → 苏州贴纸库 → 相框与照片卡 / 纸卡与票据 / 插画与装饰。上海也使用这些分类。浏览全系列时同一 sticker_id 仅显示一次，并保留全部来源。

用户作品记录 source_template_id、source_template_version、source_library_id、source_library_version。一个作品允许关联多个来源库，手动更换素材推荐库不改变已有页面内容。模板预览默认显示该模板版本对应的贴纸库；收藏库默认浏览最新已发布版本。

## 3. 手帐适用分类

数据继续使用既有 kind + subcategory，界面及本地导出目录使用中文。不要把“收藏、最近、苏州、水彩”混成素材分类：前两项是来源入口，苏州是内容归属，水彩是风格标签。

| 中文分类 | kind | 子分类与展示名 | 首期范围 |
| --- | --- | --- | --- |
| 背景（独立背景库） | background | paper_texture 纸张纹理、page 整页底图、scene 场景底图 | 不进入贴纸库、贴纸分类栏与贴纸搜索结果；通过独立背景入口使用 |
| 相框与照片卡 | photo | frame 相框、photo_card 照片卡 | 独立空框和空白照片卡；slot 需绑定可编辑占位结构，后续以组件支持；fixed 不自动收录 |
| 纸卡与票据 | paper | note 便签、checklist 清单卡、route 路线卡、ticket 票据、title_card 标题底板 | 优先空白可复用纸卡；带特定行程文字的票据标注城市、地点 |
| 文字贴纸 | text | title 标题、body 正文、date 日期、quote 引语、caption 照片说明 | 仅收录具有独立装饰价值、能复用的字图；普通说明正文和个人日期不自动收录 |
| 插画与装饰 | illustration | scene 场景插画、object 主题物件、botanical 花草、tape 胶带、stamp 装饰印章、ornament 其他装饰 | 首期核心素材 |
| 品牌标识 | branding | logo 品牌标志、seal 品牌印章、series_mark 系列标志 | 仅明确允许用户复用的内容；默认不自动公开品牌 Logo |

标签与分类分开：城市（苏州、上海）、主题（园林、建筑、美食、交通）、风格（水彩、复古、线稿）、颜色等使用受控标签。品牌标识和装饰印章按用途区分。

首期素材为透明 PNG/WebP 的 image；未来可增加 component（相框+照片槽位等组合）。renderType 表示渲染方式，kind 表示语义，不能用 photo 推断可替换。首期不把带人物照片的整组或整页合成图自动作为贴纸。

筛选必须同时考虑语义、对象边界、透明背景、有效像素区域、尺寸和是否包含固定照片。透明通道存在只是必要检查之一，不足以证明适合贴纸。明确排除页面根节点、空图层、隐藏辅助线、个人照片、个人信息、重复组快照。通过规则校验直接发布，无人工审核流程；转换配置可显式 include/exclude 覆盖规则。

## 4. 存储与资源去重

业务 ID 与图片哈希分离：sticker_id 是稳定收藏身份；sha256 是不可变文件身份。重命名、修改标签不新上传图片；更换图像产生新资源哈希和内容版本，原有作品继续使用旧哈希。

新增统一 ResourceBlob 资源注册表，由预设和贴纸共同引用。推荐 OSS key：assets/sha256/前两位/完整哈希.扩展名。目录不含城市、库名或版本号，归属通过数据库关系表达。本地面向用户的导出目录仍用中文，例如“贴纸库/插画与装饰/花草”。

去重以完整文件字节 SHA-256 为准，全局跨模板、贴纸库和分类复用。同图不同编码字节可能不同：转换端统一编码规则和版本；像素哈希仅用于提示相似/重复候选，不作为自动覆盖依据。缩略图是独立派生资源，按源哈希+转换参数版本记录映射，其文件也通过 SHA-256 去重。

若预设已有同字节图片，贴纸直接引用其资源，无须复制到 stickers/ 目录。若需要裁切透明边缘，裁切结果属于新派生资源，记录 source_blob、裁切矩形和算法版本。相框内部透明孔洞须保持。旧 OSS 对象先登记原 key 与哈希即可复用，不强制批量复制到新路径；同哈希暂时存在多个旧对象时选一个规范引用，迁移完成后再回收重复对象。

去重不能通过只信任客户端声称的哈希实现。上传端直传 OSS；可信发布进程或 OSS 同区域处理任务校验真实字节摘要、格式、尺寸、解码与大小限制。业务 API 不接收和转发资源文件。首期可使用受控本地发布工具完成字节校验并登记；面向后台浏览器上传时必须补齐可信云端校验后才能发布。

物理删除采用引用扫描和延迟清理，禁止按某一个库的引用计数直接删对象。有效引用包含预设历史版本、贴纸版本、待发布上传及已同步作品资源。未登记云端作品引用前，历史发布资源不自动物理清除。取消收藏不会删除资源。

## 5. Django 数据模型

建议新增 sticker_library app 管理目录、收藏和发布；通用 ResourceBlob 放在保留的 file_manager 内，通过迁移接入 diary_presets。不要复制另一套用户、上传鉴权或下载服务。

| 模型 | 关键字段及约束 |
| --- | --- |
| ResourceBlob | id、sha256 唯一、bucket、object_key、mime、byte_size、width、height、has_alpha、status、created_at；仅 verified 可发布 |
| ResourceDerivative | source_blob、variant、parameters_version、result_blob；前三字段联合唯一 |
| StickerCategory | kind、subcategory 联合唯一、中文名、排序、active；校验允许的组合 |
| Sticker | UUID、稳定 source_identity 唯一（命名空间+转换源标识）、category、active、current_revision；不要按名称当主键 |
| StickerRevision | sticker、number 联合唯一、name、keywords、resource_blob、thumbnail_blob、render_type、尺寸、授权/复用范围、组件清单（后续）、created_at；发布后不可变 |
| StickerTag / StickerRevisionTag | 受控标签及关联；发布版本的搜索信息保持可追溯 |
| StickerLibrary | UUID、template 一对一 PROTECT、title、description、current_version、active；series 从模板关联读取 |
| StickerLibraryVersion | library、number 联合唯一、preset_version、status、created_at、actor；锁定本次模板版本和贴纸集合 |
| StickerLibraryItem | library_version、sticker_revision、position、display_name；同一库版本同一个 sticker 只出现一次（保存 sticker 外键并加联合唯一约束，服务层校验 revision 属于 sticker） |
| StickerSource | sticker、template、preset_version、page_id、object_id；记录全部来源与溯源，不复制二进制 |
| UserLibraryFavorite | user、library 联合唯一、created_at；收藏整库 |
| UserStickerFavorite | user、sticker 联合唯一、created_at；收藏单张 |
| StickerPublishJob | 幂等键、输入摘要、目标模板、预期 revision、状态、错误摘要、结果版本；支持断点重试 |

系列收藏首期不单建：收藏苏州、上海库后在“我的贴纸库”按城市系列分组。系列总览允许浏览所有库。未来若需要“订阅整个系列及未来新库”，必须新增明确的系列订阅语义，不与当前收藏混淆。

索引：库内列表按 library_version+position+id，分类按 category+active，收藏按 user+created_at+id。UUID、时间和 position 使用稳定游标分页。搜索首期采用名称、关键词、标签匹配，小规模可数据库查询；使用真实中文查询样本验证后再选 ngram 全文索引或独立搜索服务，不依赖英文分词默认配置。

## 6. PSD 转换与发布流程

1. 转换 PSD，输出现有预设以及 sticker-library.json；提取可复用对象，共享原包资产文件，不再另复制一套上传目录。
2. 在转换配置中维护模板稳定标识、源对象稳定标识、分类、标签及 include/exclude；无法关联旧对象时报告新增/移除差异，不能悄悄使收藏 ID 全部变化。
3. 生成候选摘要：各分类数量、排除理由、重复资源、资源大小和缩略图。无需审批，校验成功即可继续。
4. 发布工具向 API 批量查询已有哈希；API 只对缺失对象发放指定 key 的短期上传授权。工具/浏览器直接上传 OSS；不得获任意 key 的写入权限或覆盖已验证资源。若需暂存区上传，云内校验后归档，重试不重复归档。
5. 可信校验完成后登记 ResourceBlob。对已存在哈希直接复用；并发上传通过数据库唯一约束和上传会话幂等收敛。
6. 开启数据库事务：校验模板预期 revision，写入贴纸版本、库版本及来源关系，同时推进模板和库的 current 指针。任一步失败则不出现“新模板配旧贴纸库”的半发布状态。
7. 重试相同输入返回同一结果；只有资源已上传但事务失败时保留暂存记录，延期回收。删除某页不自动删除被其他页/库使用的贴纸。
8. 本地与生产数据库分别登记同一稳定内容 ID、哈希和版本映射；使用明确的环境参数，输出数据库目标和新增/复用计数，不记录密码或密钥。

当前工具按 (kind, subcategory, digest) 去重，后续需拆成“资源按 digest 去重、内容按 source_identity 维护、库成员按 sticker 去重”。这样跨分类引用同一图片也不多存文件。

清单示例（路径只供本地上传工具解析，客户端得到资源 ID）：

```json
{
  "schemaVersion": 1,
  "templateKey": "city.suzhou",
  "libraryKey": "city.suzhou.stickers",
  "items": [{
    "sourceIdentity": "city.suzhou.botanical.white-flower",
    "name": "白花枝",
    "kind": "illustration",
    "subcategory": "botanical",
    "renderType": "image",
    "tags": ["苏州", "园林", "花草"],
    "resource": {"sha256": "完整64位摘要", "path": "assets/white-flower.webp"},
    "sources": [{"pageID": "page-01", "objectID": "object-17"}],
    "position": 10
  }]
}
```

## 7. API 与后台管理

建议端点（待实现）：

- GET /api/stickers/categories：统一中文分类字典与字典版本。
- GET /api/sticker-libraries?series=&q=&cursor=：库卡片、封面、数量、收藏状态、当前版本。
- GET /api/templates/{id}/sticker-library?template_version=：预设指定版本关联的库。
- GET /api/sticker-libraries/{id}/items?version=&kind=&subcategory=&q=&cursor=&limit=40：分页目录、缩略图资源与元数据。
- GET /api/stickers?scope=favorites|all&library_id=&series=&kind=&subcategory=&q=&cursor=：统一搜索；列表实体去重，并返回来源。
- PUT/DELETE /api/me/sticker-library-favorites/{id}：幂等收藏/取消收藏；单张收藏使用独立 sticker-favorites 端点。
- POST /api/resources/download-plan：批量提交 resource_id，鉴权后返回直达 OSS/CDN 的短期 URL、大小、sha256、过期时间；不以任意 object_key 签名。
- 发布准备、上传完成与提交端点仅管理员可用。所有分页上限、查询长度和批量资源数量设服务端限制。

响应必须固定 library_version；加载下一页时不能悄悄混入新版本。目录返回版本 ETag，签名 URL 单独提供 expiry，不能把过期 URL 当长期缓存标识。首屏可批量签发当页缩略图地址避免逐张请求。

后台导航：系列 → 手帐模板 → 页面 / 贴纸库。贴纸页展示分类数、缩略图、名称、来源页、共享库数、资源状态，支持新增、移除成员、排序、分类、标签及禁用。移除成员文案为“从本库移除”，与全局下架区分；修改先入草稿再原子发布，无审核环节。后台图片也直取 OSS。

## 8. 客户端交互与搜索

预设详情增加“页面 / 贴纸库”标签；贴纸库页顶部提供“收藏贴纸库”，显示分类、贴纸数和少量预览。收藏不下载整库。单张长按可收藏，并可预览透明细节。库详情区分“浏览预览”和“添加到画布”：没有正在编辑的作品时不隐式创建作品。

画布贴纸面板：顶部来源选择“当前手帐 / 我的贴纸库 / 全部”，其下库选择器可按系列分组，再下方是搜索框、统一大分类、子分类与网格。“最近使用”“收藏单张”是快捷入口，不占用素材大分类。当前手帐无来源库时展示我的库和内置素材。

搜索默认限定当前选中的库，选择“全部库”才跨库；页面明确显示范围。关键词匹配中文名称、别名、标签，可用城市名筛选来源；多条件同时生效。输入防抖约 300ms、取消旧请求并检查请求身份，避免旧响应覆盖新关键词。空结果可提示扩大到全部库。离线搜索只覆盖已缓存目录，并标明范围。

## 9. 懒加载与统一下载

1. 打开面板只取分类、库卡片和首屏约 40 条元数据；可见网格加载缩略图，最多预取邻近一屏；不拉全部库和全部原图。
2. 缩略图按显示尺寸解码，设置内存缓存上限；磁盘缓存以 blob 哈希+派生规格为 key，避免签名 URL 变化形成重复缓存。
3. 点击添加才申请原图地址并进入统一资源下载队列，显示当前贴纸进度与取消入口；完成后校验长度和 SHA-256，再原子写入缓存。
4. 下载任务状态：queued → downloading → verifying → ready；旁路 paused/failed/cancelled。小贴纸取消后可重新下载，大文件才需要分段续传；不得声称 iOS 强制终止后一定持续运行。
5. 从 PresetDownloadManager 抽取 ResourceDownloadCoordinator，预设下载和贴纸下载共享哈希任务、缓存与并发预算。初始原图并发 3、缩略图并发 6，可配置；用户正在添加的贴纸优先于后台预取。
6. 同一哈希多个消费者共享网络任务，但各自保留添加意图；取消一个消费者不取消其他消费者需要的下载。暂停整本下载也不能误停贴纸的共享请求。
7. URL 过期时刷新授权；续传前验证 ETag/对象版本和 Content-Range，服务器未正确响应范围请求时重新下载，绝不能直接拼接不同内容。
8. 点击幂等只针对同一次未完成添加意图；添加成功之后再次点击同一贴纸，允许生成新的图层。切换手帐、页面或编辑对象后，旧任务完成不能向错误的画布插入；保留缓存并要求用户重新选择，或提示返回原目标。
9. 导入时在作品内按哈希复用资源文件，每次创建独立图层 ID。移动/缩放/旋转互不影响，同一素材不反复存入同一本作品。共享缓存可清理，作品所需文件必须持久保存；跨作品物理去重另行设计，首期以独立作品可导出为先。
10. 最近使用仅在添加成功后记录；下载失败保留可重试状态，不生成空对象；添加视为一次撤销操作，清理资源须考虑撤销/重做历史引用。

收藏按账号存服务器并缓存本地，支持离线操作队列和幂等重放；退出账号清理私人目录及收藏状态，进行中的任务绑定账号，不能把结果写入另一账号。公共字节缓存是否跨账号保留由资源可见性决定，缓存命中不绕过授权。

首期不自动“下载收藏库”。可后续添加显式“离线保存”按钮，展示剩余去重字节、进度和取消功能。收藏表示关注，离线保存表示缓存固定版本，二者独立。

## 10. 更新、下架与验收

库更新展示新版本提示，已打开网格可继续固定旧版本，用户刷新后切换。收藏单张指向稳定 sticker_id，浏览默认取当前可用 revision；作品保存确切资源哈希。库被下架时收藏显示不可用且允许移除；已有合法导入作品的本地资源不随远端下架消失。授权撤销等特殊规则需单独处理，不能直接删用户作品。

首期实施顺序：统一分类与资产注册 → 转换工具生成贴纸清单和幂等发布 → 后台贴纸管理 → 模板预览与库收藏 → 编辑器懒加载、单张下载与作品内去重 → 搜索和离线体验。分类、资源身份及发布事务应先冻结契约，再同时接入两端。

验收必须覆盖：苏州/上海各有独立库且共用分类；同哈希跨库仅一份规范 OSS 资源；重复发布不新增重复库与收藏身份；预设图像可直接被贴纸引用；浏览只取缩略图，收藏不下载；库内/跨库搜索范围正确；首次添加才下载原图；重复添加只新增图层；并发点击共享下载；断网、签名过期、取消及切换账号/页面不会误插入；移除库成员不破坏别的库和旧作品；模板与库版本同步发布，失败后可安全重试。


## 11. 独立背景库与最终数据模型

### 11.1 两套产品入口，共享资源底层

每个手帐模板可同时关联一个贴纸库和一个背景库。例如城市系列 → 苏州手帐 → 苏州贴纸库 / 苏州背景库。两者独立浏览、搜索、收藏、发布状态和数量统计；没有素材时隐藏对应入口，不生成空收藏卡片。贴纸搜索不混入背景，背景搜索也不返回装饰贴纸。

背景库固定分类：纸张纹理（paper_texture）、整页底图（page）、场景底图（scene）。贴纸库使用相框与照片卡、纸卡与票据、文字贴纸、插画与装饰、品牌标识五类。背景与贴纸可以引用同一个 ResourceBlob，产品分库不意味着 OSS 重复存储。

背景只提取明确属于背景的底图；不得把含照片、文字、装饰的整页预览当作背景。无独立背景图的模板可暂时没有背景库。小块纸卡仍属于贴纸。纹理允许不透明，不套用贴纸透明通道的筛选规则。

### 11.2 采用统一 Material 模型，避免两套重复业务

第 5 节是概念拆解，实际实现统一以下名称，不同时再建一套 Sticker 与 Background 同构表：

- MaterialLibrary：template 外键、library_type（sticker/background）、title、description、active、current_version；(template, library_type) 唯一。
- MaterialLibraryVersion / MaterialLibraryItem：沿用版本、固定内容 revision、位置和来源规则，分别替代 StickerLibraryVersion / StickerLibraryItem。
- Material / MaterialRevision / MaterialSource：替代 Sticker 等模型；Material 增加 material_type，背景 revision 增加 background_options。库成员的类型必须匹配库类型，服务层与发布校验共同保证；图片资源仍引用 ResourceBlob。
- MaterialCategory：保持 kind + subcategory，新增适用 material_type。background 只允许加入 background 库，其余分类按字典校验。
- UserLibraryFavorite：user + library 唯一，不因两个库属于同一个模板而合并。
- UserMaterialFavorite：user + material 唯一，支持收藏单张背景或贴纸。
- MaterialLibraryStats / MaterialStats：一对一派生统计，可保存当前收藏数与更新时间，不能作为收藏关系的唯一事实来源。

前文 /api/sticker-libraries 与 /api/stickers 为概念端点；实际新接口统一 /api/material-libraries?type=sticker|background 和 /api/materials?type=...，客户端贴纸/背景模块固定传入自身类型。目录、收藏、发布和下载复用基础设施，界面独立。

模板版本发布清单同时记录 sticker_library_version_id 和 background_library_version_id，允许为空。后台只改某个素材库时也生成新的模板目录版本，页面资源哈希可完全复用；保持模板预览与两个库版本一一对应。收藏人数绑定稳定 library_id，不随版本增长重置。

### 11.3 背景应用行为

背景卡片显示完整缩略图和比例；点选后按需下载，在目标页面上临时预览，可切换“填满 / 完整显示”，纹理经素材标记允许后才出现“平铺”。用户确认后替换页面背景，作为一条撤销记录；取消不修改作品。

使用专门的 page.background 引用，不按普通小贴纸居中插入。若现有文档格式尚不支持，先增加带格式版本的背景字段及旧数据读取兼容，再接入界面；不可在没有检查现有文档模型的情况下直接假定字段已经存在。背景永远位于内容层下方、默认锁定，页面只应用一个当前背景。纹理存推荐平铺尺寸，场景底图存推荐焦点和 fill/fit 默认值。背景替换不修改其他图层。

## 12. 后台按手帐管理素材库

导航：预设管理 → 系列 → 手帐详情 → 页面 / 贴纸库 / 背景库。独立素材总库入口用于跨手帐搜索和复用，但不能替代手帐下直接管理的入口。

手帐列表显示：系列、手帐名、发布版本、页数、贴纸数、背景数、贴纸库收藏人数、背景库收藏人数。数量默认对应当前发布版本；草稿数量单独标记。

库管理页包含：库封面、名称、说明、所属手帐、当前版本、发布状态、当前收藏人数、分类分布、搜索框和分页网格。素材卡片显示名称、分类、关键词、来源页、单张收藏人数及资源校验状态。列表视图另展示尺寸、文件大小、哈希摘要、共享库数量和最后修改时间。

支持操作：

1. 查看高清预览和透明效果；背景支持页面比例模拟。
2. 从当前手帐已转换资源提取，或从全局素材库选择已有素材加入；新文件直传 OSS。
3. 编辑名称、分类、关键词、搜索别名、推荐用途；批量添加标签、移动分类、移除成员。
4. 调整分类内排序；排序只影响当前库，不修改其他库。跨页排序通过“移动到位置/最前/最后”支持，不能只支持当前分页拖拽。
5. 查看所有来源页、被哪些库引用以及历史版本。删除来源页不会直接物理删除共享资源。
6. 保存草稿、校验并发布；不需要审核。全局素材内容修改会生成新 revision，其他库不会自动换图，须显式发布引用新版。
7. “从当前库移除”“全局下架”明确区分；普通管理员管理库成员，具备全局权限的管理员才能全局下架。

发布结果显示新增素材、复用资源、新上传字节、分类数量、库版本和失败原因。后台查看只能返回必要管理信息，不能在公开接口暴露收藏用户身份。

## 13. 收藏人数：定义、准确性与展示

必须区分四个指标：贴纸库收藏人数、背景库收藏人数、单张贴纸收藏人数、单张背景收藏人数。均指当前仍保留收藏关系的去重账号数，不是点击次数、下载次数或累计收藏动作数。

收藏整库不会把其中所有素材的单张收藏数加一；收藏单张也不会自动收藏所属库。同一用户收藏同一库多个版本仍只计 1 人。若以后显示系列收藏人数，应以该系列各库收藏用户集合去重计算，不能简单相加；手帐综合收藏人数同理。

PUT 收藏通过唯一约束幂等写入，仅真正新增关系时更新计数；DELETE 仅实际删除时减一。关系和计数在同一事务中更新，对同一对象采用固定锁顺序或原子更新，处理并发收藏/取消、重试、账号注销级联删除，计数不能变负。首期数据规模小可直接 COUNT 关系表，先保证准确，再引入派生计数。

建立定期核对任务，以关系表重新计算派生统计并修复偏差；任务可重试且不会反复加数。用户注销删除其收藏关系后必须同步修正相关统计。若缓存公开计数，可允许短暂延迟，并以 updated_at 标明后台数据更新时间。

客户端库卡片与详情显示“128 人收藏”和本人收藏状态，单张详情显示收藏人数，避免网格每一格堆叠过多数字。本人点击采用乐观更新，失败回滚；首次响应返回服务器 count 与 is_favorited。数字缩写只用于展示，API 返回完整整数。后台默认准确值；首期不收集额外行为埋点。未来如需“新增/取消收藏趋势”，另建事件记录并明确保留周期，不用当前关系表伪造历史趋势。

## 14. 客户端贴纸功能完整重构

### 14.1 交互结构

重做当前本地贴纸选择器的目录、分类、搜索、收藏和加载层，不在旧的静态 categories 数组上继续追加云端条件。保留经验证的画布插入、图层操作与撤销接口，通过新的适配层调用。

画布工具栏分开提供“贴纸”“背景”。两者均支持半屏/全屏面板，复用网格和搜索基础组件，但分别保留筛选状态。贴纸面板：

- 顶部：标题、搜索、关闭；搜索时展示当前范围。
- 来源切换：当前手帐、我的贴纸库、发现；最近使用、收藏单张作为快捷入口。
- 我的贴纸库：展示收藏库卡片，按系列分组；进入苏州库后可返回库列表或切换上海库。
- 库内：库名、收藏状态/人数、统一大分类、按需显示子分类、素材网格。
- 单张：点击下载并添加；长按打开详情，提供高清预览、收藏、关键词和来源库入口。不同于背景，贴纸添加后沿用当前单次添加关闭面板行为。

预设详情设“页面 / 贴纸 / 背景”，两个素材标签各自展示对应库与收藏按钮；只有一个库存在时隐藏另一个空标签。预设浏览不要求先下载整本手帐，也不自动打开编辑器。纯浏览点击素材展示详情，编辑器内点击才执行添加或背景预览。

空状态明确区分：未收藏库、当前手帐无关联库、筛选无结果、离线目录不完整、库已下架。没有网络时仍可使用已缓存且允许使用的素材。当前手帐来自多套预设时显示全部来源库，不能只取最后一次导入来源。

## 15. 关键词与中文搜索设计

### 15.1 结构化字段

每个素材保存：display_name（简短可读名）、aliases（同义名称）、subject_tags（主体）、theme_tags（主题）、style_tags（风格）、color_tags（颜色）、usage_tags（用途）。城市和系列从来源关系派生，不重复手填到每一个素材。kind/subcategory 同样来自分类字典。

推荐每张 3—8 个高相关主体/主题/用途关键词，别名 0—5 个；这是编辑质量提示，不是阻止发布的硬限制。禁止把所有热门词塞入每张素材。关键词使用独立列表，不使用逗号拼接长字符串作为唯一结构；带文字的图片可保存 text_content 用于检索，但不能让 OCR 长正文压过主体名称。

示例：

| 素材 | 名称/别名 | 主体、主题 | 风格/颜色/用途 |
| --- | --- | --- | --- |
| 白花枝 | 白花枝；白色花枝、花枝 | 花草、花朵、园林 | 水彩、白色、边角装饰 |
| 园林窗框 | 园林窗框；花窗、窗棂相框 | 园林、建筑、相框 | 中式、照片装饰 |
| 空白便签 | 米白撕边便签；便条、记事纸 | 纸卡、撕边 | 米白、复古、写字、记录 |
| 苏州车票 | 苏州车票；车票、旅行票据 | 交通、旅行 | 复古、行程记录 |
| 米白手工纸 | 米白手工纸；纸纹、纹理纸 | 纸张、纹理 | 米白、手工纸、页面背景 |

### 15.2 来源与维护

转换端优先读取人工配置的分类和关键词，其次从规范图层名、模板/页面元数据生成建议。清除“组件_、分层重建、v02、复制”等技术前后缀，不把版本号当搜索词。转换工具输出缺名称、词过少、分类不匹配、疑似固定照片等质量提示；规则校验通过即可发布，不增加审核步骤。

建立受控同义词字典，例如便签↔便条，胶带↔纸胶带；同义词必须限定含义，不能把荷花和所有花草完全等同。允许通用分类召回具体子项，但具体词不无条件召回所有同类。图像内容不确定时不自动加“水彩”“樱花”等未经确认的标签；后台支持批量修正并生成新发布版本。

### 15.3 查询与排序

搜索先固定 type 和 scope，再进行关键词召回，权限与上下架条件始终生效。支持中文词、英文分类别名、大小写与全半角规范化；简繁映射和拼音/首字母作为后续增强项，首期不承诺默认数据库 LIKE 已实现中文分词。

“苏州 花草”应识别来源城市与主体条件，组合筛选；“白色 胶带”按颜色与主体交集匹配。无法解析的词作为普通文本查询。整句完全匹配优先于拆词，拆词默认 AND，不能用 OR 扩大到大量无关结果；无结果时给出放宽条件建议，不静默改变条件。

排序原则：名称完全匹配 > 名称短语匹配 > 别名匹配 > 主体/用途标签 > 其他标签与来源。收藏人数只作为相关性相近时的次要排序信号，不能让热门但无关素材排在精确匹配前。最后以稳定 ID 打破并列，游标包含查询与排序版本；翻页期间固定结果集版本或快照边界，避免收藏数变化造成重复/漏项。

输入约 300ms 防抖，限制关键词长度，取消旧请求，服务端使用参数化查询。空关键词展示库内默认顺序与常用标签；首期不伪造“热门搜索”。搜索历史只在设备按账号存储，提供清空操作，不默认上传用户输入。

首期规模较小时可用数据库参数化匹配与明确词典实现名称/别名/标签查询；上线前使用至少“苏州花草、便条、花窗、白色胶带、纸纹、车票、无结果词”等样本验收。规模增长后以索引服务替换 Repository 后端，不改变客户端契约。

## 16. 本次新增验收标准

- 背景库与贴纸库完全分开，模板详情及后台都能分别查看与收藏，素材字节仍共享。
- 后台进入任一手帐能看到两库素材、分类、来源、发布版本及当前收藏人数，支持独立编辑和一致发布。
- 同一账号重复收藏只增加一次；取消、重试、并发、注销后人数正确；整库收藏不膨胀单张计数。
- 客户端旧收藏完成映射，已有作品可继续打开；新面板按库分页、按需下载，背景采用预览确认与可撤销替换。
- “便条”能找到便签，“花窗”能找到园林窗框，“白色 胶带”不会优先返回白花；贴纸搜索不会出现纸张背景。
