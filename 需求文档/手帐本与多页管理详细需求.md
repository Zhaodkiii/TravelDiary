## 1. 需求来源与文档优先级

### 1.1 用户已明确

- 可以新建多本手帐、选择一本手帐、预览该本的内容。
- 一本手帐包含多页，可以新建一页或选择已有页继续编辑。
- 从编辑器返回后，可以预览整本及其中每一页的设计内容。
- 当前独立画布作为一页，继续保留智能对象分层、局部背景、装饰和涂鸦。
- 数据在本地持久化；需明确模型、文件、加载与展示方式。
- 根画布与对象使用通用编辑流程，对象处理通过 fullScreenCover 打开；背景默认透明。
- 不要求兼容历史存档；核心实现保留中文注释。

### 1.2 本文提出的实施基线

下列默认值是本方案的设计选择，不冒充用户已经确认的结论：统一一本内纸张尺寸、两列页面总览、空本允许存在、页内自动保存、封面引用某一页、回收站保留 30 天。参数需在手机原型验证后调整，变更须记录。

本文件是手帐本、多页目录、页面版本发布和跨页资源管理的最新依据。智能对象内部编辑规则以《智能对象图层与独立编辑方案》为准。早期单页文档中的独立 CURRENT 指针、入口选图直接创建整个作品、latest.txt 唯一入口、页面专用画笔、历史存档迁移要求，不作为多页版本实施依据。

本文件描述目标方案；既有代码仅能作为单页编辑基础。不得因为文档出现接口或界面名称就将其标记为已完成。

## 2. 首版范围与阶段

| 阶段 | 必需能力 | 完成条件 |
| --- | --- | --- |
| A：基本闭环 | 手帐列表、新建本、空本、新建空白/照片页、选页编辑、保存返回、预览、重开 | 两本各两页能分别编辑、保存和恢复 |
| B：管理完善 | 重命名、封面、页面排序、删除与恢复、逐页阅读 | 目录变更与文件一致，恢复不丢图层 |
| C：稳定性完善 | 草稿恢复、缓存淘汰、异常重试、后台中断处理、辅助功能 | 本文异常规则与验收矩阵通过 |
| 后续扩展 | 页面复制、跨本复制/移动、模板库、整本导出、PDF、云同步、共享协作 | 单独需求与验收，不混入首版必需项 |

不支持旧文件导入或自动迁移；遇到旧格式说明“不支持此文件格式”，不覆盖其文件。相同新协议内的上一次完整提交恢复属于故障恢复，不属于历史格式兼容。

## 3. 产品结构与完整操作流程

```text
手帐列表
├── 新建手帐 → 空本页面总览
└── 选择手帐 → 页面总览
                  ├── 新建空白页 → 页面编辑器
                  ├── 从照片新建页 → 系统照片选择器 → 页面编辑器
                  ├── 点击页面 → 页面编辑器
                  │                └── 打开对象 → 同一编辑器的全屏子页面
                  └── 阅读整本 → 逐页阅读 → 编辑当前页
```

### 3.1 手帐列表

- 卡片显示封面、名称、有效页数、最近修改时间；默认按最近修改时间倒序，时间相同时按 ID 稳定排序。
- 点击卡片进入页面总览；浏览动作不改变修改时间。
- 新建按钮始终可见；无手帐时展示“创建第一本手帐”。
- 首版进入手帐 Tab 展示书架，不自动打开上次编辑器。可提供“继续编辑”快捷入口，保存最近 bookID/pageID 并在使用前检查有效性。
- 新建输入名称与尺寸预设，默认名称“未命名手帐”；名称允许重复，以 UUID 识别身份。去除首尾空白后长度 1～60 个可见字符，禁止仅空白，不把名称用作文件路径。
- 尺寸默认 A5 竖向：148 × 210 mm @300 DPI，对应 1748 × 2480 px。新建界面提供 A5、竖版 1000 × 1400、正方形 1000 × 1000 三个预设，每次打开新建界面默认 A5。一本内页面尺寸一致，空白页、照片页和预设页均继承本子尺寸；已有本保留存档尺寸。A5 PNG 导出使用 1 倍倍率，输出 1748 × 2480 px 并写入 300 DPI；毫米转整数像素有取整误差。其他已有尺寸保留原来的 2 倍导出行为。
- 创建成功持久化空本并进入总览；失败保留输入并提供重试；连续点击不重复创建。

### 3.2 页面总览

- iPhone 竖屏默认两列卡片，按页面顺序从左到右、从上到下排列；大字体或窄窗口允许一列。
- 卡片显示整页缩略图、动态页码、可选页标题、封面标识及必要的保存/预览状态。
- 页面缩略图保持比例，不裁剪作品边缘。透明区域放在中性底板上；点击进入编辑，预览按钮进入整本阅读。
- 空本显示“新建第一页”，阅读按钮不可用。允许一本有零页，不自动生成看不见的占位页。
- “新建页”默认添加在末尾；在页面菜单中可以选择“在此页后新建”。
- 排序模式支持拖动，并提供“前移/后移”的辅助功能替代；结束排序后一次提交完整 pageID 顺序。失败恢复先前顺序并提示。
- 封面页通过 pageID 指定，不依赖页码；排序不会改变指定封面。

### 3.3 新建页

- 空白页：建立默认透明根画布，持久化并加入本的目录后，才全屏进入编辑器。
- 照片页：先选择并完整导入照片，再生成含照片对象的页面，最后发布到本目录。取消选图不新增页面；导入失败不新增空白页。
- 单次从照片新建页首版只选一张；进入编辑器后可以继续添加照片。
- 创建操作使用 operationID 实现幂等重试；同一请求超时或重复回调不生成重复页。确认失败后允许重新提交新的请求。
- pageID、根 contentID、所有新 layerID 均独立生成；跨页不能引用另一页的可变对象内容。
- 默认页标题为空，界面显示“第 N 页”；可重命名，标题不决定文件路径或顺序。

### 3.4 页面编辑与返回

- 页面编辑器只加载当前页；复用现有 DiaryEditorScreen、会话、渲染及图层模型。
- 页面内容自动保存。页面级按钮为“完成”，其含义是等待最新修改保存成功后返回；不是取消整个编辑过程。
- 页面级不提供“取消全部编辑”；已自动保存的修改不能被返回按钮静默抹掉。
- 未保存失败时停留编辑器，提示重试；不显示“已保存”，也不跳转并丢弃内存内容。
- 成功返回总览，保留原滚动位置并刷新对应 pageID 卡片；预览可显示“更新中”，不得短暂跳到别的页。
- 从阅读页进入编辑时，完成后回到同一 pageID 的阅读位置，再刷新其预览。
- 页码是索引派生值，导航与保存始终传 bookID/pageID，不用数组下标定位。

### 3.5 对象内部编辑

- 内层继续通过 fullScreenCover 打开同一个编辑页面；照片、文字、贴纸拥有独立背景与涂鸦。
- 对象工作副本的完成操作提交到父会话，作为父级一次撤销；取消丢弃工作副本。
- 子编辑器打开期间父会话不接收编辑指令；正式页面可以保存打开子对象前的稳定版本，不能混入未提交对象修改。
- 内层草稿按 bookID/pageID/contentID 与基线版本隔离。子对象完成不表示最外层页面已经发布，须沿父级提交到根页面。
- 返回父级时保留对象外部位置、角度、缩放和父级顺序；内部越界装饰不能导致主体跳动。

### 3.6 整本阅读

- 阅读为只读整页展示，一屏一页，横向滑动；显示“当前页 / 总页数”。
- 进入时指定有效 pageID，否则打开第一张有效页；空本不能进入阅读。
- 支持放大查看页面预览、回到总览和编辑当前页；放大状态下优先处理平移，避免误翻页。
- 查看缩放、滚动位置、阅读进度属于用户界面状态，不修改作品或页版本。
- 缺少预览时自动生成；单页损坏显示该页占位及重试入口，仍可翻到其他页，不把损坏页算作不存在。
- 删除、恢复或排序后按 pageID 重新定位；当前页已删除则选择原位置的下一页，没有下一页选上一页，没有页面则返回空本总览。

## 4. 数据模型与不变量

### 4.1 手帐本 DiaryBook

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| format / schemaVersion | String / Int | 新协议标识与版本，未知版本不写回 |
| id | UUID | 永久本 ID，与目录名一致 |
| catalogRevision | UUID | 每次目录提交更新，用于并发校验 |
| title | String | 名称，非文件路径 |
| createdAt / updatedAt | Date | 统一编码为 UTC 时间；创建时间不随编辑变化 |
| defaultPageSize | Size | 有限正数，首版统一全本尺寸 |
| coverPageID | UUID? | 指定有效页；nil 表示动态使用第一张有效页 |
| pages | [DiaryPageEntry] | 唯一有效阅读顺序，无重复 ID |
| trashedPages | [DiaryTrashedPageEntry] | 已软删除页面的引用和恢复元数据 |

本的 updatedAt 在重命名、页面创建/编辑提交/排序/删除/恢复、封面变更时更新；浏览、预览生成、缓存重建不更新。

### 4.2 页面目录项 DiaryPageEntry

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| id | UUID | 在本内唯一，与 page.json 一致 |
| title | String | 可为空；页码由 pages 顺序计算 |
| createdAt / updatedAt | Date | 内容提交或页标题修改时更新 |
| revisionID | UUID | 指向完整不可变页面快照 |
| size | Size | 与该页根画布尺寸一致；用于不加载图层就排版卡片 |

页标题与顺序以 book.json 为权威，不在 page.json 重复维护。size 是明确的查询冗余，发布页面前必须检查与根内容一致，读取矛盾视为无效版本。

### 4.3 页面文档 DiaryPageDocument

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| id / bookID | UUID | 页面及所属本，加载时检查身份 |
| rootContentID | UUID | 必须存在于 objects，角色是 canvas |
| assets | [AssetID: Asset] | 当前快照引用的资源描述，不嵌入图片字节 |
| objects | [ContentID: DiaryObjectContent] | 本页可达对象图；每个对象只有一个可变内容所有者 |

现有 DiaryDocument 在新架构中承担页面文档职责，可命名为 DiaryPageDocument。根画布没有外部摆放变换；其内部对象仍使用父级局部坐标、固定锚点和独立变换。

### 4.4 资源与对象约束

- assets 中记录 ID、相对资源路径、类型、校正方向后的像素尺寸、字节长度；建议加入内容摘要用于完整性校验与后续去重。
- 原资源写入后不可变；替换照片创建新资源引用，旧版本仍引用旧文件。
- 资源可以跨页共用；图层及对象内容不能跨页共享可变实例。
- 父子图不能成环；对象 ID 与图层 ID 必须唯一；引用目标必须存在。坐标和尺寸禁止 NaN/Infinity。
- 页面图层数组由底到顶绘制。页目录数组由前到后阅读；两者顺序互不影响。
- UI 选中对象、画布缩放、工具选择、阅读位置不进入作品文件。
- 撤销历史按编辑会话管理；重新打开页面首版不承诺恢复撤销栈，但必须恢复所有已提交图层内容。

## 5. 本地文件协议

```text
Application Support/Diaries/<ownerScope>/
├── library-index.json                  # 可重建的书架摘要缓存
└── books/<bookID>/
    ├── book.json                       # 唯一正式目录和页面版本引用
    ├── book.previous.json              # 同协议上一次完整目录提交
    ├── assets/<assetID>.<ext>           # 书内共用、不可变的原始资源
    ├── pages/<pageID>/revisions/<revisionID>/
    │   ├── page.json                   # 页身份、资源表、对象文件索引
    │   └── objects/
    │       ├── <contentID>.json
    │       └── <contentID>.drawing
    └── drafts/<pageID>/<sessionID>/
        ├── draft.json                  # 基线页版本、目标对象、更新时间
        └── …                          # 完整工作副本或已定义的快照引用

Caches/DiaryPreviews/<ownerScope>/<bookID>/<pageID>/<revisionID>/
├── thumbnail.png
└── preview.png
```

- book.json 是某页当前版本的唯一权威。页面目录不再另设独立 CURRENT 发布指针，避免两份“当前版本”分歧。
- 数据文件使用 Codable/JSON；涂鸦保留原生 drawing 文件；原图不转 Base64 塞进 JSON。
- 所有文件路径基于受控根目录拼接。加载拒绝绝对路径、目录穿越、身份不匹配和超出预算的文件。
- library-index 仅保存本 ID、名称、页数、封面引用、修改时间等摘要；写入失败不影响作品，可扫描 book.json 重建。
- 原图和文档放持久目录，不放 Caches；预览可由系统清理，清理后必须能重建。
- 无须首版引入数据库与文件索引双重权威。是否增加 SwiftData 后续由查询需求决定。
- 当前 app 内部目录格式不是用户可导出的单文件包；可编辑包导出后续另行设计。

## 6. 写入事务与保存状态

### 6.1 发布页面新版本

1. 编辑器冻结不可变文档快照，记录 basePageRevision、sessionID 和本次操作 ID。
2. 后台验证对象图、资源与尺寸，写入新增资源。
3. 生成唯一 revisionID，将 page.json、对象 JSON 与 drawing 全部写入新快照目录。
4. 在同一本的串行仓库中重新读取最新 book.json，检查当前 pageID 仍有效且 revisionID 等于 basePageRevision。
5. 在最新目录基础上只更新这一页引用及时间，保留同时发生的其他页编辑和目录顺序变更。
6. 保留原完整 book.json 为 previous，再使用同卷原子替换发布新 book.json。
7. 返回明确的 PageCommitResult；更新书架摘要，并触发新版预览任务。

步骤 6 之前失败：旧目录仍有效，新文件为未发布候选，不显示为成功。步骤 6 成功后，即使摘要或预览生成失败，页面已经保存，不能提示“保存失败”并让用户重复提交。

原子替换是可见性边界，不等于无限制的断电持久保证；实现应使用平台文件协调机制并验证中断恢复，不在 UI 承诺零丢失。

### 6.2 并发与乱序

- 一本内发布由同一个 actor/串行仓库协调。多个 Store 实例不得各自绕过锁修改 book.json。
- 不同页保存允许并行准备资源，但发布时合并到最新目录，不能用旧本对象整份覆盖其他页。
- 同页首版只允许一个写会话；重复打开路由到已有会话或提示正在编辑，不启动第二个可写副本。
- 仍需校验基线 revisionID；冲突时保留本地草稿并阻止覆盖，允许重载已保存版。首版不自动合并同页修改。
- 保存队列合并高频待保存快照；同一页面按序发布。旧保存结果不得覆盖新 revisionID 或把更新的内存状态标为已保存。
- 目录改名、封面、排序等都通过同一仓库执行，并使用 operationID 防止重复操作。

### 6.3 自动保存与退出

- 拖动/滑块/笔画结束形成一次命令；建议静止 1 秒自动保存，不把每个手指移动事件写盘。
- 状态包括：已保存、待保存、保存中、保存失败；内层显示“草稿已保存”而非误导为整页已提交。
- 点击完成立即 flush 最新快照；有保存任务时等待并处理剩余修改，成功才关闭。
- 切后台尽力请求有限后台时间 flush，不能依赖系统保证执行到结束。尚未写盘的操作可能无法在强制终止后恢复，应尽量缩短保存窗口。
- 保存失败保留内存文档、历史和草稿，显示重试；返回按钮不能绕过失败直接释放会话。
- 一个失败任务不得清除最近一次可用正式版本。

## 7. 草稿、异常恢复与删除

### 7.1 对象草稿恢复

- 正式页面与对象草稿分开；内层自动保存不发布到 book.json。
- 重开页面先加载正式版本，然后检查草稿；有匹配基线的草稿时提供“恢复编辑 / 放弃草稿”。
- 多层嵌套草稿记录父会话链及基线；恢复从最外层未提交会话开始，不将孤立的深层草稿直接覆盖根页面。
- 基线已变化时不自动恢复覆盖；保留草稿并说明版本不匹配，后续提供另存页面能力前不可静默合并。
- 完成提交成功后才清除相应草稿发布引用；取消明确丢弃本次对象工作副本。

### 7.2 删除与回收站

- 页面删除需要明确确认，提示“移到最近删除”；书本删除同理，确认文案包含名称与页数。
- 软删除页面从 pages 移入 trashedPages；记录删除时间、原位置、邻近 pageID、原版本引用和是否曾作封面。
- 删除指定封面页后 coverPageID 设为 nil，使用当前第一页；删除最后一页后保持空本并显示默认封面。
- 建议保留 30 天；到期后在下一次可执行清理时回收，不承诺到点立即执行后台任务。
- 恢复优先插回有效邻页旁，否则用原位置夹在现有索引范围内；若用户后来另设封面，不因恢复自动覆盖其选择。
- 整本软删除通过同一受控仓库将本移入 ownerScope 下的 trash/books，保存删除元数据；恢复保持 ID，身份冲突则停止并报错。
- 正在编辑的页面或本不能直接删除；提示先完成/退出编辑，再执行删除事务。
- 永久删除与清空回收站另行确认；执行前检查没有活动编辑、导出、草稿恢复或预览读取任务使用对应资源。

### 7.3 资源回收

- 首版可以保守保留未引用素材，不能为了腾空间立即删除刚从图层移除的照片。
- 回收必须扫描：有效页、保留的上次目录与页版本、回收站、草稿、活动历史/会话、进行中的导出任务。
- 只有没有任何保留引用的资源才可删除。资源本内共用，不以单页删除作为删除原图的依据。
- 清理缓存与删除作品分开呈现；“清理预览缓存”不删除任何可编辑内容。

## 8. 按需加载与预览

| 场景 | 必须读取 | 不应提前加载 |
| --- | --- | --- |
| 书架 | 本摘要、可见封面缩略图 | 每本全部页面对象与原图 |
| 页面总览 | book.json、可见页缩略图 | 所有页面编辑会话 |
| 阅读 | 当前页大预览、邻近页预览 | 整本全分辨率图片 |
| 编辑 | 当前页对象图、drawing、编辑尺寸图片 | 其他页的图层树 |
| 对象编辑 | 当前页面已加载数据的工作副本 | 重新解码全本资源 |

### 8.1 预览生成规则

- 编辑预览、页面缩略图、阅读预览和导出使用同一渲染规则；棋盘格、控制框、工具、页码标识不绘入作品。
- 建议缩略图长边 480 px，阅读预览长边 1800 px；保留 alpha。尺寸是缓存级别，不改页面设计单位和原图。
- 缓存键包含 ownerScope/bookID/pageID/revisionID/尺寸等级/rendererVersion；页面版本相同但渲染规则变化时也须失效。
- 异步完成时比对当前绑定的 ID 与 revisionID，不能把复用卡片上旧任务的图片贴到新页面。
- 使用可见请求优先级、请求合并和取消；建议同时进行 1 个重渲染任务，避免大量页并行解码原图。
- 页面缓存、资源解码缓存设置明确内存预算；建议总预算起点 64 MiB，实机测量后调整，内存警告主动释放可重建内容。
- 初次进入不应等待全本预览完成；无缓存先显示比例正确的占位，逐页填充。

### 8.2 刷新和封面

- 页面提交返回 pageID/revisionID 后直接通知对应总览与阅读模型失效刷新，不靠整本重载或延时猜测。
- 封面使用所指页面的当前版本预览；该页更新后封面同步失效。
- 未指定封面动态使用第一张有效页；排序会改变自动封面，明确指定的封面不变。
- 整页透明或空白是合法页面，不能当作渲染失败。封面卡片外层可以加纸张底板和名称。

## 9. 异常与数据保护

| 情况 | 必须行为 |
| --- | --- |
| 用户取消照片选择 | 留在原界面，不发布新页 |
| 照片读取失败/受限 | 提示重选，不生成缺资源页面 |
| 磁盘不足 | 保留旧提交及内存修改，显示可重试状态；缓存可清理但不擅删作品 |
| 单页资源缺失 | 标记受影响页并保留原引用，不用占位内容覆盖保存；其他页继续可读 |
| 页对象 JSON 或 drawing 损坏 | 禁止将损坏内容按空白页保存；显示重试/恢复提示 |
| 当前本目录损坏 | 尝试验证 previous；使用前告知恢复到上次完整目录；两份均坏则保留文件并标记异常本 |
| 索引损坏或过期 | 扫描有效 book.json 重建，不删除本目录 |
| 预览缺失/系统清缓存 | 重新生成，不影响编辑数据 |
| 文件版本不支持 | 只提示，不自动迁移或覆盖 |
| 帐号切换/退出 | 先保存或处理失败，关闭旧会话，取消旧账号预览任务并清理内存缓存；新列表只读新 scope |
| 旧账号异步任务晚返回 | 比对 ownerScope/sessionID 后忽略结果，不写入当前账号界面 |
| 手帐已软删除但旧回调返回 | 验证仍有有效目录引用，不恢复书架条目、不重新发布被删页 |

应用业务层还需阻止账号切换绕过未保存失败。退出登录不自动删除本地手帐；永久删除账号数据按现有账户策略单独处理。系统备份策略应区分可编辑原始资料与可重建缓存，不把原图标记为可随意清理数据。

## 10. 服务接口与模块边界

以下接口为设计契约，参数与返回值须在编码时统一定义，不是既有 API：

```swift
// 一本仓库协调所有正式发布，避免目录与页面独立保存产生矛盾。
protocol DiaryBookRepository {
    func listBooks() async throws -> [DiaryBookSummary]
    func createBook(request: CreateBookRequest) async throws -> DiaryBook
    func loadBook(bookID: UUID) async throws -> DiaryBook
    func createPage(request: CreatePageRequest) async throws -> PageCommitResult
    func openPage(bookID: UUID, pageID: UUID) async throws -> OpenPageResult
    func savePage(request: SavePageRequest) async throws -> PageCommitResult
    func updateBook(request: UpdateBookRequest) async throws -> DiaryBook
    func reorderPages(request: ReorderPagesRequest) async throws -> DiaryBook
    func trashPage(request: TrashPageRequest) async throws -> DiaryBook
    func restorePage(request: RestorePageRequest) async throws -> DiaryBook
}
```

SavePageRequest 包含 bookID、pageID、basePageRevision、operationID、sessionID 与冻结文档；PageCommitResult 包含 pageID、新 revisionID、本 catalogRevision、提交时间，不能用 Bool 隐藏冲突或失败原因。

## 11. 性能、交互与辅助功能目标

- 建议验收规模：20 本，每本 100 页，每页 30 个对象；这是性能测试样本，不是静默限制用户创建数量的硬上限。
- 验收目标建议：命中本地缓存后书架/总览首屏 500 ms 内可交互；当前页完整打开 2 s 内可编辑。必须记录目标设备、冷/热启动、图像尺寸与测量结果，未测量不能写成已达标。
- 滚动与翻页不在主线程做磁盘读写和整页批量解码。当前渲染实现若必须在主线程使用 UIKit，须限制任务规模并测量卡顿，不能笼统声称渲染已全部后台化。
- 极端大图先读取元信息再下采样，编辑与导出使用不同分辨率；不同时持有全本原图解码结果。
- 名称和页标题支持中文、emoji、多行截断、动态字体；按钮点击区域建议至少 44 pt。
- VoiceOver 描述“第 N 页，页标题，是否封面”；排序提供按钮替代拖动，不能只用颜色传达保存失败。
- 首版不依赖仿真翻书动画；减少动态效果开启时使用简单切换。
- 多窗口编辑先限制同页单写；界面进入后台、设备旋转、内存压力时维持 bookID/pageID 身份，不重新创建文档。

## 14. 首轮落地记录（2026-10-14）

本节记录实际代码范围，覆盖状态优先于前文目标能力的措辞。

已接入项目的流程：书架 → 新建本（竖版/正方形）→ 新建空白页或照片页 → 现有全屏编辑器 → 完成返回并刷新预览；页面总览可进入整本阅读，也可在阅读中打开当前页编辑并回到原页。根画布与对象的透明背景、嵌套图层和涂鸦继续复用。

已接入的管理动作：手帐重命名、指定封面/自动封面、页面前后移动、页面软删除及恢复。页面总览采用自适应卡片列数。逐页阅读仅请求当前及相邻页的大预览。

实际存储映射：

- `DiaryBook` 保存本目录、有效页、已删除页与封面引用。
- 当前 `DiaryDocument` 保留类型名称并增加 `bookID`，承担页级文档职责。
- `DiaryDocumentStore(ownerID:bookID:)` 作为当前本的存储入口；所有实例共用文件串行队列。
- `books/<bookID>/book.json` 是正式页面版本的唯一入口；快照使用 `pages/<pageID>/revisions/<revisionID>/manifest.json` 命名，职责对应前文的 page.json。
- 图片资源存放在本目录的 assets，共用原始文件；页面 JSON 记录自己的引用。
- 预览放在 Caches，按账号、本、页、revision 与尺寸隔离；内存缓存预算 64 MiB。
- 初版书架直接读取各本 book.json，尚未加入可重建的 library-index。
- 同页基线不一致时拒绝覆盖；浏览预览不改变编辑会话保存基线。
