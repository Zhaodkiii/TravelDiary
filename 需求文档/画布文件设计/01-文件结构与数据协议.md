# 01 文件结构与数据协议

## 1. “文件”实际包含什么

编辑中的作品使用一个目录；传输时可压缩为 `.tdiary`。首版内部目录先实现，用户导入导出文档包另行排期。

```text
<documentId>/
├── CURRENT.json
├── revisions/
│   └── r000001/
│       ├── manifest.json
│       └── pages/<pageId>.json
├── assets/<assetId>.<扩展名>
├── drawings/<内容校验值>.drawing
└── cache/
    ├── previews/
    └── thumbnails/
```

修订目录保存某次完整文档状态。图片可被多个修订共用，图片文件一旦提交就不覆盖。CURRENT 指向当前有效修订，不是页面内容本身。

## 2. CURRENT 指针

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| schemaVersion | 整数 | 当前协议为 1 |
| documentId | UUID 字符串 | 必须与 manifest 一致 |
| revision | 正整数 | 单调增加的提交号 |
| manifestPath | 字符串 | 相对文档根目录的清单路径 |

例如 `manifestPath` 为 `revisions/r000001/manifest.json`。所有文件引用均相对于 `<documentId>` 根目录，不能有设备绝对路径、上跳目录或外部链接。

## 3. manifest 清单

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| schemaVersion | 整数 | 文件协议版本，与应用版本分开 |
| documentId | UUID | 作品唯一身份 |
| revision | 整数 | 与 CURRENT 指向的版本一致 |
| title | 字符串 | 作品名称 |
| createdAt / updatedAt | UTC 时间字符串 | 排序与展示信息，不用于图层排序 |
| pageRefs | 有序数组 | 每项有 id 和 path，数组决定页顺序 |
| assets | assetId 到资源记录的映射 | 图片和随文档保存的字体等资源 |

资源记录包含 `kind`、`path`、`mimeType`、`byteSize`、`sha256`。图片另有 `pixelSize`；方向统一规范化为 upright，像素尺寸对应规范化资源。`sha256` 对最终保存的字节计算，不能对预览图计算后用于原图校验。

应用随附字体可使用稳定 fontId；自定义字体必须有可持久访问的字体资源映射。所有图层共享同一份资源表，不能每次使用照片都复制一份 Base64。

## 4. page 页面文件

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| id | UUID | 页面身份 |
| size | width、height | 正数，页面设计单位 |
| background | 有判别类型的对象 | `solid` 保存 color；图片背景保存 assetId 和取景规则 |
| layers | 图层数组 | 从底到顶绘制 |
| drawingRef | 对象或 null | 有绘画时包含 path、format、contentVersion；空画笔为 null |

背景固定在内容最下方，画笔固定在内容最上方。页面本身不保存手机屏幕尺寸、缩放查看比例和当前选中对象。

## 5. 图层外壳

所有图层包含：

```text
id、name、type、visible、locked、opacity、transform、payload
```

`type` 为 `image`、`text`、`group`。`payload` 根据 type 解码；未知 type 不能静默删除再保存。ID 在整个文档内唯一，复制图层递归生成新 ID。

`transform` 保存 position、pivot、scale、rotationDegrees、flipX、flipY。字段含义见坐标文档。位置允许在页外，scale 必须大于零，所有数值必须有限。`opacity` 为 0～1；即使完全透明仍保留数据。

### 5.1 图片 payload

| 字段 | 含义 |
| --- | --- |
| role | photo 或 sticker，用于决定工具入口 |
| assetId | 对应素材资源 |
| size | 外框的本地宽高，非原图像素宽高 |
| crop | 照片保存 fit=cover、zoom、offsetX/Y；贴纸为 null |
| mask | rectangle 或 roundedRectangle；圆角值使用本地设计单位 |

贴纸没有 crop 时按完整图片比例显示，size 必须保持原始宽高比；不能隐式采用照片 cover 规则裁掉贴纸。第一版图片尺寸、crop、transform 不重复保存最终屏幕矩形。

### 5.2 文字 payload

包含 text、layoutWidth、fontId、fontSize、lineHeightMultiple、alignment、color。颜色为 sRGB 的 `#RRGGBBAA`，字号和宽度使用设计单位。文本按统一布局服务换行并自动计算高度。

### 5.3 分组 payload

包含 role 和 children。原型 role 为 photoComposition，children 恰好包含一个 photo 和若干 sticker / text；首版不允许 group 内再嵌 group。

父子关系只由 children 表达；parentId 不持久化，运行时遍历生成。分组不保存独立拉伸宽高，边界通过子元素计算，固定 pivot 不随边界重算。

## 6. 读取约束

- 缺少必要字段、重复 ID、资源引用断裂、无效数值视为损坏，提示并保留原文件。
- 新 schemaVersion 超过支持范围时不覆盖保存；升级旧版本必须显式迁移。
- missing asset 可保留布局并显示占位，但不能把缺失图自动变成新空图覆盖文档。
- 业务数据由模型保存，View、UIImage 和解码缓存不写进 JSON。
- 后续增加滤镜、描边、蒙版等字段时必须定义缺省值和旧版本行为。
