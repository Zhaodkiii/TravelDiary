# 04 本地资源与保存恢复

## 1. 本地目录归属

建议在应用沙盒的持久 Application Support 目录下建立 `Diaries/<ownerScope>/<documentId>/`。通过系统目录 API 每次定位根目录，不把当前沙盒绝对路径写入 JSON。

ownerScope 使用内部稳定账号标识或本地游客标识，不使用电话号码等展示信息。账号切换不能把其他账号目录当作当前作品集合；游客迁移另按账号需求处理。

用户需要在“文件”中访问时，可通过显式导出文档包实现。删除应用可能删除本地文档，自动保存只保证应用所管理的存档，不等同于云备份。

## 2. 不同资源存什么

| 内容 | 文件形式 | 说明 |
| --- | --- | --- |
| 照片 | JPEG/PNG 等已支持图片 | 导入后持久副本，用于重开与输出 |
| 贴纸 | 保留透明度的 PNG 等 | 不转换为会丢失透明度的格式 |
| 背景图 | 图片资源 | 页面保存 assetId，纯色背景直接存颜色 |
| 字体 | 应用内版本化字体或文档内字体文件 | 文档引用 fontId/字体资源映射 |
| 画笔 | 原生绘画数据文件 | 固定页面设计坐标及兼容版本 |
| 页面与图层 | JSON | 数据和文件引用，不含图片 Base64 |
| 预览与缩略图 | 降采样图片 | 可清理并再生，不替代原素材 |

原始导入文件可按需要另存 source 副本；首版至少保留高质量、方向规范化的编辑主资源。若进行了格式转换，明确区分“源文件”和“规范化编辑资源”，不能宣称两者字节完全相同。后续裁剪和变换始终基于不可变编辑主资源。

## 3. 导入资源

```text
系统选择器临时结果
  → 获取文件字节并验证格式/尺寸
  → 方向规范化、必要格式转换
  → 写入文档内临时文件
  → 校验字节数、内容校验值及可解码性
  → 发布不可变 assets 文件
  → 建立 AssetRecord
  → 提交图层 assetId 引用
```

用户取消相册权限或删除原照片后，已成功导入的副本继续有效。远程贴纸下载失败不能先把一个永久损坏引用写进文档。相同资源可按内容校验值去重，但同一个文件被多个图层引用时，修改取景仅修改对应图层。

## 4. 保存一次修改

内存中有已提交文档状态和正在进行的交互预览。手指松开或点击完成后，把完整修改提交为命令，推进 revision，进入保存队列。

以从 r000001 保存到 r000002 为例：

1. 捕获不可变文档快照，持有它引用的素材。
2. 新照片或画笔数据先落盘，并确保写入完成。
3. 在同卷 staging 中写入新页 JSON 和 manifest。
4. 验证页面、资源、ID 与路径完整，发布为 revisions/r000002。
5. 原子替换 CURRENT 指向新 manifest，保留上一有效指针。
6. 对应 revision 标记已保存，之后再生成缩略图。

素材没变时不重新复制照片；移动照片主要新增一份很小的页面 JSON。原型每次保存完整页面结构，便于恢复，后续再评估增量存储。

同一文档的保存任务串行，旧任务完成不能把更新的内存状态误标为“已保存”。磁盘满或文件写入失败时仍显示未保存，可重试；不能把仅更新缩略图当作保存成功。

## 5. 下次打开的恢复顺序

1. 定位账号范围下的文档目录。
2. 读取 CURRENT，找到确定的 manifest 和 revision。
3. 校验 schemaVersion，读取页面顺序和资产资源表。
4. 读取当前页，根据 children 建立图层树及父节点索引。
5. 对每个图层计算父到子的世界矩阵、可见性与锁定状态。
6. 用 assetId 解析本地图片，载入当前页必要资源及字体。
7. 按本地 size、crop、transform 重建照片、贴纸和文字。
8. 载入绘画数据，在页面上方按同一坐标绘制。
9. 根据当前屏幕计算新的查看比例，允许继续编辑。

图片异步到达时不重新分配照片框位置，框的几何来自 JSON。每个任务携带当前 documentId、pageId、layerId、assetId 和请求代次，忽略已经被替换的加载结果。

## 6. 加载效率

列表只读封面缩略图；打开作品优先读取当前页；图片按需要显示的像素尺寸解码，放大或导出时提高分辨率。缓存键包含资源身份、版本或校验值、解码档位及处理参数。切页可释放解码缓存，不能删除核心资源。

图片文件体积不等于解码内存，例如 4000×3000 的四通道位图基础像素数据约 48 MB，还不包括其他缓冲。不要只按 JPEG 文件大小控制内存预算。

## 7. 异常和回收

| 情况 | 恢复行为 |
| --- | --- |
| 新修订写完但指针未发布 | 仍打开旧的已提交修订，孤立目录以后清理 |
| CURRENT 损坏 | 回退明确保留的前一有效指针；不盲目取最大目录编号 |
| 某图片丢失 | 显示占位、保留布局，允许重新关联；导出前提示 |
| 字体缺失 | 保留原 fontId，提示替代；不静默覆盖原文档 |
| 新协议版本不支持 | 提示或只读，禁止强行降级保存 |
| 缓存丢失 | 从核心资源重新生成 |
| 删除或替换照片 | 等文档、保留修订、撤销、导出全部释放引用后才回收 |

关闭后恢复依赖当前文档快照，不依赖撤销栈。首版不承诺恢复上一会话的历史栈。修订快照只用于可靠保存与恢复，用户可浏览的“版本历史”需要另做产品功能。
