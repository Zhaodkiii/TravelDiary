## 1. 首版边界与原型参数

- iPhone 优先；页面与照片组合两个编辑范围，组合内部保持独立图层。
- 贴纸、文字允许伸出照片边缘；页面范围外的部分不导出。
- 画笔属于页面，始终盖在普通内容上，不跟随照片移动。
- 图片导出先行；PDF、云同步、深层分组后续开发。
- 单页原型先验证：一页背景、一张照片、一个贴纸、一段文字、一份画笔数据；也允许添加额外元素以验证重叠和排序。

| 参数 | 原型默认值 | 说明 |
| --- | --- | --- |
| 页面设计尺寸 | 1000 × 1400 设计单位 | 原型测试值，不限制后续页面比例 |
| 页面背景 | 不透明浅色 | 原型不开放透明页面导出 |
| 图层变换 | 平移、等比缩放、旋转 | 首版不开放倾斜、透视和非等比拉伸 |
| 查看缩放 | 适应屏幕比例的 0.5～8 倍 | 仅查看状态，需实机验证 |
| 命中目标 | 至少约 44 × 44 屏幕点 | 小元素扩展触摸范围，不放大视觉内容 |
| 吸附 | 进入距离 6 屏幕点，脱离距离 10 屏幕点 | 按查看比例换算，防止来回抖动 |
| 图片导出 | PNG，2000 × 2800 像素 | 原型先用一种固定格式验证，产品档位另定 |
| 历史预算 | 最多 100 条或约 64 MiB，先到者生效 | 起始预算，按最低目标设备调整 |
| 自动保存 | 操作提交后空闲 1 秒，持续操作每约 5 秒提交已完成状态 | 不保存半个手势；后台保存为尽力完成 |

不在本轮调整现有工程最低系统版本。目标设备、系统和最终性能门槛在原型开始时记录。

## 2. 模块结构与职责边界

模块目录、文件职责、核心方法及调用流程见[画布编辑器整体架构与目录设计](./画布编辑器整体架构与目录设计.md)。

手帐编辑器独立建立 `DiaryEditor` 功能目录，负责图层树、画布交互、绘画适配、统一历史、文档存档和导出。图片通过素材导入接口接入。

```text
DiaryEditor/（建议目录，尚未创建）
├── Domain/          文档、页面、图层、资源、几何规则
├── Application/     编辑会话、命令、历史、保存与导出编排
├── Infrastructure/  文件存储、图片解码、绘画与渲染适配
└── Presentation/    画布、工具栏、输入与图层面板
```

文档不存 View、UIImage、CALayer 或 UIKit 对象。核心几何使用独立数值类型，平台转换留给适配层。数据库不是作品内容的第二份权威副本。

## 3. 数据协议

完整文件协议、位置恢复、照片裁剪、贴纸层级、文字及本地资源说明见[画布文件设计](./画布文件设计/README.md)，其中附有具体坐标和 JSON 示例。

### 3.1 文档与页面

| 类型 | 字段 | 约束 |
| --- | --- | --- |
| DocumentManifest | schemaVersion、documentId、title、revision、pageRefs、assets | 页顺序只由 pageRefs 决定 |
| Page | id、size、background、layers、drawingRef | layers 从底到顶；drawingRef 可空 |
| AssetRecord | id、kind、path、mimeType、byteSize、sha256、pixelSize | 路径相对文档根，图片宽高对应方向规范化后的资源 |
| DrawingRef | path、format、contentVersion | 不混入普通 layers 排序 |

文档 ID 和图层 ID 使用稳定 UUID 字符串。运行时建立 layerId → 节点、layerId → 父节点索引；序列化只存 children，不重复存 parentId。

### 3.2 图层统一外壳

```text
LayerNode
  id: UUID
  name: String
  visible: Bool
  locked: Bool
  opacity: Double [0, 1]
  transform: Transform
  payload: Image | Text | Group
```

持久化 JSON 使用明确的 `type` 判别字段，手写稳定的编码协议，不将 Swift 枚举自动编码形状直接当作长期文件规范。

| 内容类型 | 必要字段 | 首版约束 |
| --- | --- | --- |
| Image | role、assetId、size、crop?、mask | role 为 photo 或 sticker；贴纸默认显示完整图片 |
| Text | text、layoutWidth、fontId、fontSize、lineHeightMultiple、alignment、color | 高度由统一排版服务推导 |
| Group | role、children | 原型只允许 photoComposition，包含恰好一个主照片和若干贴纸文字 |

分组没有独立可拉伸的 width/height。其边界由可见子元素推导；变换锚点单独保存，不随推导边界变化而改变。组透明度作用于子树合成结果，不能简单逐个降低子元素透明度，否则重叠处结果不同。

图层锁定、可见性受祖先状态约束。隐藏元素仍在数据中；复制对象递归生成新 ID，复用不可变资源。

### 3.3 变换字段

```json
{
  "position": { "x": 500, "y": 600 },
  "pivot": { "x": 200, "y": 150 },
  "scale": 1,
  "rotationDegrees": -8,
  "flipX": false,
  "flipY": false
}
```

- position 是 pivot 映射到父级后的坐标。
- pivot 是本地坐标中的固定旋转和缩放中心。
- scale 为正的等比倍率，flip 与 scale 分开表达。
- 原型 scale 限制为 0.05～20，裁剪 zoom 限制为 1～10；同时验证数值有限和尺寸大于零。限制可在实机验证后调整。
- 旋转角规范为 [-180°, 180°)，不记录不断累积的整圈。
- 图片以左上角 (0,0) 建立本地矩形，初始 pivot 为中心；文字初始 pivot 为文本框顶部中心，后续文本高度变化不移动锚点。
- 照片组合初始 pivot 为主照片框中心；内部贴纸移动不重设组合 pivot。

## 4. 坐标、边界与变换

### 4.1 坐标约定

页面及本地坐标均为左上原点、x 向右、y 向下。正角度在视觉上顺时针。几何计算使用 Double；对接平台绘制时显式转换坐标系。

采用列向量，矩阵从右向左作用：

```text
Mlocal = T(position) × R(rotation) × S(scale × flip) × T(-pivot)
Mworld = MparentWorld × Mlocal
screenPoint = V × Mworld × localPoint
localPoint = inverse(V × Mworld) × screenPoint
```

V 只含查看比例和平移。导出使用目标输出比例替换 V，不使用当前手机视口。

### 4.2 移动、缩放、旋转

- 移动：把手指起点与当前位置分别映射到父坐标，以差值更新初始 position，避免直接用屏幕偏移。
- 缩放：以固定 pivot 为中心，用当前手指到中心距离与起始距离的比值乘初始 scale。手指过近中心时保持上次有效值。
- 旋转：在父坐标内计算起始、当前方向角之差，叠加初始角度；跨 ±180° 连续处理。
- 原型使用独立缩放和旋转手柄，不在同一次单指拖动中猜测操作类型。
- 组合变换不把新坐标逐个写回子元素。
- 修改照片框尺寸属于布局操作；原型通过裁剪预设保持框中心、固定框宽并调整高度，装饰位置保持不变。
- 文字换行宽度修改属于布局操作；缩放手柄改变整体 scale，不把文字横向拉长。

### 4.3 边界

图片区分外框、裁剪范围和图片原始像素范围。组合的操作边界取可见子元素经变换后的边界并集，允许负本地坐标。只有页面输出边界和照片自身蒙版产生裁切，组合默认不裁切其子元素。

选中框与手柄保持合理屏幕尺寸；缩放查看不会令手柄小到难以点击。完全移出页面的元素通过图层面板选中，并以“移回页面”命令调整到页面中心。

### 4.4 对齐吸附

原型支持页面或当前组内参考对象的中心线、边缘对齐。拖动期间只预览辅助线，吸附结果在手势结束作为一次变换提交。距离阈值使用屏幕点换算，不因放大而变得过强。旋转接近 0°、±90°、180° 时以 3° 进入、5° 脱离为起始阈值。

## 5. 照片取景与替换

图片导入后采用确定的方向规范化策略。设规范化图片为 W × H 像素，外框为 Fw × Fh 设计单位：

```text
base = max(Fw / W, Fh / H)
s = base × zoom
displayWidth = W × s
displayHeight = H × s
left = (Fw - displayWidth) / 2 + offsetX
top = (Fh - displayHeight) / 2 + offsetY
abs(offsetX) <= (displayWidth - Fw) / 2
abs(offsetY) <= (displayHeight - Fh) / 2
```

offset 单位为照片框本地设计单位；zoom 相对 cover 基础比例。超范围偏移夹取到合法范围，禁止照片框露空。原型裁剪不支持框内任意旋转，照片整体旋转交给图层变换。

双指缩放取景以手势焦点为中心：设图片中心 c、焦点 q、倍率变化 r，则新中心为 `q + r × (c - q)`，再根据新中心求 offset 并夹取。进入裁剪后暂停页面缩放手势。

| 操作 | 数据变化 | 保留内容 |
| --- | --- | --- |
| 拖动照片组合 | 组 position | 图片取景与装饰相对位置 |
| 拖动照片子图层 | 子图层 position | 装饰各自位置 |
| 裁剪拖动 | offsetX/Y | 外框位置与尺寸 |
| 裁剪缩放 | zoom、offset | 外框与组合变换 |
| 替换照片 | assetId，取景重置为 cover 居中 | 图层 ID、外框、组变换、装饰 |
| 切换框比例 | 本地尺寸及必要 pivot/position 补偿，重新夹取 crop | 框在父级中的中心位置、装饰坐标 |

裁剪打开工作副本，“完成”提交一次 CropPhoto 命令，“取消”恢复进入前状态。替换照片只有资源导入成功后才提交；取消选择无历史记录。主照片不能独立删除导致空照片组合，删除操作引导删除整个组合；替换始终可用。

## 6. 编辑范围与交互状态机

编辑范围为 `page(pageId)` 或 `group(groupId)`。交互模式为 `layout`、`crop(photoId)`、`text(textId)`、`ink`、`preview`；保存、导出进度独立管理。

| 模式 | 允许操作 | 退出规则 |
| --- | --- | --- |
| layout | 选中、拖动、手柄、图层操作、查看变换 | 结束当前手势后切换 |
| crop | 调整当前照片取景、选择框比例 | 完成提交，取消不修改 |
| text | 文本与样式工作副本输入 | 完成提交一次；取消回滚 |
| ink | 页面绘画或擦除、双指查看 | 笔画结束后退出 |
| preview | 查看作品，无编辑手柄 | 返回原范围和选择 |

原型仅在页面范围进入 ink；组合内隐藏画笔入口。组合“完成”只切换范围，内部已完成命令仍在统一历史中，不把整个组合编辑过程再压成一条重复命令。

### 6.1 命中优先级

1. 工具栏、面板等界面控件。
2. 当前选中对象的变换手柄。
3. 当前范围内从顶到底的可见、未锁定元素。
4. 背景空白：取消选择。

页面范围把组合当作一个命中对象；按其可见子元素覆盖区域判断，而不让组合大面积空白完全挡住下面元素。选中后允许在选中框内拖动整个组合。

原型图片按外框命中，透明贴纸内部透明部分也算命中区域；后续可增加像素透明度命中，不影响文件协议。小元素扩大的触摸区域只在没有更精确命中时作为候选。同类候选按层级决定，必要时从面板选择。

### 6.2 手势仲裁

- 单指布局手势与双指查看手势由统一控制器协调，不由各 View 互相争夺。
- 单指拖动途中加入第二根手指：回滚未提交的元素预览，切换为双指查看，不产生幽灵历史记录。
- 双指结束后剩下一根手指不立即开始移动元素，等待全部离开再识别新手势。
- ink 中出现第二指时，结束或取消当前输入事务后再进入查看；是否保留已识别笔画以绘画适配器明确回调为准，必须单次记录。
- 来电、失去焦点、应用后台等中断：布局拖动回滚未提交值；文本保留会话草稿；已完成笔画提交，未完成绘画按适配器结束状态处理。

## 7. 文字和绘画

### 7.1 文字排版

统一 TextLayoutService 接收文本、字体引用、字号、行距、对齐及 layoutWidth，产生确定的行布局和边界。预览与导出使用同一排版规则，不分别让两个布局系统猜测文本高度。

原型使用固定字体集合，支持中文、英文、换行和常见 emoji。自动增高，不截断正文；文本框宽度大于零。空白新文字取消创建，现有文字清空并完成按删除命令处理。组内文字与组一起等比缩放，修改文字本身字号则只更新该文字。

排版缓存按文本与全部样式参数失效。字体缺失时保留原引用并提示；不能将替代字体结果静默写回源文档。

### 7.2 顶层绘画适配

绘画数据采用页面设计坐标，画布控件内容尺寸和页面逻辑尺寸一致。内容渲染与 PKCanvasView 使用同一查看变换来源，避免两套滚动缩放各自累积。手指绘画启用，排版时不拦截内容手势。

原型采用笔、颜色、粗细及整笔橡皮擦，清空可撤销；局部像素擦除后续评估。只允许明确支持的墨水类型，保存其兼容版本信息。原型外观固定浅色，验证系统深浅色切换不改变最终墨水颜色。

绘画导出固定截取整个页面范围，不能使用实际笔画 bounds 作为画面原点，否则笔画会错位。跨平台可编辑笔画不在首版承诺范围。

## 8. 统一命令与撤销

### 8.1 命令结构

```text
EditorCommand
  id、label、pageId
  targetIds
  before、after（必要状态或差量）
  retainedAssetIds / retainedDrawingBlobs
  estimatedMemoryCost
```

命令示例：AddLayer、RemoveLayer、TransformLayer、ReorderLayer、SetVisibility、SetLock、ReplacePhoto、CropPhoto、EditText、SetBackground、ReplaceDrawing。删除与排序必须记录父级及原位置；删除组合保存完整子树。

开始交互捕获 before，移动阶段只更新预览工作状态，结束产生 after。没有实际变化不入栈；取消恢复 before。业务修改只能经过命令入口，不能让属性面板直接绕过历史修改文档。

undo 将 before 应用到文档并推进新的保存 revision；redo 应用 after。revision 单调增加，不能因为撤销而把持久化版本号倒退。撤销后新增命令释放重做分支持有的资源引用。

### 8.2 PencilKit 历史协调

采用文档历史为唯一用户可见时间线。绘画适配器在一次完整画笔或橡皮擦交互开始、结束时捕获 PKDrawing 前后数据，产生一条 ReplaceDrawing。

- `canvasViewDrawingDidChange` 只通知正在变化，不能每次回调都推入历史。
- 程序回放 drawing 时设置 replay 标志，阻止回调再次生成命令。
- 所有工具栏及系统快捷撤销路由到文档历史；隔离或重置绘画控件内部历史，禁止两条独立时间线交错。
- 清空画笔同样是一条 ReplaceDrawing。
- 接入前验证委托事件边界、擦除、后台中断和原生撤销手势；如无法可靠统一，此项为原型阻断问题。

快照数据按内容校验值共享，避免 before/after 重复驻留。达到预算时淘汰最旧命令并释放引用，保持当前文档可保存；单条命令超过预算时需明确降级策略，不静默破坏可预期的撤销。

## 9. 保存与加载的具体方案

### 9.1 不可变修订与提交指针

采用下列原型物理布局，细化总文档中的逻辑文档目录：

```text
<documentId>/
├── CURRENT.json                 # 指向已完整提交的 revision
├── revisions/
│   ├── r000001/
│   │   ├── manifest.json
│   │   └── pages/page_001.json
│   └── r000002/...
├── assets/<assetId>.<ext>        # 不可变资源
├── drawings/<contentHash>.drawing
├── cache/previews/...
└── cache/thumbnails/...
```

manifest 中所有资源及 pageRef 路径统一相对文档根目录，例如 `revisions/r000002/pages/page_001.json`。格式中显式约定根目录，禁止根据读取位置猜测相对路径。

### 9.2 提交流程

1. 捕获最新完整命令提交后的不可变文档快照，分配新 revision。
2. 写入新增素材及绘画 blob，校验成功后再建立引用。
3. 将 manifest 与页面写入同卷 staging 目录并校验。
4. 将 staging 发布为完整 revisions/rXXXXXX 目录。
5. 通过平台可靠文件替换机制更新 CURRENT 指针，保留先前有效指针。
6. 只有指针发布成功，才将该 revision 标记已保存；缓存缩略图随后更新。

保存队列每文档串行执行，最新待保存快照可以替换尚未开始的旧任务；旧任务完成不能把新修改标为已保存。多文件一致性通过修订目录与提交指针实现，不依赖“每个 JSON 分别写成功”。

若第 5 步前中断，仍读取旧指针，孤立新目录不自动当作用户已提交版本；若指针损坏，回退到明确保留的前次有效指针。保留至少上一完整修订。写盘失败保留 dirty 状态与重试入口。

### 9.3 加载和清理

读取 CURRENT → 校验版本与引用 → 读取当前页 → 构建索引 → 异步加载资源及 drawing → 恢复编辑。

后台资源结果携带 documentId、pageId 和当前请求标识，页面切换或照片替换后丢弃过期结果。打开未知新版本采用只读提示，不自动降级覆盖。

清理资源前计算当前修订、保留修订、历史栈、正在导出快照和未完成提交的引用并集；只回收并集之外的文件。原型可以暂不自动清理核心资源，缓存可独立清理。

## 10. 预览与导出

### 10.1 共享渲染语义

文档先解析成可绘制场景：世界变换、裁剪、可见性、组透明度、资源与文字布局。预览和导出共享场景解析和排版，不让两条路径各自解释图层字段。

原型 UI 使用 SwiftUI；内容视图具体采用 SwiftUI 或自定义绘制由一致性验证决定。图片导出走独立服务，绘画从 PKDrawing 按页面范围渲染后显式合成，不截图整个编辑器。

### 10.2 导出步骤

1. 结束或取消当前临时编辑；原型导出期间禁用文档修改，允许取消任务。
2. 捕获不可变快照并持有其资源引用。
3. 预检原始资源、字体及绘画数据；缺失时失败并列出问题对象。
4. 按固定目标像素尺寸建立 sRGB 输出，比例必须与页面一致。
5. 绘制背景；从底到顶递归绘制内容，分组透明度按整体合成。
6. 显式绘制页面顶部的画笔图像，裁切到页面矩形。
7. 编码至临时输出文件，成功后交给系统分享或相册保存入口。
8. 释放快照资源；报告成功、失败或取消，清理不完整临时文件。

相册权限失败与图片生成失败分开报告：已成功生成的图片可以继续分享。预览缓存分辨率不决定导出分辨率。大图读取须纳入内存预算，不能把所有源图完整解码并长驻后再额外生成成品。

## 11. 关键验证与变更规则

必须先验证：旋转组合内部命中、缩放后的拖动、裁剪焦点、文字跨预览导出一致、PencilKit 坐标同步、混合撤销和中断保存恢复。详细步骤见原型计划。

坐标、裁剪语义、编码字段或字体布局变化属于文件协议变更，应明确 schemaVersion 迁移，不静默解释旧值。原型数值调整可保留 schemaVersion，但需要记录原因和验证结果。
