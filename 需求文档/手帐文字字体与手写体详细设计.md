## 1. 目标与当前代码

用户打开文字编辑 sheet，输入内容、选择字体，输入框中的已有文字和后续输入立即使用最新字体。完成后，画布、对象预览、页面预览和导出采用相同字体。关闭并重新打开作品后仍能编辑。

当前阅读范围及结论：

| 文件 | 当前行为 | 需要改造 |
| --- | --- | --- |
| `Presentation/DiaryEditorScreen.swift` | `textEditor` 使用 TextEditor、字号滑块和完成/取消 | 拆分文字编辑 sheet，增加字体选择与实时预览 |
| `Domain/DiaryDocument.swift` | DiaryLayer 保存 text、fontSize，无字体引用 | 增加可保存的字体标识 |

## 2. 首版范围

- 一个文字图层整段使用一种字体和一个字号，支持多行文字。
- 内置系统字体以及至少一款覆盖常用简体中文的手写字体；建议最终控制在 2～3 款风格差异明显的手写字体，数量按安装包体积确定。
- 分类为“全部、系统、手写”，支持按字体显示名称搜索。
- 支持新建文字、编辑已有文字、取消、完成、统一撤销/重做、保存重开。
- 字体随应用资源打包，离线可用；字体提供者预留云端来源。
- 首版不提供局部文字混排、用户导入字体、自动生成个人笔迹、字体下载商城。

手写字体是字符的字形设计，用户仍然通过键盘输入可编辑文字。自由手写继续走已有画笔流程。中文手写体必须包含中文字形；只有英文字形的字体不能算作中文手写功能完成。

## 3. Sheet 的交互布局

使用一个文字编辑 sheet，建议默认 `.large`，同一弹窗中展示输入区和字体选择区，避免选字体时再覆盖一个 sheet。

```text
取消                  文字编辑                  完成
┌────────────────────────────────────────────────┐
│ 多行输入框：用当前字体和字号显示                  │
│ 今天的山风很温柔……                             │
└────────────────────────────────────────────────┘
字体：手写字体名称                 字号：36
字号滑块
全部 / 系统 / 手写                搜索字体
字体名称    用该字体展示“山川与日常 Aa 123”    ✓
字体名称    用该字体展示“山川与日常 Aa 123”
```

操作规则：

1. 新建文字默认系统字体、36 个设计单位；不自动继承其他图层的字体。首版不保存“上次选择”偏好。
2. 编辑已有文字时加载该层内容、字号和字体，定位到当前字体行。
3. 点击字体行立即更新草稿中的 fontID，输入框的全部文字同步变化；字体列表勾选状态同步更新。
4. 空输入框也显示当前字体的示例占位文字；占位文字不写入文档。
5. 选择字体不自动提交、关闭弹窗或清空输入内容，光标和选区保持；点击“完成”才提交。
6. 字体列表可独立滚动；键盘出现时输入区仍可见，保留“收起键盘”入口，避免字号/字体工具完全被遮挡。
7. 键盘候选文字正在组合时允许选择字体，先更新选择状态，待组合结束再应用样式，避免中文输入中断。
8. 字号沿用首版界面的 18～90 范围；文档已存字号可超出该滑块范围，打开时不得静默改写。若遇超范围值，显示原值并扩展滑块范围到原值。
9. 空白文字不能点完成；有效文字保留用户输入的换行和空格，不因校验而裁掉排版。
10. 修改后的草稿通过取消直接丢弃；有修改时禁用下拉关闭，用户明确选择完成或取消。无修改时允许下拉退出。
11. 完成期间禁用重复点击，成功后关闭；保存提交失败时显示错误并保留草稿。

## 4. 输入框实时字体实现

推荐新增 `DiaryTextInputView: UIViewRepresentable` 封装 UITextView，以便明确处理光标、中文组合输入和样式同步。

- 使用字体解析服务取得 UIFont，赋给 UITextView.font 和后续输入的 typingAttributes。
- 更新已有文本的字体和段落样式时保留 selectedRange、滚动位置；仅必要时写回文本，避免每次 SwiftUI 更新都重置输入框。
- 文本编辑使用 Coordinator 同步草稿，通过差异判断防止委托和 updateUIView 循环更新。
- markedTextRange 非空时，不替换 attributedText；记录待应用样式，在输入组合结束后应用。
- 内容只包含纯文本和整段样式；粘贴外部富文本时转为纯文本，应用当前字体，避免隐式引入多个字体。
- 首版保留现有居中、1.2 倍行高的页面文字样式；输入区应用相同段落参数。
- 字号为画布设计单位，作品不跟随系统动态字号自动重排；弹窗标题和工具标签仍支持系统动态字号。

输入框是编辑区域，其宽度与作品文本框可能不同，所以换行不必逐行相同。若需要判断最终换行，在输入区下增加按实际图层宽度绘制的“画布效果”预览，缩放显示。最终布局以统一渲染器为准，不承诺输入框和画布在不同宽度下完全同样换行。

## 5. 手写字体如何加入项目

### 5.1 素材准备

准备可随应用分发的中文手写 TTF 或 OTF 文件，以及对应授权说明。记录字体显示名、PostScript 名称、版本、文件校验值及支持语言。授权范围需覆盖 App 内嵌与用户导出图片；是否允许未来把字体随可编辑作品分发单独记录。

优先选择覆盖常用中文、标点、数字和拉丁字符的字体。上线前用真实旅行文案检查：“雨崩、武功山、太行山、四姑娘山、虎跳峡、苏州、上海、成都、杭州”。具体字体名称和下载来源待素材确认后补入目录，首版不依赖联网下载系统可选字体。

### 5.2 资源与注册

建议采用独立 `DiaryFonts.bundle`，与预设资源按用途分开管理，保留目录结构：

```text
Projects/App/Resources/DiaryFonts.bundle/
├── catalog.json
├── fonts/
│   └── <fontID>-<version>.ttf
└── licenses/
    └── <fontID>.txt
```

使用 Core Text 文件注册 API 按进程注册 bundle 内字体。注册服务负责幂等、并发串行化、错误记录和结果验证；创建 UIFont 之前必须完成注册。应支持直接进入编辑器、书架预览、预设预览及导出，不依赖用户先打开字体选择页。

主 bundle 的静态字体也可采用 UIAppFonts 注册；本方案选择独立资源包加运行时注册，便于未来接入下载包，避免同时维护两套注册清单。

注册成功后用 `UIFont(name: postScriptName, size:)` 创建字体。文件名、中文显示名、字体族名和 PostScript 名称不能混用；注册后需核验实际字体名称，防止默默回退系统字体。

字体包不得覆盖已有同名、不同内容的字体。更新字体须区分版本，并处理 PostScript 名称冲突；首版已发布的字体文件保持不变，避免旧作品排版随升级改变。

### 5.3 字体目录字段

| 字段 | 含义 |
| --- | --- |
| id | 稳定业务标识，例如 handwriting.zh.style01，示例不是实际字体 |
| version | 字体资源版本，保证重新加载可追溯 |
| displayName | 用户看到的名称 |
| category | system / handwriting |
| postScriptName | 创建字体所需的真实字体名 |
| relativePath | bundle 内路径，系统字体可为空 |
| sha256 | 校验具体字体文件 |
| supportedLanguages | zh-Hans、en 等素材声明，不能替代实际缺字检查 |
| licensePath | 内置授权说明路径 |
| sampleText | 字体行展示文本 |

## 6. 图层与本地保存

建议新增 `DiaryFontReference`，并让 DiaryLayer 保存可选 `font`；缺省解释为系统字体，不需要把字体文件复制到每一个文字图层。

```json
{
  "kind": "text",
  "text": "今天在雨崩",
  "fontSize": 36,
  "font": {
    "id": "handwriting.zh.style01",
    "version": "1"
  }
}
```

- 字体目录是 fontID 到具体字体文件和 PostScript 名称的映射；作品引用稳定 ID 和版本。
- 字体信息随现有对象 JSON 保存，页面 revisions、manifest 继续使用现有机制。
- 字体属于应用共享资源，首版无需写入 `books/<bookID>/assets`；预设导入整本或单页只保留字体引用。
- 撤销快照包含 font 引用，不能只保存在编辑器状态或 UserDefaults 中。
- 文档引用缺失字体时保留原始引用，临时用系统字体预览并提示“字体暂不可用，已临时替代”；不能在保存其他修改时悄悄覆盖 fontID。
- 缺失字体的图层重新打开编辑时显示原字体状态，用户明确选择替代字体后才修改引用。
- 未能恢复字体时，导出前提示排版可能变化并提供“使用替代字体导出 / 取消”；不把替代结果称为原样导出。

## 7. 绘制、尺寸与智能对象

`DiaryPageRenderer.textStyle` 调用统一 `DiaryFontResolver`，bounds、画布绘制、对象缓存、页面缩略图和高清导出都使用该字体及相同段落样式。

改变字体只调整文字自身的排版：保持文本框宽度，重新计算高度；固定图层外部位置、旋转、缩放与锚点参数。不自动移动对象内的贴纸、背景、涂鸦；字体较大导致文字与装饰重叠时，用户可继续编辑装饰。

选中框及命中范围随实际文字边界更新。对象的预览边界重新计算，避免手写字体上挑、下伸笔画被裁掉。超过现有文本测量高度上限时应明确处理，不能静默截断长文本。

字号、字体变化会改变换行，替换前后即使字号相同，视觉大小也可能不同。预览缓存必须在提交文字样式后失效；字体注册完成或字体可用状态改变时也需要提高字体目录 generation，刷新相关预览，避免继续显示缺失字体的旧缓存。

## 8. 缺字、错误与性能

- 使用统一系统级字体回退策略显示缺少的字符和 Emoji；输入框、画布、导出采用同样策略。
- 对当前文案检测目标字体的字形覆盖；提示“部分字符使用系统字体”，不要把中文回退后的效果宣传为该手写字体。
- 不支持的字体文件、文件损坏、注册失败：在选择器标记不可用，允许继续使用其他字体，不触发 fatalError。
- 字体列表使用懒加载，字体行只展示短样例；不为每行重复注册和解码整套字体。
- 字体读取与校验可在后台进行，UI 状态更新回主线程；多个页面并行请求同一字体时复用注册任务。
- 不对用户可自由输入的中文字体做只包含样例文案的子集裁剪，否则新输入的汉字会缺失。
- 体积预算在选定真实字体后测量，再确定内置款数；不得预先声称中文字体只有几百 KB。

## 9. 文件与核心接口规划

以下均为拟新增文件，按实际项目目录进一步落地：

```text
Projects/Core/Fonts/
├── FontCatalog.swift                 # 字体目录与资源描述
├── FontRegistry.swift                # 注册、幂等与注册结果
└── FontResourceProvider.swift        # 内置来源；预留云端来源
Projects/Features/DiaryEditor/
├── Domain/DiaryFontReference.swift   # 稳定字体引用
├── Application/DiaryTextEditDraft.swift
├── Infrastructure/DiaryFontResolver.swift
└── Presentation/Text/
    ├── DiaryTextEditorSheet.swift
    ├── DiaryTextInputView.swift      # UITextView 桥接
    └── DiaryFontPickerView.swift
```

核心方法职责：

- `FontResourceProvider.catalog()`：读取字体目录，返回可显示的字体描述。
- `FontRegistry.ensureRegistered(reference:) async throws`：确保所需字体已注册，合并重复请求。
- `DiaryFontResolver.resolve(reference:size:)`：返回 UIFont、实际字体身份及替代状态；同步绘制前先完成准备。
- `DiaryTextEditDraft`：保存 targetLayerID、初始内容、当前文字/字号/字体，不直接修改文档。
- `DiaryEditorSession.applyTextEdit(draft:)`：完成时检查目标仍存在且未锁定，一次提交全部字段，并形成一条撤销记录；禁止改成依赖此时 selectedID 的另一个图层。
- `DiaryPageRenderer.textStyle(_:)`：统一字体、颜色、段落样式的唯一入口。

领域模型不存 UIFont、SwiftUI.Font 或 Bundle 绝对路径。通用字体服务不依赖 DiaryEditorSession。

## 10. 与预设和后续云端的关系

预设文字增加与文档相同的 font 引用，包清单声明 requiredFonts。PSD 转换工具提取字体身份并通过显式映射表匹配 fontID，不能仅凭显示名假定同一字体。

转换结果中无法映射的字体要进入报告：可编辑文字按明确的替代策略输出，若为保持视觉选择栅格化，则标记其不再是可编辑文字。导入时检查依赖字体是否随应用提供。

后续云端只扩展 FontResourceProvider：下载、校验、落盘、注册后交给同一解析器。文档仍引用稳定 ID 和版本，禁止将临时下载 URL 写进作品。字体资源更新/删除不得让仍在编辑中的文字立即失效；字体重名冲突必须在注册前处理。

## 11. 实施顺序与验收

1. 确定至少一款中文手写字体素材和授权，建立字体目录、注册与解析服务。
2. 增加图层字体引用及保存/读取，接通统一渲染与缺失字体提示。
3. 实现文字 sheet、字体列表、输入框即时样式和草稿提交。
4. 接入预设字体映射、缓存刷新与导出缺失字体处理。
5. 在真机上验收中文输入、键盘、长文本与高清导出。

验收清单：

- [ ] 不先打开其他页面，直接打开文字 sheet 也能选择手写字体。
- [ ] 输入前选字体、输入后切字体、连续切换字体，输入框都立即反映最新选择。
- [ ] 切换字体保持光标、选区、文本和中文候选输入，无跳字或重复输入。
- [ ] 取消不修改作品；完成一次产生一条撤销记录，撤销/重做恢复文字、字号、字体。
- [ ] 保存并杀进程重开，字体引用和实际字体恢复；进入文字对象后仍可编辑。
- [ ] 字体改变后对象内贴纸、背景、涂鸦仍可单独编辑，外部摆放不跳动。
- [ ] 页面预览、对象预览和导出字体一致，放大导出不使用低分辨率截图。
- [ ] 中文、英文、数字、标点、Emoji、缺字及多行文本显示正常。
- [ ] 缺失/损坏字体可回退并告知，保留原引用；导出明确提示替代。
- [ ] 大字号及上挑/下伸字形不被裁切；旧的预览缓存及时刷新。
- [ ] 内置字体在飞行模式可用，字体列表不会因重复注册崩溃。
