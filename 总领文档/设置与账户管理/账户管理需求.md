# 账户管理需求

## 一、模块目标

账户管理模块承接设置页中的账户入口，负责展示当前账号资料、登录方式绑定状态、登录方式绑定/换绑、退出登录和账号注销。当前实现位于 `SupportClient/SupportClient/Projects/Features/AccountManagement/`，由 SwiftUI 页面、`AccountManagementViewModel`、Application UseCase、Domain 模型与 Repository 协议、Infrastructure Repository 和后端 API 共同组成。

本模块的核心目标是：

- 让正式账号用户能够查看账号 ID、联系方式、登录方式、登录时间和 Pro 状态。
- 让用户能够查看手机号、邮箱、Apple 登录等登录身份的绑定状态，并在服务端允许时进行绑定或换绑。
- 让高风险操作先完成已绑定身份的再验证，再提交目标身份或账号注销请求。
- 让退出登录和注销后的会话清理统一回到 `AppSessionStore`，避免页面局部状态与全局会话状态不一致。

当前实现范围已经覆盖账号资料加载、身份列表加载、手机号/邮箱/Apple 绑定与换绑、手机号/邮箱/Apple 注销验证、注销提交和退出登录。未确认后台是否支持注销状态查询、注销取消、服务端数据清理进度展示；当前客户端只实现注销提交后的本地登出。

## 三、设置页账户入口

### 需求说明

设置页必须提供稳定的账户入口。正式账号点击后进入账户管理页；设备游客账号点击后不直接进入管理页，而是打开登录页，将游客账号升级或绑定为正式账号。

### 基础要求与业务规则

- 设置页显示“账户管理”入口和右侧摘要。
- `session.isDeviceAccount == true` 时，右侧文案显示未登录，并通过升级登录弹窗承接后续动作。
- 正式账号优先显示 `session.displayName`，为空时显示 `session.email`。
- 设置页不直接发起账号管理 API，只负责导航和入口判断。

### 验收标准

- 正式账号点击入口后进入 `AccountManagementView`。
- 游客账号点击入口后展示 `LoginView` sheet，且 `session.isDeviceAccount` 变为 `false` 时自动关闭 sheet。
- 设置页的账户摘要与当前 `UserSession` 一致。
- 设置页没有直接依赖 `SupportAccountIdentityAPI`、`SupportDeactivationAPI` 或 OTP API。

### 技术细节与设计代码位置

- 入口页面：`SupportClient/SupportClient/Projects/Features/Settings/Presentation/SettingsView.swift`。
- 主 Tab 和导航：`SupportClient/SupportClient/Projects/App/Sources/App/AppCoordinatorView.swift`。
- 游客账号升级入口：`SupportMainCoordinatorView.handleAccountEntryTap()` 根据 `session.isDeviceAccount` 分流。
- ViewModel 创建：`SupportClient/SupportClient/Projects/App/Sources/App/AppContainer.swift` 中 `makeAccountManagementViewModel`。

## 四、账号资料与登录身份列表

### 需求说明

账户管理页进入后需要同时加载账号资料和登录身份列表，让用户看到当前账号基本信息，以及手机号、邮箱、Apple 登录等身份的绑定、可绑定和可修改状态。

### 基础要求与业务规则

- 资料加载来自当前 `UserSession`，包含 `accountID`、`displayName`、`contact`、`signInMethod`、`signedInAt`、`isPro`。
- 身份列表来自已鉴权接口 `/api/v1/accounts/identities/`，查询时带 `bundle_id`。
- 资料和身份列表并发加载，任何一侧失败都会进入统一错误提示。
- 未登录或会话为空时，Repository 抛出 `AccountManagementError.missingSession`。
- 后端返回未知 provider 时，`AccountIdentityList.from(dto:)` 会忽略该项，不让未知登录方式进入 UI。

### 验收标准

- 进入账户管理页时显示资料 loading 和身份列表 loading。
- 成功后展示账号资料卡、账户信息区、登录身份列表、退出登录区和危险操作区。
- 后端返回 `bound/modifiable/bindable` 后，UI 行为与这些标志一致。
- 会话缺失时展示本地化错误，不提交任何账号身份接口。

### 技术细节与设计代码位置

- 页面入口：`SupportClient/SupportClient/Projects/Features/AccountManagement/Presentation/AccountManagementView.swift`。
- 状态持有：`SupportClient/SupportClient/Projects/Features/AccountManagement/Presentation/AccountManagementViewModel.swift` 的 `profile`、`identityList`、`isLoadingProfile`、`isLoadingIdentities`。
- UseCase：`LoadAccountProfileUseCase`、`LoadAccountIdentitiesUseCase`。
- 领域模型：`AccountProfile`、`AccountIdentityList`、`AccountIdentityStatus`。
- Repository 协议：`AccountManagementRepository.loadAccountProfile`、`loadIdentities`。
- API：`SupportAccountIdentityAPI.listIdentities(bundleId:)`。

## 五、登录方式绑定与换绑

### 需求说明

用户可以对手机号、邮箱或 Apple 登录进行绑定或换绑。绑定/换绑属于高风险身份操作，必须先使用已绑定身份完成再验证，获得 `verificationTicket` 后再提交新目标身份或 Apple 凭证。

### 基础要求与业务规则

- 操作类型由 `AccountIdentityOperation.bind(provider)` 或 `.change(provider)` 表达。
- 再验证 purpose 分别为 `bind_identity` 和 `change_identity`。
- 目标手机号/邮箱发码 scene 分别为 `identity_bind` 和 `identity_change`。
- 手机号输入使用 `PhoneNumberInputModel`，提交给后端时使用 E.164；邮箱输入使用 `EmailAddressInputModel.normalizedEmail`。
- 目标验证码发出后冻结目标快照，校验和重发必须使用同一个手机号或邮箱，避免用户编辑后验证码与目标不一致。
- Apple 绑定或换绑使用系统 `ASAuthorizationAppleIDCredential` 中的 `identityToken`、`authorizationCode` 和 `userIdentifier`。

### 验收标准

- 点击绑定/修改后先进入再验证选择，而不是直接提交新目标。
- 手机号或邮箱目标格式无效时，发送验证码按钮不可用。
- 再验证 OTP 只有达到 6 位并且有 `otpID` 时才提交校验。
- 绑定或换绑成功后刷新 `identityList`，完成态关闭后回到账号管理主页面。
- OTP 错误时保留在当前验证码步骤并清空验证码，允许用户重试。
- 取消 Apple 登录时回到上一状态，不把取消当作业务失败。

### 技术细节与设计代码位置

- 流程状态：`AccountIdentityFlowState` 定义 `choosingReauth`、`reauthOTP`、`reauthApple`、`enteringTarget`、`targetOTP`、`submitting`、`completed`、`failed`。
- ViewModel 编排：`beginBind`、`beginChange`、`requestIdentityReauth`、`requestIdentityReauthOTP`、`verifyIdentityReauthOTPIfReady`、`requestTargetOTP`、`submitIdentityTargetOTPIfReady`、`completeIdentityAppleBind`。
- UseCase：`RequestIdentityVerificationUseCase`、`VerifyIdentityVerificationUseCase`、`BindAccountIdentityUseCase`、`ChangeAccountIdentityUseCase`。
- Repository 实现：`DefaultAccountManagementRepository.requestIdentityVerification`、`verifyIdentityVerification`、`requestTargetOTP`、`bindIdentity`、`changeIdentity`。
- API：`SupportAccountIdentityAPI.requestVerification`、`verifyAndIssueTicket`、`bindIdentity`、`changeIdentity`。
- OTP 能力复用：`SupportClient/SupportClient/Projects/Core/Networking/API/Auth/OTPAPI.swift`。
- Apple 凭证处理：`AccountManagementView.handleIdentityAppleReauthResult`、`handleIdentityAppleBindResult`。

## 六、账号注销与退出登录

### 需求说明

账户管理页需要提供普通退出登录和高风险账号注销。退出登录只清理本地会话并回到未登录状态；注销要求用户选择验证方式、完成 OTP 或 Apple 再认证、输入确认短语后，提交注销请求并执行本地登出。

### 基础要求与业务规则

- 退出登录必须通过 `SignOutUseCase`，成功后调用 `sessionStore.setSignedOut()`。
- 注销流程由 `AccountDeactivationFlowState` 管理，状态包括 `idle`、`chooseVerification`、`enteringOTP`、`appleReauth`、`finalConfirmation`、`submitting`、`completed`、`failed`。
- 注销可配置 `immediateDeactivation`、`countdownHours`、`dataRetentionDays`、`anonymizePersonalData`、`deleteRelatedData` 和可选原因。
- 手机号注销验证使用 scene `account_deactivation` 并带 `userId`。
- Apple 注销验证使用 `ASAuthorizationAppleIDCredential`。
- 注销成功后客户端立即执行登出；服务端数据删除、匿名化、倒计时执行由后台负责，客户端当前不展示后续进度。

### 验收标准

- 点击退出登录前出现确认弹窗，确认后回到未登录状态。
- 点击注销后必须先选择可用验证方式。
- OTP 验证码达到 6 位后进入最终确认；最终确认需用户输入固定确认短语。
- 提交注销时按钮区域展示 loading，成功后调用登出并切到 signedOut。
- 验证失败或提交失败时展示失败卡片，用户可以返回重新选择或取消。
- 注销流程取消时清空 OTP 和倒计时状态。

### 技术细节与设计代码位置

- 页面区块：`AccountManagementView.sessionSection`、`dangerSection`、`deactivationOverlay`。
- 状态定义：`SupportClient/SupportClient/Projects/Features/AccountManagement/Presentation/AccountDeactivationFlowState.swift`。
- ViewModel 编排：`beginDeactivation`、`requestVerification`、`completeOTPIfReady`、`completeAppleReauth`、`submitFinalDeactivation`、`signOut`。
- 领域模型：`AccountDeactivationOptions`、`AccountDeactivationVerification`、`AccountDeactivationSubmission`。
- UseCase：`RequestAccountVerificationUseCase`、`SubmitAccountDeactivationUseCase`，退出登录复用 `SignOutUseCase`。
- Repository 实现：`DefaultAccountManagementRepository.requestVerification`、`submitDeactivation`。
- API：`SupportDeactivationAPI.submit(_:)` 调用 `POST /api/v1/deactivation/`。

## 七、整体业务流程

```text
设置 Tab
  ↓
SettingsView 账户入口
  ↓
前置检查：session.isDeviceAccount
  ├── 是 → LoginView 升级游客账号
  └── 否 → AccountManagementView
              ↓
           ViewModel.load(session)
              ↓
           并发加载 AccountProfile + AccountIdentityList
              ↓
           用户选择绑定/换绑、退出登录或注销
              ↓
           UseCase 编排
              ↓
           AccountManagementRepository
              ↓
           SupportAccountIdentityAPI / OTPAPI / SupportDeactivationAPI / AuthRepository
              ↓
           结果映射为 AccountProfile、AccountIdentityList 或 AccountDeactivationSubmission
              ↓
           更新 flowState / identityFlowState / AppSessionStore
              ↓
           页面展示成功、失败、loading、弹窗或返回登录态
```

### 成功路径

账号资料成功路径：进入账户管理页后并发加载本地会话资料和远端身份列表，更新 UI。

身份绑定成功路径：选择绑定或换绑 → 选择已绑定身份再验证 → 取得 `verificationTicket` → 输入新目标或获取 Apple 凭证 → 提交绑定/换绑 → 更新身份列表 → 展示完成态。

注销成功路径：选择验证方式 → OTP 或 Apple 再认证 → 最终确认 → `POST /api/v1/deactivation/` → `SignOutUseCase` → `AppSessionStore.setSignedOut()`。

### 失败、重试和恢复

资料或身份列表加载失败时进入 `errorMessage` alert，用户关闭后可重新进入页面触发加载。OTP 错误等可恢复错误保留在 OTP 步骤并清空验证码，允许重试；不支持的验证方式、缺失会话或 Apple 凭证无效进入失败态。注销提交失败不清理会话，用户可返回重新操作或取消。

### 取消、并发和幂等

Apple 授权取消被识别为用户取消，并回到前一状态。验证码倒计时由 `countdownTask` 和 `identityCountdownTask` 管理，取消流程时停止。`isRequestingIdentityReauthOTP` 和 `isRequestingIdentityTargetOTP` 防止重复发码；注销提交当前没有显式提交锁，依赖 `flowState = .submitting` 和 UI 展示减少重复提交，但仍建议补充幂等键或按钮禁用校验。

## 八、状态模型

| 状态 | 进入条件 | 用户可见结果 | 退出条件 |
| --- | --- | --- | --- |
| `profile == nil` 且 `isLoadingProfile` | 进入账户管理页加载资料 | 资料区域 loading | 加载成功或失败 |
| `identityList == nil` 且 `isLoadingIdentities` | 进入账户管理页加载身份列表 | 身份区域 loading | 加载成功或失败 |
| `flowState.idle` | 默认或注销取消 | 不显示注销浮层 | 点击注销 |
| `flowState.chooseVerification` | 点击注销 | 验证方式选择卡片 | 选择 OTP/Apple 或取消 |
| `flowState.enteringOTP` | 注销 OTP 发码成功 | 输入 6 位验证码 | 验证码满 6 位、返回或重发 |
| `flowState.appleReauth` | 选择 Apple 验证 | 系统 Apple 登录 | 授权成功、失败或取消 |
| `flowState.finalConfirmation` | 注销身份验证完成 | 最终删除确认 | 确认提交或取消 |
| `flowState.submitting` | 提交注销请求 | loading | 成功或失败 |
| `identityFlowState.choosingReauth` | 点击绑定/换绑 | 再验证方式选择 | 选择方式或取消 |
| `identityFlowState.reauthOTP` | 选择手机号/邮箱再验证 | OTP 输入卡片 | 校验成功、失败、返回或重发 |
| `identityFlowState.enteringTarget` | 取得 `verificationTicket` | 新手机号/邮箱输入或 Apple 授权 | 发目标 OTP、Apple 成功或返回 |
| `identityFlowState.targetOTP` | 新目标发码成功 | 目标验证码输入 | 提交、重发或返回编辑 |
| `identityFlowState.submitting` | 提交绑定/换绑 | loading | 成功或失败 |
| `errorMessage` | 可恢复错误 | Alert | 用户关闭 |

## 九、数据与持久化

| 数据 | 所有者 | 存储位置 | 生命周期 | 清理时机 |
| --- | --- | --- | --- | --- |
| `UserSession` | 会话与认证模块 | `AppSessionStore` / 认证仓储快照 | 登录到登出或会话失效 | `SignOutUseCase` 成功后 |
| `AccountProfile` | 账户管理 ViewModel | 内存 `@Published profile` | 账户管理页 ViewModel 生命周期 | 页面销毁或重新加载覆盖 |
| `AccountIdentityList` | 账户管理 ViewModel | 内存 `@Published identityList` | 账户管理页 ViewModel 生命周期 | 绑定/换绑成功后覆盖 |
| `verificationTicket` | 账户管理流程状态 | 内存 `identityFlowState` | 单次绑定/换绑流程 | 完成、取消或失败退出 |
| OTP ID 和验证码 | 账户管理流程状态 | 内存字段和 flow state | 单次验证流程 | 验证成功、取消、失败清空 |
| 设备 ID | Foundation 安全能力 | Keychain，`SupportKeychain.getOrCreateDeviceID()` | 设备安装生命周期 | 当前账户管理模块不清理 |
| 注销选项 | 账户管理 ViewModel | 内存 `AccountDeactivationOptions` | 当前账户管理页生命周期 | 页面销毁或用户修改 |

账户管理模块当前不单独写入 CoreData。账号级 AI、OSS、文件缓存清理不由本模块直接执行，退出登录后由应用生命周期和相关注册表处理。

## 十、错误模型

| 错误类别 | 触发条件 | 是否重试 | 用户反馈 | 清理动作 |
| --- | --- | --- | --- | --- |
| 会话缺失 | `session == nil` | 否，应回到登录态 | 本地化错误 | 不提交后端请求 |
| 不支持的验证方式 | 当前账号无可用邮箱/手机号/Apple 或 API 未返回 OTP | 可换方式 | 失败卡片或 alert | 保留流程或返回选择 |
| OTP 发送失败 | 网络失败、后端拒绝、限流 | 可重试 | Alert 或停留 OTP 步骤 | 清空本次 OTP 输入 |
| OTP 校验失败 | 验证码错误、过期 | 可重试 | Alert | 清空验证码，保留 otpID |
| Apple 凭证无效 | 没有 `identityToken` 或授权失败 | 可重新授权 | 失败卡片 | 回到对应 Apple 状态或前一状态 |
| 注销提交失败 | 后端拒绝或网络失败 | 可重试 | 失败卡片 | 不登出、不清理会话 |
| 登出失败 | `SignOutUseCase` 抛错 | 可重试 | Alert | 保留当前会话 |

## 十一、与其他模块的接口边界

### 本模块负责

- 设置页账户入口后的账号资料和身份管理 UI。
- 账号身份绑定、换绑、再验证和目标验证状态机。
- 注销配置、注销身份验证、注销提交后的本地登出。
- 将后端 DTO 映射为账户管理领域模型。

### 本模块不负责

- 登录注册主流程、游客账号创建和 Token 刷新。
- 账号级 AI、OSS、文件缓存的具体清理实现。
- 服务端注销任务的执行、撤销、进度查询和数据删除策略。
- Push、通知收件箱、首页展示和第二相机能力。

### 上游调用方

- `SettingsView` 提供入口。
- `SupportMainCoordinatorView` 根据当前 `UserSession` 创建并持有 `AccountManagementViewModel`。
- `AppContainer` 负责装配账号管理依赖。

### 下游依赖

- `SignOutUseCase` 和认证仓储负责退出登录。
- `SupportAccountIdentityAPI` 负责身份列表、再验证、绑定和换绑。
- `OTPAPI` 负责手机号和邮箱发码。
- `SupportDeactivationAPI` 负责注销提交。
- `SupportKeychain` 提供设备 ID。

### 输入和输出契约

| 契约 | 输入 | 输出 |
| --- | --- | --- |
| `loadAccountProfile` | `UserSession?` | `AccountProfile` |
| `loadIdentities` | `UserSession?`、`bundleId` | `AccountIdentityList` |
| `requestIdentityVerification` | provider、purpose、bundleId、deviceId | OTP 上下文或 Apple ready |
| `verifyIdentityVerification` | provider、purpose、proof | `VerificationTicket` |
| `bindIdentity` | provider、ticket、proof | 更新后的 `AccountIdentityList` |
| `changeIdentity` | provider、ticket、newTarget、newOtpID、newCode | 更新后的 `AccountIdentityList` |
| `submitDeactivation` | `AccountDeactivationOptions`、verification | `AccountDeactivationSubmission` |

## 十四、当前实现、缺口与演进

### 当前实现

账户管理已经形成完整 Feature 切片，设置页入口、正式账号管理、游客账号升级入口、身份列表、绑定/换绑、注销、退出登录都有真实代码支撑。后端访问集中在 Repository 和 Core Networking API，页面没有直接构造 HTTP 请求。

### 当前缺口

- 注销只实现提交，不展示注销状态查询、取消注销或服务端清理进度。
- 注销提交没有显式客户端幂等键，弱网或重复点击下需要确认后端是否幂等。
- 账户管理专项测试缺失，现有测试主要覆盖网络和认证基础能力。
- `DefaultAccountManagementRepository.requestVerification` 中邮箱注销验证使用 scene `"login"`，而手机号使用 `"account_deactivation"`；这可能是兼容设计，也可能是场景漂移，需要与后端契约确认。
- `AccountManagementViewModel` 同时承担较多流程状态编排，后续如果再增加第三方登录方式，建议拆出身份操作 coordinator 或 reducer。

### 建议演进

- 增加账户管理 ViewModel 状态机测试，优先覆盖高风险注销和换绑。
- 将 OTP scene、purpose 等字符串集中为领域常量，减少前后端契约漂移。
- 为注销提交增加客户端 request id 或后端幂等约定。
- 若后台已支持注销查询/取消，在本模块增加注销状态卡片，并把注销后会话处理与服务端状态明确解耦。

## 十五、整体验收标准

- [ ] 设置页正式账号与游客账号入口分流明确。
- [ ] 账号资料和身份列表加载、空态、失败态可见。
- [ ] 绑定/换绑必须经过已绑定身份再验证，并冻结新目标验证码。
- [ ] 注销必须经过身份验证和最终确认，成功后清理本地会话。
- [ ] 退出登录和注销后的全局状态统一由 `AppSessionStore` 发布。
- [ ] 失败、取消、重试、并发和清理行为有明确代码位置。
- [ ] 关键 API 路径、payload 和鉴权要求可测试。
