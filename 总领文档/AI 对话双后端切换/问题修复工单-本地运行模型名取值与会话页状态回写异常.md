# 问题修复工单-本地运行模型名取值与会话页状态回写异常

## 1. 背景

在 `AI 对话双后端切换` 的 `local` 模式联调过程中，当前日志暴露出两类问题：

1. 本地运行模式下，chat 场景最终消费的模型标识存在“智能体名顶替基础模型名”的风险。
2. 会话页在本地运行模式流式更新期间，出现大量 `AttributeGraph cycle` 与 `Modifying state during view update` 日志，说明 UI 状态回写时机存在异常。

本工单聚焦这两类问题，其中第一类是主问题，必须优先修复。

## 2. 现象

### 2.1 主问题：模型名取值错误

用户明确给出的目标关系是：

```json
{
  "name": "agent-19-15-doubao-seed-2-0-pro-260215",
  "display_name": "Doubao-Seed-2.0-Pro",
  "identity": "agent",
  "baseModelName": "doubao-seed-2-0-pro-260215"
}
```

对于这种 `identity = agent` 的场景行：

- `name` 是智能体行自己的标识。
- `baseModelName` 才是底层模型名。

因此，本地运行时真正发给上游 AI API 的 `"model"`，应该取：

`doubao-seed-2-0-pro-260215`

而不是：

`agent-19-15-doubao-seed-2-0-pro-260215`

### 2.2 当前日志线索

用户提供的日志中，已经出现了本地模式连通和上游 endpoint 暴露：

- `LocalAIChat 已连接（本地运行时）`
- `result=success message=https://ark.cn-beijing.volces.com/api/v3/chat/completions`

同时，当前 iOS 日志里已有本地 chat 选型打印：

- `AIChat 本地 chat 选型 display=... model=... baseModelName=...`

这说明当前链路已经能拿到：

- `row.displayName`
- `row.name`
- `row.baseModelName`

但最终是否把 `baseModelName` 正确映射到请求 `"model"`，仍需要修正。

### 2.3 次问题：会话页状态回写异常

用户提供的日志还出现了大量：

- `=== AttributeGraph: cycle detected through attribute ... ===`
- `Modifying state during view update, this will cause undefined behavior.`

这类日志说明：

- SwiftUI 视图更新期间，有同步状态回写。
- 本地模式流式事件、候选结果集更新、Composer 焦点变化或某些 `@State` / `@Published` 写入时机不对。

它不一定直接造成模型请求错误，但会影响会话页稳定性，必须并入同一轮排查。

## 3. 代码事实

### 3.1 本地请求最终确实消费 `AIResolvedConfig.model`

[LocalAIChatStreamClient.swift](/Users/hua/Documents/project/DeepTutor/SupportClient/SupportClient/Projects/Features/AIChat/Infrastructure/LocalAIChatStreamClient.swift)

当前请求体直接发送：

```swift

```

这意味着只要 `AIResolvedConfig.model` 被解析成 `agent-...`，最终发给上游的也是错值。

### 3.2 `AIResolvedConfig.model` 来自 `AIScenarioConfig.model`

[AIConfigModels.swift](/Users/hua/Documents/project/DeepTutor/SupportClient/SupportClient/Projects/Core/AI/AIConfigModels.swift)

当前链路是：

```text
AIScenarioRemoteModelRow
  -> asScenarioConfig()
  -> AIScenarioConfig.model
  -> toResolvedConfig()
  -> AIResolvedConfig.model
  -> LocalAIChatStreamClient 请求体 "model"
```

### 3.3 当前 `AIScenarioRemoteModelRow.asScenarioConfig()` 直接使用 `name`

[AIConfigModels.swift](/Users/hua/Documents/project/DeepTutor/SupportClient/SupportClient/Projects/Core/AI/AIConfigModels.swift)

当前实现：

```swift

    AIScenarioConfig(

        model: name,
        apiKey: apiKey,
        temperature: temperature,
        maxTokens: maxTokens
    )

```

这对普通 `identity = model` 行是合理的，但对：

- `identity = agent`
- `baseModelName != nil`

的行不成立。

### 3.4 当前场景行解析不会自动把 agent 行降解为 base model

[AIConfigModels.swift](/Users/hua/Documents/project/DeepTutor/SupportClient/SupportClient/Projects/Core/AI/AIConfigModels.swift)

当前 `resolveRow(...)` 与 `resolveScenarioRow(...)` 的职责是“选中哪一行”，不是“把 agent 行转换成底层模型名”。

所以只要选中的是 `agent` 行，后续 `asScenarioConfig()` 就会错误地把 `name` 吃下去。

### 3.5 当前 agent 数据本身已经把 `baseModelName` 正确保存到了模型层

[AISettingsMutationService.swift](/Users/hua/Documents/project/DeepTutor/SupportClient/SupportClient/Projects/Features/AISettings/Application/AISettingsMutationService.swift)

当前新建本地智能体时：

```swift

```

这说明数据本身不是完全丢失，而是消费链最后一步取错了字段。

### 3.6 本地运行时已经真实连到执行器，不只是 UI 占位

[LocalAIChatRuntime.swift](/Users/hua/Documents/project/DeepTutor/SupportClient/SupportClient/Projects/Features/AIChat/Infrastructure/LocalAIChatRuntime.swift)

当前 `LocalAIChatRuntime.runTurn(...)` 会：

1. `aiConfigCenter.resolve(for: .chat)`
2. 拿到 `AIResolvedConfig`
3. 在 endpoint 非 `local` 时直接调用 `streamFromAPI(...)`

这说明模型名错误会真正影响上游请求，而不是只影响展示。

## 4. 问题判断

## 4.1 主问题结论

当前主问题是：

> `identity = agent` 的场景行在转换成 `AIScenarioConfig` 时，错误地使用了 `name`，而不是在可用时优先使用 `baseModelName` 作为真实底层模型名。

因此：

- 展示层可继续显示 `display_name = Doubao-Seed-2.0-Pro`
- 领域层可继续保留 `name = agent-19-15-doubao-seed-2-0-pro-260215`
- 但请求层必须把 `"model"` 发成 `baseModelName = doubao-seed-2-0-pro-260215`

### 4.2 次问题结论

当前次问题是：

> 本地模式流式过程中，候选结果集回写、状态机更新、Composer 焦点变化或视图层绑定存在“视图更新期间同步改状态”的行为，导致 `AttributeGraph cycle` 和 `Modifying state during view update`。

它和主问题属于不同层级，但同一轮联调里都要记录。

## 5. 修复要求

### 5.1 主问题修复要求

必须满足：

1. `identity = agent` 且 `baseModelName` 非空时，请求模型名取 `baseModelName`。
2. `identity = model` 时，仍取 `name`。
3. UI 展示层仍显示 `displayName`，不因请求模型名修复而改变。
4. 日志里要同时打印：
   - 展示名
   - 行名 `name`
   - 实际请求模型名
   - `baseModelName`

### 5.2 推荐修复点

优先考虑在以下位置之一修复：

1. `AIScenarioRemoteModelRow.asScenarioConfig()`
2. `AIScenarioRemoteBundle.resolveConfig(...)`
3. `ScenarioPolicyResolver.resolve(...)` 之后、进入 `AIResolvedConfig` 之前

推荐优先级：

- 优先在 `AIScenarioRemoteModelRow.asScenarioConfig()` 做统一修复。

原因：

- 问题根因就在“行 -> 配置”的转换处。
- 能同时覆盖 `AIConfigCenter.resolve(for:)` 的所有消费者。
- 不需要在 `LocalAIChatRuntime` 或 `LocalAIChatStreamClient` 做特判。

### 5.3 次问题修复要求

需要补一轮排查：

1. 哪个视图或回调在 `body` 更新期间同步写状态。
2. 候选结果集刷新是否触发了同步 `@State` / `@Published` 写入。
3. `AIChatViewModel`、Composer 焦点、session log 面板、候选结果接收器是否存在环状驱动。

当前工单先记录为同轮问题，不要求和主问题完全一起修完，但至少要一起定位。

4. 最后回归：
