# 应用启动链路需求

## 一、模块目标

应用启动链路负责把 iOS 进程启动后的基础依赖、网络可用性、会话状态、设备登记、账号级运行时和首屏路由串成一条可恢复的流程。它的业务目标是确保用户在冷启动、未登录、已登录恢复、账号切换和服务端鉴权失效时，都只经过一套根生命周期决策。

当前实现范围：

- `SupportClientApp` 创建 `AppContainer.live()`，注入 Core Data 与根内容依赖。
- `AppContainer` 作为 Composition Root 装配网络、认证、通知、AI、OSS、文件和 OCR 等长生命周期对象。
- `AppCoordinatorView` 先等待网络路径评估，再触发 `AppLifecycleCoordinator.bootstrapLaunchAfterNetworkEvaluation(...)`。
- `AppSessionStore` 负责 `.loading`、`.signedOut`、`.signedIn(UserSession)` 三态。
- `AppLifecycleCoordinator` 负责冷启动会话恢复、未登录清理、设备登记、账号级引导和鉴权失效回收。
- `SignedInSessionPreparationRegistry` 串行化已登录账号准备，避免多个入口重复启动账号级 bootstrap。

本模块不负责具体登录表单、业务页面内容、网络引擎内部重试策略、AI 设置编辑、OSS 上传和 OCR 业务编排；这些由对应功能模块负责。

## 三、应用进程入口与依赖装配

### 需求说明

应用启动后必须先构建全局依赖图，再把根内容依赖注入 SwiftUI 首屏。依赖装配需要集中在单一入口，避免页面自行创建网络、认证、AI、OSS 或文件服务。

### 基础要求与业务规则

- `SupportClientApp` 只负责创建容器、挂载 `ContentView` 和注入 `managedObjectContext`。
- `AppContainer.live(environment:)` 负责配置日志、创建 `SupportBackend`、Core Data、认证、通知、AI、文件、OSS、OCR 和账号运行时。
- `AppSessionStore` 先构造，再通过 `bindRestoreSessionUseCase` 注入 `RestoreSessionUseCase`，解决认证仓储和会话状态之间的循环依赖。
- `RouteCoordinator` 必须在容器阶段绑定 `AppLifecycleCoordinator`，系统鉴权失效才能回到生命周期统一入口。
- 装配过程不得依赖页面出现次数；SwiftUI View 重建不能重复创建全局运行时。

### 验收标准

- 冷启动进入 `ContentView` 时，`AppCoordinatorView` 能拿到同一组 `AppCoordinatorDependencies`。
- `SupportBackend`、`AppSessionStore`、`AppLifecycleCoordinator`、`RouteCoordinator` 和账号级服务只由 `AppContainer` 统一创建。
- `restoreSessionUseCase` 未绑定时，`AppSessionStore.restoreIfNeeded()` 会进入 `.signedOut` 并记录错误，不会卡在 `.loading`。
- 日志中可以看到 AppContainer、各 Assembly 和生命周期协调器的初始化节点。

### 技术细节与设计代码位置

- 入口：`SupportClient/Projects/App/Sources/SupportClientApp.swift`。
- 根内容：`SupportClient/Projects/App/Sources/ContentView.swift`。
- 组合根：`SupportClient/Projects/App/Sources/App/AppContainer.swift`。
- Assembly 产物：`SupportClient/Projects/App/Sources/App/Architecture/AssemblyProducts.swift`。
- 会话状态：`SupportClient/Projects/App/Sources/App/AppSessionStore.swift`。
- 路由绑定：`SupportClient/Projects/App/Sources/App/Architecture/RouteCoordinator.swift`。

## 四、网络门控与冷启动触发

### 需求说明

启动链路必须先等待设备网络路径完成首次评估，再决定是否执行会话恢复、应用级 bootstrap 和设备登记。网络不可用时，应留在启动页并展示网络门禁，不提前触发一批必然失败的远端请求。

### 基础要求与业务规则

- `AppCoordinatorView` 持有 `NetworkPathMonitor`，启动后调用 `networkMonitor.start()`。
- `.loading` 状态下，`AppLaunchScreenView` 的 `.task(id:)` 使用网络评估结果作为触发条件。
- `bootstrapLaunchAfterNetworkEvaluation(networkHasEvaluated:networkSatisfied:)` 只有在已评估且可用时继续。
- 网络已评估但不可用时，显示 `NetworkGateView`，并等待网络恢复后重新触发。
- 冷启动 bootstrap 由 `AppLifecycleCoordinator` 持有，避免业务页面生命周期取消设备登记或账号准备任务。

### 验收标准

- 网络未评估时不会执行会话恢复。
- 网络不可用时不会调用 `AppSessionStore.restoreIfNeeded()` 或 `DeviceRegistrationCoordinator`。
- 网络恢复后启动链路能继续执行，不需要用户手动重启 App。
- `NetworkGateView` 只作为覆盖层，不替代会话状态机。

### 技术细节与设计代码位置

- 网络监控：`SupportClient/Foundation/NetworkPathMonitor.swift`。
- 启动页与网络门控：`SupportClient/Projects/App/Sources/App/AppCoordinatorView.swift`。
- 网络不可用覆盖层：`SupportClient/Projects/App/Sources/App/Presentation/NetworkGateView.swift`。
- 生命周期入口：`SupportClient/Projects/App/Sources/App/Architecture/AppLifecycleCoordinator.swift`。

## 五、会话恢复与根状态分流

### 需求说明

冷启动时，应用需要从本地会话快照和 Token 中恢复用户身份，并尽可能拉取服务端最新 `UserSession`。恢复结果决定进入登录页、主框架准备页或继续停留启动页。

### 基础要求与业务规则

- `AppSessionStore.state` 初始为 `.loading`。
- `restoreIfNeeded()` 冷启动只执行一次，重复触发直接跳过。
- `RestoreSessionUseCase` 委托 `AuthRepository.restoreSession()`。
- `DefaultAuthRepository.restoreSession()` 先读取 `SessionSnapshotStore`，再预热 Token，随后尝试调用 `backend.auth.fetchCurrentSession()` 获取最新会话。
- Token 明确失效时，必须清理 token、设备认证缓存和会话快照，并发布鉴权失效事件。
- Token 暂时不可用或服务端最新会话拉取失败但不属于明确鉴权失效时，可以降级使用本地 `cachedSession`。
- `AppSessionStore` 在恢复后会校验内存 `UserSession` 与 `SessionSnapshotStore` 是否一致，并记录诊断日志。

### 验收标准

- 无本地快照时进入 `.signedOut`。
- 本地快照有效且 Token 可用时进入 `.signedIn(UserSession)`。
- Token 明确失效时清理本地会话并回到登录态。
- 远端会话刷新失败但可降级时，仍可用本地快照进入后续账号准备。
- UI 分流只根据 `AppLifecycleCoordinator.sessionState` 和 `preparedAccountID` 决定，不由业务页面自行判断 token。

### 技术细节与设计代码位置

- 状态容器：`SupportClient/Projects/App/Sources/App/AppSessionStore.swift`。
- 恢复用例：`SupportClient/Projects/Features/Auth/Application/RestoreSessionUseCase.swift`。
- 认证仓储：`SupportClient/Projects/Features/Auth/Infrastructure/DefaultAuthRepository.swift`。
- 快照存储：`SupportClient/Projects/Features/Auth/Infrastructure/SessionSnapshotStore.swift`。
- 根分流视图：`SupportClient/Projects/App/Sources/App/AppCoordinatorView.swift`。
- 相关测试：`SupportClientTests/Networking/SupportAuthSessionPersistenceTests.swift`。

## 六、未登录与游客设备登记

### 需求说明

当冷启动恢复不到有效会话，或者用户退出登录后，应用需要进入未登录运行时，清理账号级内存状态，并以游客身份登记设备，保证服务端仍能识别安装级设备。

### 基础要求与业务规则

- `.signedOut` 时展示 `SignedOutAuthCoordinatorView` 和 `LoginView`。
- `SignedOutAuthCoordinatorView.task` 调用 `lifecycle.handleSignedOutTask()`。
- `handleSignedOutTask()` 使用 `didRunSignedOutTask` 防止同一未登录态重复清理。
- 未登录清理包括重置已登录准备状态、清空 `preparedAccountID`、重置 `AppBootstrapper`、切换 `AccountSessionRuntime` 到 guest、重置并执行游客设备登记。
- 游客设备登记不携带认证 token，`DeviceRegistrationRequest` 仍包含安装设备 ID、系统版本、设备型号、地区语言、App 版本和模拟器标记等设备信息。

### 验收标准

- 首次进入未登录态后，会执行一次账号运行时清理和游客设备登记。
- 重复 SwiftUI 渲染不会重复跑未登录清理。
- 游客设备登记失败不会阻塞登录页展示，但必须记录失败日志。
- 登出后账号级缓存、OSS 凭证和 AI 运行时缓存回到 guest 或被清理。

### 技术细节与设计代码位置

- 未登录入口：`SupportClient/Projects/App/Sources/App/AppCoordinatorView.swift`。
- 生命周期处理：`SupportClient/Projects/App/Sources/App/Architecture/AppLifecycleCoordinator.swift`。
- 设备登记：`SupportClient/Projects/App/Sources/App/DeviceRegistrationCoordinator.swift`。
- 设备登记 Android 对齐与迁移细化：[`设备登记需求.md`](./设备登记需求.md)。
- 账号运行时：`SupportClient/Projects/App/Sources/App/Architecture/AccountSessionRuntime.swift`。
- 存储清理注册表：`SupportClient/Projects/App/Sources/App/Architecture/StorageRegistry.swift`。
- 登录 UI 与 ViewModel 创建：`SupportClient/Projects/App/Sources/App/AppContainer.swift`、`SupportClient/Projects/Features/Auth/Presentation/LoginViewModel.swift`。

## 七、已登录账号准备与主框架放行

### 需求说明

恢复或登录成功后，应用不能立即展示主框架；必须先完成账号运行时切换、已登录设备登记、AI 配置预热、远端 AI 配置刷新和 OSS STS 预取。只有当前账号被标记为 prepared 后，主 Tab 才能展示。

### 基础要求与业务规则

- 已登录状态进入 `AppLifecycleCoordinator.enqueueSignedInPreparation(...)`。
- 冷启动期间由 `bootstrapLaunchAfterNetworkEvaluation` 直接调度账号准备；非冷启动的 `.signedOut -> .signedIn` 或账号 ID 变化由 `handleSessionStateTransition` 调度。
- `SignedInSessionPreparationRegistry` 对同一个 accountID 合并并发准备任务，准备成功后记录 `.prepared(accountID)`。
- `AccountSessionRuntime.activateUser(accountID:)` 先执行账号切换清理，再重置 AI 运行时缓存、路由图和会话级 ViewModel 缓存。
- `DeviceRegistrationCoordinator.requestRegisterWithLimitedRetry(...)` 对已登录设备登记最多尝试 3 次，退避为 0ms、300ms、600ms。
- 设备登记结果为 `submitted` 或 `skippedSameLaunchSubmission` 时才允许进入账号级 bootstrap。
- `AppBootstrapper.bootstrapAccountIfNeeded(accountID:)` 按顺序执行 AI prewarm、remote AI config refresh 和 OSS STS prefetch，并按 accountID 去重。
- `AppCoordinatorView` 只有在 `preparedAccountID == session.accountID` 时展示 `SupportMainCoordinatorView`，否则继续展示启动页。

### 验收标准

- 已登录冷启动不会在账号准备完成前进入主 Tab。
- 同一个账号的账号级引导不会在同一启动周期重复执行。
- 设备登记鉴权失效或可重试失败耗尽时，会中止后续 AI/OSS bootstrap。
- 账号切换后，旧账号 ViewModel 缓存和运行时凭证不会继续被新账号复用。
- 主框架里首页、第二相机和设置 Tab 均使用同一份 `UserSession` 与容器依赖。

### 技术细节与设计代码位置

- 生命周期编排：`SupportClient/Projects/App/Sources/App/Architecture/AppLifecycleCoordinator.swift`。
- 准备任务注册表：`SupportClient/Projects/App/Sources/App/Architecture/SignedInSessionPreparationRegistry.swift`。
- 账号运行时：`SupportClient/Projects/App/Sources/App/Architecture/AccountSessionRuntime.swift`。
- 账号级 bootstrap：`SupportClient/Projects/App/Sources/App/AppBootstrapper.swift`。
- 设备登记结果与重试策略：`SupportClient/Projects/App/Sources/App/DeviceRegistrationRequestOutcome.swift`。
- 设备登记执行：`SupportClient/Projects/App/Sources/App/DeviceRegistrationCoordinator.swift`。
- 主 Tab 放行：`SupportClient/Projects/App/Sources/App/AppCoordinatorView.swift`。
- AI 配置中心：`SupportClient/Projects/Core/AI/AIConfigCenter.swift`。
- OSS 运行时配置：`SupportClient/Core/FileStorage/FileTransferService.swift`、`SupportClient/Projects/App/Sources/App/Architecture/AssemblyProducts.swift`。

## 八、服务端鉴权失效与启动链路中止

### 需求说明

启动、设备登记、Token 刷新或任意网络请求中，一旦服务端明确判定会话失效，应用必须通过统一事件回到未登录态，并中止账号级启动链路，避免继续用失效 token 预热 AI、OSS 或账号缓存。

### 基础要求与业务规则

- 网络层通过 `SupportAuthSessionInvalidation.postIfNeeded(...)` 发布服务端鉴权失效事件。
- `RouteCoordinator.startSystemEventRouting()` 只启动一次系统事件监听，并把事件转交 `AppLifecycleCoordinator.handleServerAuthInvalidationIfNeeded(...)`。
- 鉴权失效处理中使用 `isHandlingServerAuthInvalidation` 防重入。
- 处理流程先暂停设备登记提交、重置账号准备、清空 `preparedAccountID`，再调用 `sessionStore.signOut()` 清理 token 和快照。
- 清理后重置 `AppBootstrapper`、切换 guest 运行时、重置 `DeviceRegistrationCoordinator`。
- `runSignedInPreparation` 在设备登记后和账号 bootstrap 后都会再次确认当前仍为 signedIn 且没有鉴权失效，再决定是否标记 prepared。

### 验收标准

- 401、401xx 业务码或明确 token 失效消息会触发统一失效事件。
- 403 不会被误判为会话失效。
- 鉴权失效后不会继续执行账号级 AI/OSS bootstrap。
- UI 最终回到未登录态，主 Tab 不再展示旧账号数据。
- 失效处理重复触发时不会并发清理同一套状态。

### 技术细节与设计代码位置

- 失效判定与通知：`SupportClient/Projects/Core/Networking/SupportNetworkModels.swift`。
- 网络触发点：`SupportClient/Projects/Core/Networking/SupportNetworkEngine.swift`、`SupportClient/Projects/Core/Networking/AuthTokenProvider.swift`、`SupportClient/Projects/Core/Networking/API/Common/SupportAPIResponseDecoder.swift`。
- 系统事件路由：`SupportClient/Projects/App/Sources/App/Architecture/RouteCoordinator.swift`。
- 生命周期回收：`SupportClient/Projects/App/Sources/App/Architecture/AppLifecycleCoordinator.swift`。
- 设备登记中止：`SupportClient/Projects/App/Sources/App/DeviceRegistrationCoordinator.swift`。
- 相关测试：`SupportClientTests/Networking/SupportAuthSessionInvalidationTests.swift`、`SupportClientTests/Networking/SupportNetworkEngineAuthTests.swift`。

## 九、整体业务流程

```text
SupportClientApp.@main
  ↓
AppContainer.live() 装配 Backend、CoreData、Auth、Notification、AI、OSS、OCR、Lifecycle
  ↓
ContentView 启动系统事件路由与通知刷新
  ↓
AppCoordinatorView 启动 NetworkPathMonitor
  ↓
网络路径完成评估
  ↓
AppLifecycleCoordinator.bootstrapLaunchAfterNetworkEvaluation
  ↓
AppSessionStore.restoreIfNeeded
  ↓
DefaultAuthRepository.restoreSession
  ↓
根据 AppSessionState 分流
  ├─ signedOut：清理账号运行时 -> 游客设备登记 -> 登录页
  └─ signedIn：账号运行时切换 -> 已登录设备登记 -> AI/OSS 账号引导 -> preparedAccountID
        ↓
      SupportMainCoordinatorView 主 Tab
```

### 成功路径

1. 进程启动后 `SupportClientApp` 创建容器和根视图。
2. `ContentView` 启动鉴权失效系统事件路由。
3. `NetworkPathMonitor` 完成路径评估且网络可用。
4. `AppSessionStore.restoreIfNeeded()` 读取本地快照和 Token。
5. 无会话时进入未登录态并登记游客设备。
6. 有会话时进入已登录准备，先切换账号运行时，再登记已登录设备。
7. 设备登记允许继续后，`AppBootstrapper` 执行 AI prewarm、远端 AI 配置刷新和 OSS STS 预取。
8. `preparedAccountID` 与当前 session accountID 一致后展示主 Tab。

### 失败、重试和恢复

| 场景 | 当前处理 | 恢复方式 |
| --- | --- | --- |
| 网络未评估 | 不执行启动恢复 | 等待路径评估完成 |
| 网络不可用 | 停留启动页并显示 `NetworkGateView` | 网络恢复后重触发 |
| `restoreSessionUseCase` 未绑定 | 记录错误并进入 `.signedOut` | 重新登录 |
| 无本地快照 | 进入 `.signedOut` | 游客登记后展示登录页 |
| Token 暂时刷新不可用 | 降级使用本地快照 | 后续请求或刷新再恢复 |
| Token 明确失效 | 清 token、设备缓存和快照，发布失效事件 | 回登录态重新认证 |
| 已登录设备登记可重试失败 | 最多 3 次退避重试，耗尽后中止账号 bootstrap | 用户仍停留启动页；当前缺口是缺少面向用户的恢复按钮 |
| 已登录设备登记鉴权失效 | 暂停提交并返回 `authSessionInvalidated` | 生命周期清理并回登录态 |
| 账号 bootstrap 后发生鉴权失效 | 不标记 prepared，回滚 preparing | 回登录态 |

### 取消、并发和幂等

- `AppSessionStore.didRestore` 保证冷启动恢复只执行一次。
- `AppBootstrapper.launched` 保证应用级 bootstrap 只执行一次；`bootstrappedAccountIDs` 保证账号级 bootstrap 按账号去重。
- `DeviceRegistrationCoordinator.lastRegisteredKey` 避免同一冷启动周期重复提交同一设备登记；`.signedInForeground` 允许显式前台重新登记。
- `SignedInSessionPreparationRegistry` 合并同一账号的 in-flight 准备任务，并在失败时 `rollbackPreparingIfNeeded`。
- `RouteCoordinator.didStartSystemRouting` 避免重复订阅鉴权失效通知。
- 鉴权失效处理中 `isHandlingServerAuthInvalidation` 防止重复清理。

## 十、状态模型

| 状态 | 进入条件 | 用户可见结果 | 退出条件 |
| --- | --- | --- | --- |
| `.loading` | App 初始启动或已登录账号未准备完成 | 启动页；网络不可用时叠加网络门禁 | 网络可用后恢复到 signedOut 或 signedIn；已登录准备完成后进入主 Tab |
| `.signedOut` | 无快照、恢复失败、登出或鉴权失效 | 登录页 | 登录成功后 `setAuthenticated` |
| `.signedIn(UserSession)` 未准备 | 会话恢复或登录成功 | 启动页，不展示主 Tab | `preparedAccountID == session.accountID` |
| `.signedIn(UserSession)` 已准备 | 账号运行时、设备登记和账号 bootstrap 完成 | 主 Tab | 登出、账号切换或服务端鉴权失效 |
| `SignedInPreparationState.preparing` | 同一账号准备任务正在执行 | 启动页 | 标记 prepared 或回滚 idle |
| `SignedInPreparationState.prepared` | 指定 accountID 准备完成 | 主 Tab 可放行 | 登出、账号切换、鉴权失效或重置 |
| 网络不可用 | `NetworkPathMonitor` 已评估且不满足 | 网络门禁覆盖层 | 网络恢复 |
| 鉴权失效处理中 | 收到统一失效事件且当前不是 signedOut | 可能短暂停留启动页或登录页切换 | 清理完成后 signedOut |

## 十一、数据与持久化

| 数据 | 所有者 | 存储位置 | 生命周期 | 清理时机 |
| --- | --- | --- | --- | --- |
| `AppSessionState` | `AppSessionStore` | 内存，`@Published` | App 进程生命周期 | 登出、恢复结果变化、登录成功 |
| `UserSession` 快照 | `SessionSnapshotStore` | `UserDefaults`，键 `support.session.snapshot.v1` | 跨启动保留 | 登出、Token 明确失效、服务端会话失效 |
| 认证 Token | `AuthTokenProvider` / `SparkKeychain` | Keychain | 跨启动保留 | `sessionStore.signOut()`、认证仓储判定明确失效 |
| 安装设备 ID | `SparkKeychain` / `SupportSystemInfo` | Keychain | 安装生命周期 | 当前实现未在启动链路中清理 |
| 设备登记去重键 | `DeviceRegistrationCoordinator` | 内存 | 单次启动/引导周期 | `reset()`、鉴权失效、未登录处理 |
| 已启动标记 | `AppBootstrapper.launched` | actor 内存 | 单次启动周期 | `resetLaunchBootstrap()` |
| 已 bootstrap 账号集合 | `AppBootstrapper.bootstrappedAccountIDs` | actor 内存 | 单次启动周期 | `resetLaunchBootstrap()` |
| `preparedAccountID` | `AppLifecycleCoordinator` / `SignedInSessionPreparationRegistry` | 内存 | 当前会话 | 登出、账号切换、鉴权失效、准备失败回滚 |
| AI 运行时缓存 | `AIConfigCenter` | 内存 / Core Data 配合 | 账号级 | `AccountSessionRuntime.activateUser/activateGuest` |
| OSS STS 与运行时凭证 | `SupportOSSConfigurationStore` / `FileTransferService` | 内存 | 账号级 | 账号切换或退出登录 |
| 文件缓存账号上下文 | `FileCacheManager` | 文件系统 + 内存上下文 | 账号级 | `StorageRegistry.prepareForAccountSwitch/SignOut` |

## 十二、错误模型

| 错误类别 | 触发条件 | 是否重试 | 用户反馈 | 清理动作 |
| --- | --- | --- | --- | --- |
| 网络未评估 | App 初始启动，路径状态未知 | 不重试请求，只等待评估 | 启动页 | 无 |
| 网络不可用 | `NetworkPathMonitor.isSatisfied == false` | 等待网络恢复 | 网络门禁覆盖层 | 不执行会话恢复 |
| 快照缺失 | `SessionSnapshotStore.load()` 返回 nil | 不重试 | 登录页 | 游客运行时与游客设备登记 |
| 快照解码失败 | UserDefaults 数据无法解码 | 不重试 | 登录页 | 调用方视为无会话；当前实现记录错误但不自动删除损坏数据 |
| Token 暂不可用 | `refreshTemporarilyUnavailable` 或未知预热错误 | 后续请求再尝试 | 当前使用缓存会话继续 | 不清理快照 |
| Token 明确失效 | missing tokens、invalid refresh、refresh failed | 不重试 | 回登录态 | 清 token、设备认证缓存、快照 |
| 会话刷新失败但非失效 | `fetchCurrentSession()` 普通失败 | 不阻塞启动 | 继续使用缓存会话 | 保留快照 |
| 已登录设备登记取消 | Task 取消或网络取消 | 作为可重试失败 | 当前停留启动页 | 不进入账号 bootstrap |
| 已登录设备登记重试耗尽 | 3 次失败 | 已完成有限重试 | 当前缺口：缺少可见错误与重试入口 | 回滚 preparing |
| 服务端鉴权失效 | 401、401xx 或明确 token 失效消息 | 不重试当前链路 | 回登录态 | 暂停登记、signOut、guest 运行时、重置 bootstrap |

## 十三、与其他模块的接口边界

### 本模块负责

- App 入口装配和根依赖注入。
- 网络评估后的冷启动恢复触发。
- 根会话状态机和首屏分流。
- 未登录、已登录、登出和服务端鉴权失效的生命周期编排。
- 已登录账号准备的串行化、去重、中止和主框架放行。
- 账号级运行时切换时触发缓存和凭证清理。

### 本模块不负责

- 登录表单交互、Apple 登录和验证码登录细节。
- 网络请求模型、Token 刷新算法和 ETag 缓存细节。
- AI 设置具体读写、模型选择和 UI 展示。
- OSS 上传、文件元数据管理和 OCR 识别业务。
- 通知中心的具体业务消息渲染。

### 上游调用方

- iOS 系统启动 `SupportClientApp`。
- SwiftUI 生命周期 `.task` 和 `.onOpenURL`。
- 网络层发布的 `SupportAuthSessionInvalidation` 通知。
- 登录成功后调用 `AppSessionStore.setAuthenticated(...)` 的认证流程。
- 登出按钮或账号管理流程调用认证仓储登出。

### 下游依赖

- `SupportBackend` 与各业务 API。
- `AuthRepository`、`RestoreSessionUseCase`、`SessionSnapshotStore` 和 `AuthTokenProvider`。
- `DeviceRegistrationCoordinator` 和 `SupportSystemInfo`。
- `AccountSessionRuntime`、`StorageRegistry`、`FileCacheManager`、`FileTransferService`。
- `AIConfigCenter`、`SupportOSSConfigurationStore`。
- `RouteCoordinator`、`NotificationDeliveryCoordinator` 和 `NotificationHostView`。

### 输入和输出契约

| 契约 | 输入 | 输出 |
| --- | --- | --- |
| 冷启动恢复 | 网络是否已评估、是否可用 | `AppSessionState` 与可能的账号准备任务 |
| 会话恢复 | 本地快照、Keychain token、远端 session API | `UserSession?` |
| 设备登记 | 设备信息、可选 userID/accountID、authenticated 标记、reason | `DeviceRegistrationRequestOutcome` 或游客路径日志 |
| 已登录准备 | `UserSession`、`DeviceRegistrationReason` | `preparedAccountID` 或准备回滚 |
| 鉴权失效处理 | status、backendCode、message、source | 清理后的 `.signedOut` |

## 十六、当前实现、缺口与演进

### 当前实现

- 当前实现已经把 App 入口、依赖装配、网络门控、会话恢复、未登录清理、已登录账号准备和鉴权失效处理集中到 App 层。
- 当前实现已经避免账号级准备依赖业务页面 `.task`，主 Tab 只有在 `preparedAccountID` 匹配当前账号后才放行。
- 当前实现已经为设备登记提供明确 outcome，并在鉴权失效或重试失败时中止后续账号级 bootstrap。
- 当前实现已经通过 `StorageRegistry` 和 `AccountSessionRuntime` 处理账号切换与登出时的缓存归属。
- 当前实现已经有会话持久化、鉴权失效判定和网络鉴权相关测试。

### 当前缺口

- 当前未发现 App 生命周期协调器、设备登记协调器、账号准备注册表和 AppBootstrapper 的专门单元测试。
- 当前已登录设备登记重试耗尽后会中止账号级 bootstrap，但 UI 仍停留启动页，未发现面向用户的错误页或重试按钮。
- `SessionSnapshotStore` 解码失败时返回 nil 并记录错误，但当前实现未自动删除损坏快照。
- `DeviceRegistrationCoordinator.registerGuestDevice` 不返回 outcome，游客登记失败只落日志，调用方无法做策略分支。
- 前台恢复路径枚举存在 `.signedInForeground`，但当前文档审计范围内未确认有前台生命周期事件接入。

### 建议演进

- 为启动链路增加纯 Swift 单元测试替身，优先覆盖状态迁移和中止条件，而不是依赖 UI 测试发现问题。
- 为已登录设备登记重试耗尽增加启动错误态或轻量重试入口，避免用户长期停留在启动页。
- 对 `SessionSnapshotStore` 解码失败增加清理策略，并在日志中区分“无快照”和“损坏快照”。
- 让游客设备登记也返回明确 outcome，便于未来做离线重试、诊断提示或埋点。
- 若后续接入 scene phase 前台恢复，应把 `.signedInForeground` 设备登记入口接到同一生命周期协调器，而不是页面自行触发。

## 十七、整体验收标准

- [ ] 冷启动时网络未评估不会提前恢复会话。
- [ ] 网络不可用时展示网络门禁，并在恢复后继续启动链路。
- [ ] 无本地会话时进入登录页并执行游客运行时和游客设备登记。
- [ ] 有本地会话时先完成账号运行时切换、已登录设备登记、AI/OSS bootstrap，再展示主 Tab。
- [ ] Token 明确失效时清理 token、快照、设备认证缓存和账号级运行时。
- [ ] 已登录设备登记鉴权失效或重试耗尽时不会继续执行账号级 bootstrap。
- [ ] 同一账号准备任务并发触发时只执行一次。
- [ ] 登出、账号切换和鉴权失效后不会复用旧账号 ViewModel、OSS 凭证或文件缓存上下文。
- [ ] 关键路径都有可定位日志，能够区分网络门控、会话恢复、设备登记、AI prewarm、remote config、OSS STS 和主 Tab 放行。
- [ ] 关键代码位置、测试缺口和建议演进均可从当前文件系统验证。
