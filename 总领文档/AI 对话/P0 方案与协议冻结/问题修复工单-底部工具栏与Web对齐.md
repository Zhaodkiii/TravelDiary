# 问题修复工单｜底部工具栏与 Web 对齐

## 1. 工单目标

对齐 iOS 端 AI 对话页底部工具栏与 Web 端的展示和交互方式，重点统一：

- 工具栏的位置
- 工具栏的高度和留白
- 操作按钮的层级
- 底部操作区与问答卡片的衔接
- 提交 / 跳过 / 继续 的行为反馈

当前问题不是单纯“按钮样式不同”，而是底部工具栏在 iOS 和 Web 上承担的业务语义不一致。

---

## 2. 问题描述

iOS 当前底部工具栏的表现，和 Web 相比存在以下常见差异：

- 工具栏更窄，视觉存在感偏弱
- 底部按钮与卡片之间的关系不够明确
- 安全区、底部间距、阴影和边框层级不一致
- 提交动作的反馈不够强
- 工具栏没有很好地把“继续作答”这个业务动作表达出来

用户在 iOS 上会更容易把它理解为一个普通输入栏，而不是一个结构化问答任务的底部操作区。

---

## 3. 与 Web 的差异

### 3.1 Web 的表现

Web 端底部区域通常更像一个完整的操作面板：

- 底部区块边界更完整
- 按钮更清晰
- 输入和提交形成闭环
- 与上方问答卡形成明确的主次关系

### 3.2 iOS 的表现

iOS 端当前更容易出现：

- 底部工具栏被压缩
- 操作密度偏高
- 按钮层级不明显
- 视觉上像“附属控件”，不是“业务主操作区”

---

## 4. 需要重点对齐的内容

### 4.1 位置与结构

底部工具栏应当与上方问答卡形成统一的业务闭环，而不是彼此割裂。

### 4.2 留白与安全区

需要确认：

- 是否贴近底部安全区
- 是否保留足够的下边距
- 是否在键盘弹出时保持稳定

### 4.3 操作按钮

需要统一：

- 提交按钮的大小
- 按钮的可点击区域
- 禁用态和可用态的反馈
- 按钮是否足够像 Web 的主操作按钮

### 4.4 与问答卡的关系

底部工具栏不应和问答卡互相抢层级。

建议明确：

- 问题内容在上
- 输入/选择在中
- 提交操作在底部

---

## 5. 可能根因

### 5.1 组件拆分问题

iOS 端可能把底部工具栏当作局部 UI 控件实现，而不是问答卡的一部分。

### 5.2 状态流转问题

底部工具栏可能没有完整接入：

- `waiting_for_input`
- `ready_to_submit`
- `submitted`
- `continue_to_next_turn`

### 5.3 视觉规范缺失

底部区域缺少统一的：

- 间距规则
- 按钮主次规则
- 边框和阴影规则
- 安全区规则

---

## 6. 建议的修复方向

### 6.1 结构修复

把底部工具栏定义为“问答任务的操作区”，不是普通输入栏。

### 6.2 视觉修复

- 增加底部操作区的完整性
- 提升按钮识别度
- 让输入区和提交区形成稳定布局
- 让底部区域和 Web 端视觉语义一致

### 6.3 交互修复

- 点击提交后要明确进入下一步
- 禁用态、加载态、成功态都要可见
- 如果需要继续回答，底部区域必须能承接状态切换

---

## 7. 需要排查的代码位置

建议优先检查以下 iOS 代码区域：

- `AIChatRootView.swift`
- `AIChatMessageList.swift`
- `AIAssistantTurnView.swift`
- `AIAssistantActivityView.swift`
- `AIAskUserCard.swift`
- 与底部输入 / 提交按钮相关的视图文件

重点确认：

- 底部工具栏是否和问答卡共用同一状态源
- 提交按钮是否真正触发后续对话流程
- iOS 底部布局是否忽略了 Web 的业务语义

---

## 8. 验收标准

- iOS 底部工具栏在视觉上接近 Web
- 底部操作区与问答卡的衔接自然
- 提交按钮的状态和行为一致
- 提交后能正确进入下一轮对话状态
- 工具栏不再只是“底部输入条”，而是“任务操作区”

---

## 9. 结论

这个问题本质上不是一个按钮样式问题，而是底部工具栏的业务角色没有和 Web 对齐。

建议把 iOS 底部工具栏升级为结构化问答流程的一部分，统一它的层级、状态和交互闭环，这样后续多端一致性会更稳。
