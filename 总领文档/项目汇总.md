## 2. 项目概览

### 2.1 项目定位

`SupplyChainClient` 是一个以账号会话为基础，组合 AI 配置、文件与 OSS、OCR、第二相机、设置和首页能力的客户端应用。

核心业务能力包括：

- 手机验证码登录、Apple 登录、设备游客账号和会话恢复。
- 账号资料、登录方式绑定/修改、账号注销。
- AI Provider、模型、API Key、运行时配置和本地持久化。
- 文件注册、上传、下载、缓存、业务绑定和删除。
- OSS STS 临时凭证和阿里云对象存储访问。
- 阿里云 OCR、本地 OCR、系统 Vision OCR 的统一编排。
- 应用内 toast、banner、alert、通知收件箱和展示指标。
- 第二相机的拍照、视频、相册、媒体预览和图片编辑。
- 首页、第二相机、设置三个主 Tab。

### 2.2 推荐架构形态

当前工程适合采用：

> 模块化单体客户端（Modular Monolith）+ 功能垂直切片（Feature Vertical Slice）+ 核心能力 Ports & Adapters。

这套形态适合当前项目的原因：

- 所有功能共享同一个 App、账号会话和后台服务。
- 业务模块数量已经较多，需要清晰边界，但还没有拆分为独立进程或独立产品的必要。
- 网络、存储、OSS、OCR、CoreData 等基础设施需要可替换，便于测试和跨平台复用。
- 认证、AI、文件、相机之间存在业务编排，过早拆成微服务式客户端模块会增加通信和状态同步成本。

### 2.3 架构原则

- 依赖方向向内：Presentation → Application → Domain，Infrastructure 实现 Domain/Application 所需的接口。
- 页面不直接创建网络客户端、数据库栈、OSS 客户端或 Token 存储。
- 业务流程通过 UseCase、Repository、Coordinator 和 Service 组合。
- 平台能力通过 Adapter 隔离，例如 Keychain、相机、系统 OCR、OSS SDK 和 CoreData。
- 账号相关缓存、配置和运行时状态必须明确账号归属，禁止跨账号复用。
- 所有全局状态变化必须有唯一入口，例如会话失效统一由 AppLifecycleCoordinator 处理。

## 4. 应用分层与依赖方向

```text
┌──────────────────────────────────────────────────────────────┐
│ App / Presentation                                           │
│ AppCoordinatorView · Tab · Views · ViewModel · Coordinator   │
└──────────────────────────────┬───────────────────────────────┘
                               │ 调用 UseCase / Repository
┌──────────────────────────────▼───────────────────────────────┐
│ Features / Application + Domain                              │
│ Auth · Account · AISettings · SecondCamera · Settings · Memory│
└──────────────────────────────┬───────────────────────────────┘
                               │ 依赖协议和领域模型
┌──────────────────────────────▼───────────────────────────────┐
│ Core / Infrastructure                                         │
│ Network · CoreData · FileStorage · OSS · OCR · Keychain       │
└──────────────────────────────┬───────────────────────────────┘
                               │ 平台和第三方 SDK
┌──────────────────────────────▼───────────────────────────────┐
│ Apple Platform / External Services                            │
│ SwiftUI · UIKit · AVFoundation · Vision · CoreData · Aliyun   │
└──────────────────────────────────────────────────────────────┘
```

推荐依赖规则：

- `Presentation` 可以依赖本 Feature 的 `Application` 和 `Domain`。
- `Application` 可以依赖 `Domain` 协议和跨模块服务接口。
- `Infrastructure` 实现 `Domain`/`Application` 定义的 Repository 或 Gateway。
- `Domain` 不依赖 SwiftUI、CoreData、URLSession、OSS SDK 或具体 ViewModel。
- `Core/Networking` 不知道具体页面，只返回模型和统一错误。
- `AppContainer` 是依赖组合根（Composition Root），负责把所有实现连接起来。

## 5. 应用启动与全局生命周期

### 5.1 启动链路

```text
SupplyChainClientApp
    ↓
AppContainer.live()
    ↓
NetworkPathMonitor 评估网络
    ↓
AppLifecycleCoordinator
    ↓
AppSessionStore.restoreIfNeeded()
    ├── 无会话 → signedOut → 登录流程
    └── 有会话 → signedIn → 账号级准备
                         ├── DeviceRegistrationCoordinator
                         ├── AIConfigCenter.prewarm / refresh
                         ├── OSS STS prefetch
                         └── 主页面 Tab
```

### 5.2 关键代码

- `SupplyChainClient/SupplyChainClient/SupplyChainClientApp.swift`：应用入口。
- `SupplyChainClient/SupplyChainClient/App/AppContainer.swift`：装配 Backend、CoreData、Auth、AI、OSS、文件和 OCR。
- `SupplyChainClient/SupplyChainClient/App/AppBootstrapper.swift`：应用级和账号级启动预热。
- `SupplyChainClient/SupplyChainClient/App/AppLifecycleCoordinator.swift`：会话恢复、账号准备、登出和失效清理。
- `SupplyChainClient/SupplyChainClient/App/AppSessionStore.swift`：发布 loading/signedOut/signedIn 状态。
- `SupplyChainClient/SupplyChainClient/App/AppCoordinatorView.swift`：根据会话状态选择启动页、登录页或主 Tab。

### 5.3 启动设计要求

- 应用级启动只执行一次，账号级启动按 `accountID` 去重。
- 启动失败必须区分网络暂不可用、Token 失效和业务初始化失败。
- 账号切换后不得复用上一个账号的 AI、文件、缓存或 ViewModel 状态。
- 启动协调器负责顺序，具体 API 和业务规则由 UseCase/Service 负责。

## 7. 关键业务流程

### 7.1 登录与会话恢复

```text
启动
  ↓
读取 SessionSnapshot + Access/Refresh Token
  ↓
Token 有效？ ── 否 ── Refresh Token 可用？ ── 否 → 登录页
  │                              │
  │                              └── 是 → 刷新 Token
  │                                           │
  │                                           ├── 成功 → 合并远端会话 → 主页面
  │                                           └── 明确失效 → 清理 → 登录页
  └── 是 → 恢复 UserSession → 账号级启动准备 → 主页面
```

实现分工：

- `RestoreSessionUseCase` 决定是否可以恢复。
- `DefaultAuthRepository` 访问认证 API 并组装 UserSession。
- `AuthTokenProvider` 管理凭证有效性和刷新。
- `SessionSnapshotStore` 持久化会话快照。
- `AppSessionStore` 发布 UI 会话状态。

### 7.2 游客账号升级

```text
设备游客登录
  ↓
创建 device session
  ↓
进入主页面，但标记 isDeviceAccount
  ↓
点击账号入口
  ↓
打开手机号/Apple 登录
  ↓
服务端绑定正式身份
  ↓
刷新 UserSession
  ↓
关闭升级弹窗并进入正式账号管理
```

关键约束：升级前后的账号缓存和文件缓存要明确迁移/隔离策略，不能只切换 UI 标志。

### 7.3 账号身份绑定与注销

```text
进入账号管理
  ↓
加载资料和身份列表
  ↓
选择绑定/修改方式
  ↓
请求验证码或身份验证
  ↓
提交绑定/修改
  ↓
重新加载账号资料

注销：资料确认 → 身份验证 → 注销提交 → 清理会话 → 返回登录页
```

关键代码由 `AccountManagement/Application` 下的 UseCase 表达，不把多个验证步骤塞进单个 ViewModel 方法。

### 7.4 AI 配置同步

```text
进入 AI 设置
  ↓
读取当前账号 CoreData 快照
  ↓
展示本地可用配置
  ↓
后台加载远端配置
  ↓
合并并更新本地快照
  ↓
用户编辑
  ↓
本地保存 → 远端保存 → 更新 RuntimeStore/Adapter
```

配置保存要区分“编辑草稿”“本地已保存”“远端已同步”状态；Provider/API Key 变化时要触发运行时适配器刷新。

### 7.5 文件上传与下载

```text
媒体/文件输入
  ↓
生成 fileUuid、文件大小、MIME、MD5
  ↓
获取 OSS STS
  ↓
上传 objectKey
  ↓
调用 File.Register 注册元数据
  ↓
业务绑定
  ↓
缓存本地文件和远端记录
```

上传失败时需要区分：本地读取失败、STS 失败、OSS 上传失败、文件注册失败和业务绑定失败；不同阶段的重试和清理动作不同。

### 7.6 OCR 编排

```text
媒体选择/相机输出
  ↓
图片预处理
  ↓
OCROrchestrator
  ├── Vision OCR
  ├── Local Server OCR
  └── Aliyun OCR
  ↓
FusionSelector 选择/融合
  ↓
MedicalTermsCorrector 修正
  ↓
OCRDocumentExtractor 输出结构化文档
```

OCR 引擎是可替换适配器，不能让页面直接调用阿里云 SDK 或本地服务 URL。

### 7.7 第二相机媒体处理

```text
相机权限
  ↓
CaptureSession
  ↓
拍照/录像/相册选择
  ↓
媒体预览与多选
  ↓
图片编辑：裁剪、旋转、涂鸦、文字、贴纸、模糊
  ↓
渲染导出
  ↓
CameraMediaSaver/FileTransferService
  ↓
上传、OCR 或业务绑定
```

相机内部实现只负责媒体产生和编辑，文件上传、OCR 和业务绑定由外部服务完成。

## 8. 数据、状态与持久化

### 8.1 状态分类

| 状态类型 | 示例 | 主要承载位置 |
| --- | --- | --- |
| 瞬时 UI 状态 | Sheet 是否打开、加载中、错误提示 | View / ViewModel |
| 会话状态 | loading、signedOut、signedIn | `AppSessionStore` |
| 领域状态 | UserSession、AISettingsSnapshot、AccountIdentity | Domain Model / Repository |
| 运行时状态 | 当前 AI Provider、OSS 临时配置 | Runtime Store / Manager |
| 持久化状态 | Token、SessionSnapshot、CoreData 配置 | Keychain、SnapshotStore、CoreData |
| 文件状态 | 缓存 URL、MD5、文件记录 | `FileCacheManager`、FileTransferService |

### 8.2 持久化边界

- Token：安全存储，不进入普通数据库或文件缓存。
- 会话快照：用于冷启动恢复，不能替代 Token 安全存储。
- AI 配置：CoreData 按账号持久化，API Key 需要更高安全等级。
- 文件缓存：Caches 目录，允许系统清理，必须支持重新下载。
- ETag 响应：仅缓存可重新获取的响应，不保存敏感凭证。
- 设备元数据：设备级存储，账号状态要单独标明归属。

## 9. 关键技术标准

### 9.1 并发与线程安全

- 网络调度、Token 刷新、回调合并和文件缓存使用 actor 或等价串行机制。
- UI 状态更新回到 MainActor。
- 同一账号的配置写入需要避免并发覆盖。
- 任务取消必须向下传递到网络、OSS、OCR 和相机处理阶段。

### 9.2 错误与恢复

- 所有跨模块错误都转换为可分类的 Error 类型。
- UI 错误文案与日志诊断信息分离。
- 认证失效、网络暂时失败、业务校验失败和本地存储失败分别处理。
- 重试只能用于明确可恢复的操作，不能掩盖数据契约错误。

### 9.3 安全

- Token、API Key、STS Secret 和用户隐私数据最小化暴露。
- 日志统一脱敏 Authorization、Cookie、API Key、文件内容和手机号。
- OSS STS 使用临时凭证，并根据过期时间刷新。
- 用户切换账号或退出登录时清理账号级数据。

### 9.4 可观测性

- 每个网络请求有 Request ID。
- 日志记录 API、Operation、业务用途、状态码、耗时、重试和缓存行为。
- 文件上传记录阶段性进度和失败阶段。
- OCR 记录引擎选择、耗时和结果质量摘要，不记录不必要的原图内容。

## 12. 实现顺序与演进建议

### 第一阶段：基础闭环

- AppContainer 和环境配置。
- 网络 Engine、Backend、错误和日志。
- Token、会话快照和冷启动恢复。
- 登录页、主 Tab 和登出。

### 第二阶段：账号与配置

- 设备登记和游客账号。
- 账号资料、身份绑定和注销。
- CoreData、AISettings Repository 和远端配置同步。

### 第三阶段：媒体基础设施

- FileCacheManager、FileTransferService。
- OSS STS、上传、下载和文件元数据。
- OCR Orchestrator、Vision/Local/Aliyun 引擎。

### 第四阶段：第二相机与体验完善

- 相机权限、拍照、录像、相册和预览。
- 编辑器、媒体保存、上传和 OCR 串联。
- 网络弱网、缓存恢复、通知和可观测性完善。

### 12.1 演进边界

- 保持当前模块化单体，不因目录数量增加就拆成独立服务。
- 当某个功能出现独立团队、独立发布或独立扩展需求时，再考虑抽取 Swift Package 或独立模块。
- 优先抽取稳定的 Core 能力，谨慎抽取仍在快速变化的 Feature 内部实现。
- 任何跨模块依赖新增前，先定义协议、数据模型和错误边界。

## 13. 架构验收清单

- [ ] AppContainer 是依赖组合根，页面不自行创建全局服务。
- [ ] 会话状态只有一个权威来源。
- [ ] Token、CoreData、文件缓存和 ETag 缓存边界清晰。
- [ ] Feature 内部遵循 Application、Domain、Infrastructure、Presentation 分层。
- [ ] 网络请求统一经过 Backend/Engine/Operation。
- [ ] 401、退出登录和账号切换有统一清理链路。
- [ ] 上传、OCR、相机和 AI 配置通过明确接口协作。
- [ ] 关键错误有分类、用户提示和诊断日志。
- [ ] 并发、重试、缓存和取消行为有测试覆盖。
- [ ] 新增功能可以在不修改无关模块的前提下接入。
