# 资源与多语言需求

## 一、模块目标

资源与多语言模块负责把 UI 文案、权限提示、图标资产、种子 JSON、错误提示和特定功能的独立文案表统一打包到应用资源层，并以 bundle 为边界向各业务模块提供稳定的读取入口。

当前项目中，这一层不是独立的“资源服务”，而是由 `Projects/App/Resources`、`Foundation/L10n`、`SecondCamera` 专用字符串表和少量功能级资源加载代码共同组成。它的目标是：

- 让界面文案与代码解耦，支持 `zh-Hans` 和 `en` 等语言包。
- 让权限用途说明、系统提示和错误提示可被系统直接读取。
- 让图片、图标、色板和 App Icon 由资产目录统一管理。
- 让 AI 设置等初始化数据以 bundle 内 JSON 的形式随应用发布。
- 让功能级文案表可以独立于全局 `Localizable.strings` 维护，避免互相污染。

## 三、功能模块

### 3.1 全局字符串本地化与兜底

#### 需求说明

全局字符串本地化负责为多数页面、弹窗、按钮、提示和错误消息提供统一入口。项目里大量 `Text(...)`、`Button(...)` 和 `alert(...)` 都通过 `L10n.text(...)` 取值。

#### 基础要求与业务规则

- 默认从 `Bundle.main` 读取全局字符串表。
- 找不到 key 时，返回 fallback；没有 fallback 时返回原 key，方便发现缺失项。
- 格式化字符串必须使用当前地区格式化规则，避免数字、日期和占位符显示异常。
- 本地化 key 命名要保持稳定，避免把业务语义写进代码常量里。
- 全局文案优先放在 `Localizable.strings`，不要散落在页面里写死。

#### 验收标准

- `zh-Hans` 和 `en` 都能正常显示全局 UI 文案。
- 缺失 key 时不会崩溃，页面至少能显示 fallback 或原 key。
- 需要格式化的字符串能正确带入参数并按当前地区输出。

#### 技术细节与设计代码位置

- `SupportClient/SupportClient/Foundation/Utilities.swift:70-83` 定义 `L10n.text`、`L10n.tr`、`L10n.format`。
- `SupportClient/SupportClient/Projects/App/Resources/zh-Hans.lproj/Localizable.strings` 和 `en.lproj/Localizable.strings` 提供主文案。
- `SupportClient/SupportClient/Projects/App/Presentation/NetworkGateView.swift`、`Core/UI/SparkVoiceInput.swift`、`Features/Auth/Presentation/*` 等页面直接消费 `L10n.text(...)`。

### 3.2 第二相机专用字符串表

#### 需求说明

第二相机有一批与拍摄、预览、编辑、贴纸、质量选择和多张处理相关的专用文案，需要和全局文案分开维护，避免 key 命名过长且相互冲突。

#### 基础要求与业务规则

- 第二相机文案使用独立表 `SecondCamera.strings`。
- 同一功能内的文案命名要围绕场景组织，如 `second_camera.preview.*`、`second_camera.editor.*`、`second_camera.multi.*`。
- 表内文案应同时覆盖中文和英文。
- 功能级字符串调用必须保留 fallback，避免某个语言包缺失时影响操作。
- 如果运行环境不是主 App bundle，也要能找到正确的资源 bundle。

#### 验收标准

- 第二相机首页、预览页、编辑器和批量选择流程都能显示对应语言文案。
- 第二相机资源在 App host 和扩展/子 bundle 场景下都可正确解析。
- 缺失 key 时至少回退到 fallback 文案，不影响主流程。

#### 技术细节与设计代码位置

- `SupportClient/SupportClient/Projects/Features/SecondCamera/CustomCamera/Internal/Editing/Support/SecondCameraEditorL10n.swift:3-103` 定义第二相机文案枚举。
- `SupportClient/SupportClient/Projects/Features/SecondCamera/CustomCamera/Internal/Editing/Support/SecondCameraEditorL10nBridge.swift:8-23` 通过 `Bundle.main.secondCameraEditor_app` 回退主 App bundle。
- 第二相机页面和编辑器相关 UI 从该表读取标题、按钮、错误和无障碍文案。

### 3.3 图标资产、App Icon 与业务图标

#### 需求说明

资源层不仅承载文本，还承载所有需要被 `Image(...)`、`UIImage(named:)`、`Image(systemName:)` 以外方式管理的视觉资源，例如 App Icon、AccentColor、AI Provider 图标和第二相机编辑器图标。

#### 基础要求与业务规则

- 视觉资源统一存放在 `Assets.xcassets`。
- App Icon、AccentColor、AI Provider、SecondCamera 等分类应保持命名稳定。
- 页面应通过资源名引用图标，不直接拼接文件路径。
- 图标资源在不同主题或状态下应使用资源集的变体，而不是在代码中硬编码切换逻辑。

#### 验收标准

- App 启动后图标、首页、AI 设置、第二相机等页面都能加载到资源集里的图片。
- 切换系统明暗风格后，存在变体的资源仍能正确显示。
- 资源名缺失时，页面能够保持可用并暴露明显的开发期问题。

#### 技术细节与设计代码位置

- `SupportClient/SupportClient/Projects/App/Resources/Assets.xcassets/Contents.json` 为资源目录根。
- `SupportClient/SupportClient/Projects/App/Resources/Assets.xcassets/AppIcon.appiconset/Contents.json` 负责应用图标。
- `SupportClient/SupportClient/Projects/App/Resources/Assets.xcassets/AI/` 下放置 AI Provider 图标，例如 `prompt`、`openai`、`claude`、`qweather` 等。
- `SupportClient/SupportClient/Projects/App/Resources/Assets.xcassets/SecondCamera/` 下放置第二相机工具图标。
- `SupportClient/SupportClient/Projects/Features/AISettings/Presentation/Models/Components/PromptInputEditorView.swift`、`ModelsSettingsView.swift`、`SecondCamera/...` 等页面直接消费这些资源名。

### 3.4 权限文案、种子 JSON 与错误本地化

#### 需求说明

这部分负责系统权限用途说明、AI 初始数据和后端错误文本。它们都不是普通 UI 文案，但同样必须和代码解耦并随版本发布。

#### 基础要求与业务规则

- `InfoPlist.strings` 必须提供相机、麦克风、相册读取和保存等用途说明。
- AI 设置的 `APIKeys.json` 和 `AllModels.json` 作为 bundle 种子数据，必须与初始化逻辑匹配。
- 后端错误消息优先使用服务器返回的嵌入文案，其次使用本地化 key，再退回原始错误内容。
- 权限文案和错误文案要能被系统和页面分别读取，不应混用同一读取入口。

#### 验收标准

- 系统弹窗显示的权限说明与实际功能一致。
- AI 设置启动时能正确读取 bundle 内的种子 JSON。
- 后端错误能按 code、msg 或 HTTP 状态码映射到可读文案。

#### 技术细节与设计代码位置

- `SupportClient/SupportClient/Projects/App/Resources/zh-Hans.lproj/InfoPlist.strings` 与 `en.lproj/InfoPlist.strings` 存放权限文案。
- `SupportClient/SupportClient/Projects/App/Resources/AISettings/APIKeys.json` 与 `AllModels.json` 存放 AI 设置初始数据。
- `SupportClient/SupportClient/Projects/Core/Networking/BackendErrorLocalizer.swift:3-68` 将 `BackendError` 和 HTTP status code 转为本地化消息。

## 四、整体业务流程

```mermaid
flowchart TD
    A[页面/服务请求文案或资源] --> B{资源类型}
    B -->|全局字符串| C[L10n.text / L10n.format]
    B -->|第二相机专用字符串| D[SecondCameraEditorL10n]
    B -->|系统权限文案| E[InfoPlist.strings]
    B -->|图片/图标| F[Image / UIImage from Assets.xcassets]
    B -->|种子数据| G[Bundle 读取 JSON]
    B -->|后端错误| H[BackendErrorLocalizer]
    C --> I[Bundle.main.localizedString]
    D --> J[NSLocalizedString(table: SecondCamera)]
    E --> K[系统权限弹窗]
    F --> L[UI 渲染]
    G --> M[AISettings 初始化]
    H --> N[错误提示文案]
    I --> O{命中 key?}
    J --> P{命中 key?}
    O -->|是| Q[返回本地化文本]
    O -->|否| R[返回 fallback / key]
    P -->|是| Q
    P -->|否| R
```

典型流程如下：

1. UI 或业务服务提出一个字符串 key、图片名或资源文件名。
2. 资源读取入口根据资源类型选择 `L10n`、`NSLocalizedString`、`Image(...)` 或 `Bundle.url(forResource:)`。
3. 系统先按当前 bundle 与语言包查找资源。
4. 如果 key 命中，返回本地化结果。
5. 如果 key 未命中，返回 fallback 或原 key，避免主流程中断。
6. 对后端错误，先读取服务端嵌入消息，再映射本地化 code/msg key，最后回退 HTTP 通用文案。

## 五、状态模型

资源与多语言模块的状态更接近“解析状态”而不是“领域状态”。当前项目主要有以下状态：

| 状态 | 含义 | 用户可见结果 |
| --- | --- | --- |
| 未请求 | 资源还没被当前视图读取 | 页面尚未渲染相关文案 |
| 已命中 | key、图片或文件存在 | 显示本地化文本或资源 |
| 已回退 | key 缺失但 fallback 存在 | 显示可用默认文案 |
| 原样返回 | key 和 fallback 都不可用 | 显示原 key 或开发期暴露字符串 |
| 资源缺失 | 图片、JSON 或表文件不存在 | 功能降级或使用默认图标/默认值 |
| 格式化失败 | 占位符与参数不匹配 | 通常显示不完整文本或触发开发期错误 |

当前实现没有独立的运行时语言切换状态机，语言选择主要跟随系统语言和 bundle 资源。

## 六、数据与持久化

这一模块的核心数据大多是只读 bundle 资源，不属于数据库持久化。

| 数据类型 | 存储位置 | 持久性 | 说明 |
| --- | --- | --- | --- |
| 全局本地化字符串 | `Localizable.strings` | 构建期静态 | 由 `L10n.text` 读取 |
| 第二相机专用字符串 | `SecondCamera.strings` | 构建期静态 | 由 `SecondCameraEditorL10n` 读取 |
| 权限用途说明 | `InfoPlist.strings` | 构建期静态 | 由系统读取 |
| App 图标和业务图片 | `Assets.xcassets` | 构建期静态 | 由 SwiftUI / UIKit 读取 |
| AI 设置种子数据 | `APIKeys.json`、`AllModels.json` | 构建期静态 | 用于初始化或回填配置 |
| 语言、地区信息 | `SupportSystemInfo` 运行时属性 | 内存态 | `languageCode`、`regionCode`、`countryCode` 来自系统 |

模块本身不负责把资源写回磁盘。只有像 AI 设置或其他领域组件在使用这些资源后，才可能把解码结果写入 Core Data、文件缓存或账号级存储。

## 七、错误模型

| 错误类型 | 触发场景 | 当前处理方式 |
| --- | --- | --- |
| 缺失本地化 key | `Localizable.strings` 没有对应条目 | 返回 fallback 或原 key |
| 缺失第二相机表 key | `SecondCamera.strings` 不包含 key | 返回 fallback |
| 资源图片不存在 | `Image("...")` 或 `UIImage(named:)` 失败 | 页面应继续显示，开发期暴露问题 |
| 权限文案缺失 | `InfoPlist.strings` 配置不完整 | 系统默认文案或打包检查失败 |
| JSON 种子文件缺失 | `APIKeys.json` / `AllModels.json` 找不到 | AI 设置初始化失败或退回默认配置 |
| 格式化不匹配 | `%d`、`%@` 等占位符与参数不一致 | 运行期文本异常，需要测试发现 |
| 后端错误无映射 | `BackendErrorLocalizer` 找不到 code/msg key | 退回 HTTP 通用文案或原始 message |

这里的重点不是“抛出多少异常”，而是“让错误尽量可读且不阻塞主流程”。当前实现已经通过 fallback 和原始消息回退降低了可见故障率，但还没有形成统一的资源校验机制。

## 八、与其他模块的接口边界

### 本模块负责

- 提供全局与功能级文案读取入口。
- 提供权限用途说明与系统可读的 plist 本地化。
- 提供静态图片、图标和色板资源。
- 提供 AI 设置等种子 JSON 数据。
- 将后端错误转换为用户可理解的提示。

### 本模块不负责

- 不负责账号状态、会话切换和网络请求。
- 不负责把资源写回数据库或远端。
- 不负责业务流程编排和页面跳转。
- 不负责资源下载、热更新或 CDN 同步。

### 上游调用方

- `App/Presentation` 下的大多数页面。
- `Auth`、`AISettings`、`Settings`、`SecondCamera` 等功能模块。
- 网络层的错误提示映射。

### 下游依赖

- `Bundle.main` 和系统本地化机制。
- `Assets.xcassets` 资源目录。
- `InfoPlist.strings`。
- bundle 内 JSON 文件。

### 输入与输出

- 输入：本地化 key、图片名、资源文件名、格式化参数、后端错误对象。
- 输出：本地化字符串、图像对象、读取到的 JSON 数据、用户提示文本。

## 十、测试策略

- 为 `L10n.text` 补充缺失 key、fallback 命中和格式化参数测试。
- 为 `SecondCameraEditorL10n` 补充 table 读取和 bundle 回退测试。
- 为 `BackendErrorLocalizer` 补充 code/msg/statusCode 三段式映射测试。
- 为 AI 种子 JSON 补充 decode 与字段兼容测试。
- 为 `InfoPlist.strings` 和关键图片资源补充打包校验，至少在构建校验阶段确认资源存在。

当前 `SupportClientTests` 主要覆盖网络、会话和 OSS 相关行为，未发现专门针对本地化表或资源缺失的单元测试，这意味着资源层更依赖构建期和人工回归检查。

## 十一、当前实现、缺口与演进

### 当前实现

- 全局字符串由 `L10n` 统一读取。
- 第二相机使用独立的 `SecondCamera.strings`。
- 权限说明使用 `InfoPlist.strings`。
- AI 初始化数据放在 `Projects/App/Resources/AISettings/`。
- 后端错误可通过 `BackendErrorLocalizer` 转成本地化提示。

### 主要缺口

- 没有独立的“资源清单”或校验工具，无法自动发现缺 key、缺图或占位符不匹配。
- 没有运行时语言切换能力，语言仍主要依赖系统选择。
- `L10n.text` 主要面向 `Localizable.strings`，功能级表仍需要各自封装。
- 测试对资源层覆盖不足，容易在改文案时漏掉英文表或第二相机专用表。

### 演进建议

1. 增加资源一致性检查脚本，校验中英文 key 集合、`InfoPlist.strings`、第二相机表和 JSON 种子文件。
2. 为功能级表建立统一封装，减少 `NSLocalizedString` 在页面中的直接散落。
3. 给重要资源添加最小化快照测试，防止重构时 key 被误删。
4. 如果未来需要手动切换语言，再引入独立的语言选择状态和 bundle 切换层。

## 十二、整体验收标准

- 全局页面、登录页、设置页、AI 页面和第二相机页面都能正常显示对应语言文案。
- `zh-Hans` 与 `en` 的 `Localizable.strings` 内容可正常读取，缺失 key 有 fallback。
- 第二相机的专用字符串表能在主 App 场景下正确工作，必要时能通过 bundle 回退找到资源。
